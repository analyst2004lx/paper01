## 一、改写时先问的三件事

1. **这个词在车间里指什么？** 写占用、工序、车辆、时段，不要写「命中 / 种子 / 画在图上 / 看不见」。
2. **这句话的主语是本文、已有文献，还是某一种对照方法？** 必须写开。禁止「预约影响集则……」这种看不出谁提出的接法。
3. **并排的两个「时间」或两个「重调度」是不是同一件事？** 算法耗时 ≠ 完工时间 \(C_{\max}\)；按工序划界的局部重调度 ≠ 全局重调度。

## 二、名词对照（旧词 → 应用的说法）

### 2.1 设定与对象

| 旧稿用词 | 改后 | 说明 |
|---|---|---|
| 持有任务图 / 持有预约表 | 用工序依赖刻画加工先后；用时间窗记录走廊占用 | 「持有」不像模型用语 |
| 这一支文献 / 这一支模型 | 写开设定，或「这一类研究」 | 不要自称「一支」 |
| 显式预约模型 | 用时间窗记录走廊占用 | 不是与「隐式预约」成对；对照是常数运输时间矩阵 |
| 按位置索引的常数矩阵 | 按**位置对**索引的常数矩阵；行驶时间可从矩阵读出 | 索引的是一对工位，不是单个位置 |
| 行驶时间是布局的固有属性 | 行驶时间只由两点之间的距离决定，与走哪条路、路上有没有车无关 | 不要读成「布局造成延误」 |
| 半开时间窗（引言里） | 以时间窗预约走廊 | 「半开」留给问题描述里占用区间的定义 |
| 无冲突路由设定 | 用时间窗预约走廊来保证车辆无冲突通行 | 「无冲突」是机制，不是「路上本来没冲突」 |
| 无冲突执行器 | 同一套走廊路网、时间窗路由与无冲突校验 | 不要造「执行器」 |
| 任务图 | 工序依赖图；必要时括号注明（任务图） | 顶点是工序，边是工件先后与同机先后 |
| 时空预约图 / 闭包 | 由走廊占用及其让行、接续关系构成的图；**预约影响集**（STRC） | 「闭包」是图论术语，摘要和引言不要当第一称呼 |

| 释放集 / 释放域 | 允许改写的占用集合 | |
| 收录 | 纳入重调度范围 | 既不是求解，也不是登记存档 |
| 活预约 | 决策时刻尚未结束的走廊占用 | |
| 机器链 | 同一台机器上排在其后的工序 | |
| 扩张 / 被扩到 | 按规则纳入重调度范围 | 不是扰动在车间里物理扩散 |
| 路段降速 | 走廊通行变慢 | 不是「车辆自行减速」；走廊是车间共享边，不属于某一辆车 |

| 便宜 / 贵 | 耗时更短 / 更长；不做种群搜索的一次全局重算 | |

| 全局右移 | 不判断哪些占用受影响，把未完成占用整体后推到阻断结束之后 | |

### 2.3 应避免的修辞（不是禁概念，是禁这种说法）

| 旧稿说法 | 为什么不好 | 改后方向 |
|---|---|---|
| 买到 / 兑现 / 挂靠点 / 制导 | 口语、答辩腔 | 改进的是…… / 带来的是…… / 引导搜索以更换指派或路径 |
| 关键链稀释、顶上来的是谁 | 不学术 | 消去一处走廊等待后，另一处约束往往会成为新的瓶颈，完工时间上的收益容易被抵消 |
| 一击反例 / 系统性漏报 / 全称否定 | 压缩过度或逻辑课用语 | 问题层面上的反例；按该方法会得到空范围；不要写成「所有局部重调度文献都错了」 |
| 本文只做测量 | 读成「文章做得太少」 | 铁路用让行关系**选择**车辆先后；本文用**既定**先后划定须改写的占用 |
| 不利读数如实报出 / 不主张以下三件事 | 先认输再立论 | 直接陈述事实；相关工作里先写别人做了什么，再写没做什么 |
| 问题层 / 框架层 / 机制层 / 方法层 | 把贡献挤成对位 | 贡献按「缺口—对象—证据」写，不按四层 |
| 相关工作「四层」 | 给自己做分类学 | 按问题类型分四类回顾 |
| 看见 / 看不见 / 画到图上 | 拟人、不具体 | 给出非空范围 / 无法表达 / 按工序依赖图划定，因找不到受影响工序而被漏掉 |
| 覆盖不到（无前词） | 第二段解释时前段没出现过 | 先在叙述里用「覆盖不到」，再界定它指表示不含让行关系，不是检测漏检 |

## 三、句式（比名词更要紧）

### 3.1 先写对象，再写关系，少堆四字格

坏：`延误只是布局属性`；`同修复引擎下仅替换边界定义`；`空影响域 ⇒ 无需重调度`。

好：一句话只推进一件事，因果写开。例如：改路程序、原排程、扰动时刻、阻断窗都相同，**唯一差别是重调度范围怎么算**。

### 3.2 主语必须能指认

- 本文给出的预约影响集……
- MAPF 用独立性检测得到的集合……（那是该方法的性质，不是本文发现）
- 按工序依赖图划界时……不会启动；**同一扰动若改为启动全局重调度**，则可以处理。

禁止把「本文贡献」和「已有方法的性质」写在同一句里却不点名。

### 3.3 两种时间、两种重调度，分句写

| 说法 | 指什么 |
|---|---|
| 算法耗时 / 响应时间 / 搜索时限 | 程序跑多久（毫秒 vs 秒） |
| 完工时间 \(C_{\max}\) | 排程里最后一道活何时结束（解的质量） |
| 按工序划界的局部重调度 | AOR：找不到受影响工序就不启动 |
| 全局重调度 | 观测到阻断后可以开搜，不依赖工序图是否为空 |

「有界修复没有反超」只指 \(C_{\max}\) 从未优于全局重调度，与谁算得更快无关。比较有界修复与全局重调度时：**先抑后扬**——先说 \(C_{\max}\) 更差、改写比例同量级，再说长处是毫秒级恢复可行。不要写「差别不在排程质量」（会读成质量差不多）。

### 3.4 相关工作：先扬后抑，按问题分类

每类固定三步：他们研究了什么、做成了什么、**但没做哪一件**（那一件正是本文要凸显的）。

- 不要用「必须先承认 / 礼让 / 不主张创新」收束。
- 旧文献可以保留引用，但叙述以近作为主，九十年代算法收成引文簇，不要逐篇展开。
- 章节开头先立住**本节在比什么**（重调度范围划在什么对象上），不要先丢一句没有对照物的操作说明。

### 3.5 主张与贡献：先说做了什么

坏：`本文不主张它是新对象，新的是它的用法`；`这些动作都不是本文创新的挂靠点`。

好：先写本文做什么（在既定计划上按让行与接续把必须改写的占用纳入范围）；再补一句「这些修复步骤用来落实影响集，主张在如何划定影响集」。

贡献不要四层对位。站得住的是三条：指认工序图覆盖不到的损坏；把范围定义为预约影响集；用对照说明可行来自划界、毫秒来自单次路径规划、少改写须对「只差允许改写哪些占用」的对照来读、\(C_{\max}\) 上不优于全局搜索。

### 3.6 「因此」只能接同一条推理

坏：上一句说「集内改路不是本文机制」，下一句用「因此」接到「这类工作没有工序图」。那是另一层差别，应另起一句。

好：`上述做法已经把……做成标准机制，本文并不把它当作贡献。与本文设定的另一点不同是：……`

### 3.7 对照必须写清「只差哪一项」

隔离预约影响集时，拆成：有界修复只改写影响集以内、集外沿用原计划；对照则把尚未结束的占用全部纳入改写。两者同一套改路程序，都不改已经结束的占用。差别仅在改写范围。

少改写**不能**从「对全局重调度」那一对照读出（两边改写比例已经接近）；只能从上述「只差改写范围」的对照读出。

有界修复能「发现损坏」，是相对**按工序划界**而言，不是相对全局重调度——全局重调度能处理走廊阻断，只是耗时在秒级。

### 3.8 标题要具体

「问题描述」「主张与方法预告」过泛。已改：`本文主张`。第 3 节建议（尚未改标题）：**走廊预约设定与执行期恢复问题**（设定 + 要解的问题）；不要用「问题建模」（STRC 在第 4 节，本章几乎没有优化模型）。

## 四、已落地段落里的范句（后文可仿）

**设定对照（常数矩阵 vs 时间窗预约）**  
行驶时间因此只由两点之间的距离决定，而不是路由决策的结果。……行驶时间就不再是固定数据，而成为两个决策的结果——车辆走哪条路，以及谁先占用了该路段。

**AOR 划界（写开，不写种子/扩张）**  
以因设备故障或插单而无法按原计划执行的工序为起点，再把同一工件的后续工序、以及同一机器上排在其后的工序一并纳入重排范围。

**覆盖不到（先出现再界定）**  
于是工序依赖图覆盖不到这些必须恢复的走廊占用：……这里的「覆盖不到」，指工序依赖图按定义不含走廊占用之间的让行关系，……而不是传感器漏检或算法偶然没查到。

**两种重调度（避免读成自相矛盾）**  
按工序依赖图划界时，走廊阻断因找不到受影响工序而不会启动局部重调度，原排程保持不可行。同一扰动若改为启动全局重调度，则可以处理，但算法耗时在秒级。

**铁路让行（用法不同，不是「只做测量」）**  
对每一处争用，alternative graph 给出两条互斥的弧（甲先通过，或乙先通过），排程就是从中选定一条。……本文的计划已经排好，……把扰动后必须作废的原走廊占用纳入重调度范围。

**相关工作收束（问题—文献缺口—主张）**  
此时会出现一类已有文献尚未处理的情形：走廊阻断等扰动并不使工序无法执行，原指派仍然有效，但与受扰时段重叠的走廊占用已经失效。……本文主张把重调度范围改到走廊占用及其让行、接续关系上，得到由这些关系唯一确定的预约影响集。
