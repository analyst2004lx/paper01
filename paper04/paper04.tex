\begin{abstract}
In flexible job shop scheduling that captures processing order with an operation-precedence graph and records the corridor occupancies of vehicles in a time-window reservation table,
the rescheduling scope after a disturbance is still delineated by affected-operation rescheduling (AOR): operations that can no longer be executed as planned are identified, and their successors on the operation-precedence graph are added.
Corridor blockage or slowdown acts only on corridors; machines and operations remain available, so AOR finds no affected operation and returns an empty scope, concluding that no rescheduling is needed.
Yet the planned occupancies inside the disturbed interval are already invalid and the original schedule is infeasible;
moreover, a corridor admits one vehicle at a time, so a vehicle planned to traverse it later must wait for the preceding one (a yielding relation), and a delay passes from vehicle to vehicle.
The problem is not detection (the blockage is known) but that the operation-precedence graph used by AOR contains only operations and their precedences, with neither corridor occupancies nor the yielding relations among them.

We instead delineate the rescheduling scope at the level of corridor occupancies and propose the spatiotemporal reservation closure (\STRC), whose output set of occupancies is called the reservation impact set.
Starting from the planned occupancies whose intervals overlap the disturbance window, \STRC{} keeps adding successor occupancies along four dependency relations among occupancies---yielding on the same corridor, and the next occupancy of the same vehicle, of the same job, and on the same machine---until none can be added (the transitive closure).
Each occupancy is determined by its corridor (path), interval, and vehicle: occupancies inside the set may have their path and interval replanned (and, under vehicle failure, their vehicle replaced), while those outside keep all three.
Once the four relations are fixed, membership in the set depends only on reachability from the seeds and is independent of the rerouting algorithm.
Bounded repair first replans conflict-free paths for the occupancies inside the set with the original vehicles; if the schedule remains infeasible, it successively adds the subsequent occupancies of the same job, of the same vehicle, and finally all unfinished occupancies to the rewritable scope.

On \NPairs\ instance--seed pairs (\NInst\ instances \(\times\) \NSeeds\ random seeds that determine disturbance injection and search), the scope delineated by AOR under corridor blockage is empty on all pairs, although the original schedule is in fact infeasible on every one of them;
with the rerouting procedure unchanged and only the scope object replaced, the number of pairs repaired to a feasible schedule rises from \FeasRone\ to \FeasRtwo.
On all pairs the impact set is closed (no dependency edge leads from inside to outside), and every occupancy outside it keeps its original corridor, interval, and vehicle after repair.
Rewriting all unfinished occupancies instead leaves runtime and makespan almost unchanged but raises the fraction of rewritten occupancies from \ResFracCheapRtwo\ to \ResFracAllFuture\ (scoping by the impact set rewrites fewer/equally many/more on \RAStabWTL\ pairs; Wilcoxon \(p=\RAStabP\)).
Compared with warm-started global rescheduling that re-searches assignment and order within a time limit, bounded repair is two to three orders of magnitude faster, but its makespan is never better under any tested time limit and cannot overtake under longer limits.
Feasibility is thus restored by the scope object; the reduction in rewrites is limited because the impact set already covers about \ClosureAliveFrac\ of all unfinished occupancies.
Rerouting inside the set and enlarging the scope after failure follow existing practice; the contribution lies in delineating the rescheduling scope on corridor occupancies instead of operations.
\end{abstract}

\section{Introduction}
\label{sec:introduction}
%% =====================================================================

Flexible job shop scheduling with transportation usually takes transport times as constants indexed by location pairs~\cite{xin2025review,meng2025cp,qin2026knowledge}, assuming no corridor contention among vehicles.
When a finite fleet shares a sparse corridor network this no longer holds~\cite{kim2026congestion}, so existing work decides machine assignment jointly with conflict-free paths before execution~\cite{vanos2026exact,sun2023integrated,lyu2019approach,li2026framework},
and a schedule then also contains a time-window reservation table recording which vehicle occupies which corridor during which interval.
A disturbance may make operations unexecutable (e.g., machine or vehicle failure) or invalidate only some corridor occupancies without changing any operation (e.g., a corridor blocked or slowed down for some period).
These works answer how to build a conflict-free schedule when information is complete. Once the shop has executed up to time \(t_{\mathrm{now}}\) and a disturbance occurs, the questions become:
which corridor occupancies are invalidated; which must be rewritten so that the schedule again satisfies corridor exclusivity and the closure constraints and can continue to be executed;
and whether such a schedule can be obtained within milliseconds of computation time without restarting a population-based search.

\textbf{The gap.}
In dynamic scheduling of flexible job shops with transportation, the rescheduling scope is usually delineated on the operation-precedence graph:
operations that can no longer be executed as planned serve as seeds, the operations following them in the same job and on the same machine are added, possibly only up to \(\theta\) steps (a manually set upper bound on the expansion depth),
and only the operations in this scope are rescheduled.
Existing dynamic scheduling studies with AGV transport delineate the scope in this way~\cite{zhang2023energy,tang2026dynamic}, a practice that traces back to affected-operation rescheduling (AOR)~\cite{abumaizar1997rescheduling,subramaniam2003maor}.
This is reasonable when the disturbance is an operation event, such as a machine failure.
When the schedule records corridor occupancies with time windows, however, a \emph{corridor blockage} closes a corridor during \([t_a,t_b)\) without modifying any machine assignment or processing order; machines and operations remain available.
The seed set of AOR (operations that can no longer be executed as planned) is therefore empty, so the scope is empty and the method concludes that no rescheduling is needed.
Yet the planned occupancies that overlap the blockage interval are no longer feasible.
Moreover, a corridor admits one vehicle at a time, so a vehicle planned to traverse it later must wait for the preceding one to leave (a yielding relation); a vehicle delayed by waiting or detouring therefore delays its follower, which delays its own follower, and the invalidation propagates across the reservation table.
The blockage itself is known, so the problem is not detection: the operation-precedence graph used by AOR has operations as vertices and job and machine precedences as edges,
and by definition contains neither corridor occupancies nor their yielding relations, so it cannot express this invalidation or its propagation;
the gap arises only in settings that record corridor occupancies with time windows.
We accordingly distinguish \textbf{Class A} disturbances, which make some operations unexecutable (robotic-arm failure, processing-time deviation, rush orders, vehicle failure),
from \textbf{Class B} disturbances, which act only on the reservation table (corridor blockage, corridor slowdown); Class B is the counterexample to operation-level scoping (Section~\ref{sec:disturbance_classes}).
Figure~\ref{fig:motivate} illustrates the gap.

\textbf{Stance.} The reservation impact set answers only \emph{which occupancies are already invalid}, not \emph{how the schedule should be changed}.
We do not use yielding relations to steer the search toward better assignments or paths, which would be schedule improvement whose gains are easily offset when another constraint becomes the bottleneck.
We use the dependencies only to decide invalidity: an occupancy reachable from the seeds belongs to the impact set, one that is not does not; once the edges are fixed, the set is unique.
The impact set is not necessarily the minimal set needed to restore feasibility, because the minimal set depends on the permitted repair actions (Remark~\ref{rem:minimality}).
Its role also differs from that of global rescheduling: it answers whether feasibility can be restored \emph{quickly} while confining rewrites to the set, not whether a better makespan can be found.
Confining rewrites matters because every rewritten occupancy is a route or time window that must be reissued to a vehicle already executing the plan; keeping the rest unchanged is a form of schedule stability~\cite{vieira2003rescheduling}.

\textbf{Contributions.}
\begin{enumerate}[label=\textbf{C\arabic*.},leftmargin=2.2em,itemsep=0.3em]
\item \textbf{A class of invalidation the operation-precedence graph cannot capture.}
Under corridor blockage and slowdown, operation-level scoping returns an empty scope although the original schedule is infeasible (\(\PassMiss\), Section~\ref{sec:e1});
the root cause is that the operation-precedence graph has no yielding relations among occupancies (Proposition~\ref{prop:miss}).
\item \textbf{The reservation impact set as the rescheduling scope.}
\STRC{} delineates the scope by closure over yielding and same-vehicle, same-job, and same-machine succession. Membership is uniquely determined and no dependency edge leaves the set.
The set is nonempty under all four disturbance types and, under Class A disturbances, contains every occupancy already included by the operation-precedence graph (Section~\ref{sec:e6}).
With the same rerouting, it rewrites fewer occupancies than rewriting all unfinished ones (fewer/equal/more on \RAStabWTL\ pairs; Section~\ref{sec:cheap}).
\item \textbf{A matching local recovery with the sources of each result separated.}
Under the same network, router, and checker, scoping on the operation-precedence graph yields an executable schedule on \(\FeasRone\) corridor-blockage pairs, scoping on the impact set on \(\FeasRtwo\) (Section~\ref{sec:e3}).
Bounded repair takes milliseconds, but its makespan is no better than that of global rescheduling under every tested time limit, and relaxing the limit does not reverse this order (Section~\ref{sec:e5});
against rewriting all unfinished occupancies, runtime and makespan are almost identical, so the millisecond runtime comes from single-pass rerouting, not from the impact set (Section~\ref{sec:cheap}).
\end{enumerate}
Integrated scheduling before execution uses the reservation table to build a conflict-free plan; this paper uses the same table at execution time to locate the invalidated scope.

Section~\ref{sec:related_work} reviews related work; Section~\ref{sec:problem} states the setting and the recovery problem; Section~\ref{sec:strc} defines \STRC{} and its properties;
Section~\ref{sec:repair} describes bounded repair; Section~\ref{sec:experiments} reports the experiments; Section~\ref{sec:conclusion} concludes.

\section{Related work}
\label{sec:related_work}
%% =====================================================================

A basic question in dynamic scheduling is on which object the rescheduling scope is delineated after a disturbance. We review four classes of objects and summarize them in Table~\ref{tab:position}.

\subsection{Local rescheduling in job shops}
\label{sec:rw_aor}

For operation-level events, delineating the scope by the affected operations is still common in dynamic scheduling with AGVs.
Zhang et al.~\cite{zhang2023energy} reschedule the operations not yet processed after a machine breakdown;
Tang et al.~\cite{tang2026dynamic} classify disrupted operations and delivery tasks as retained, continued, or reconstructed, and compare full rescheduling, partial rescheduling, and right shift.
This practice dates back to AOR~\cite{abumaizar1997rescheduling,subramaniam2003maor}, which reschedules only the operations directly or indirectly affected.
Delineating the scope along the time axis and enlarging it after failure have also been studied, including match-up~\cite{akturk1999matchup}
and Local Rescheduling with incrementally enlarged time windows~\cite{kuster2007local}; right shift instead postpones the entire unfinished part.
Rolling-horizon and decomposition methods trade off scale against quality~\cite{zeitrag2025novel,zhao2019decomposition}; see~\cite{vieira2003rescheduling,ouelhadj2009survey} for surveys.
These works presuppose that the disturbance acts on operations; when it only makes a corridor impassable, the scope can be empty although the schedule is infeasible.

\subsection{Occupancy order on exclusive resources}
\label{sec:rw_ag}

The alternative graph of Mascis and Pacciarelli~\cite{mascis2002alternative} generalizes the disjunctive graph: vertices are occupations of block sections,
fixed arcs encode route precedence, and paired alternative arcs encode which train passes first; D'Ariano et al.~\cite{dariano2007branch} use it for real-time train rescheduling.
Our yielding relations express the same kind of precedence, but the use differs. In the alternative graph, occupancy order is a decision variable chosen to avoid positive cycles and optimize the objective;
in our setting the order is already fixed, and we use it only to bring invalidated occupancies into the scope.
Moreover, railways treat block sections as machines, so an unavailable section is itself an operation-level event and the mismatch studied here does not arise.

\subsection{Local replanning in conflict-free multi-vehicle routing}
\label{sec:rw_mapf}

In multi-agent path finding (MAPF), replanning only the affected agents is standard.
\v{S}vancara et al.~\cite{svancara2019online} compare Replan All, Replan Single, and Replan Affected, determining the affected agents by independence detection;
Malka et al.~\cite{malka2024online} replan only the agents affected by observed map changes; lifelong MAPF treats spatiotemporal occupancy as a first-class constraint~\cite{zhang2024guidance}.
We adopt the mechanism ``change only the affected, keep the rest''. MAPF, however, has no job--operation--machine assignment, so operation-level scoping cannot miss a blockage there,
and its affected set is the output of a detection algorithm that varies with the implementation, whereas the reservation impact set is fixed once the edges are given (Section~\ref{sec:containment}).

\subsection{Flexible job shop scheduling with transportation}
\label{sec:rw_position}

Much recent work still takes travel times as a constant matrix~\cite{xin2025review,meng2025cp,qin2026knowledge,fu2025integrated}, in which a corridor blockage has no counterpart.
Congestion-aware dispatching selects vehicles by proxies such as local density~\cite{kim2026congestion}.
Van Os and Basten~\cite{vanos2026exact} formalize flexible job shop scheduling with conflict-free transportation and solve most benchmark instances to optimality;
two-stage schemes first fix production and then resolve vehicle conflicts~\cite{sun2023integrated}; a learning-based scheduling layer can be coupled with a conflict-resolving routing layer~\cite{li2026framework}.
These works build a conflict-free schedule \emph{before} execution.
Among the cited works, a reservation table and execution-time disturbances never appear together:
Zhang et al.~\cite{zhang2023energy} state that ``the collision of AGVs are ignored'', while Sun et al.~\cite{sun2023integrated} resolve conflicts with time-window Dijkstra but assume that ``AGVs are always available'' and leave breakdowns to future research.
When both are present, the only directly applicable practice is operation-level scoping, which yields an empty scope for a corridor blockage (\PassMiss, Section~\ref{sec:e1}). Table~\ref{tab:refcheck} lists the original sentences behind these paraphrases.

\section{The corridor-reservation setting and the execution-time recovery problem}
\label{sec:problem}
%% =====================================================================

\subsection{System setting and notation}
\label{sec:system_brief}

The setting follows the flexible job shop with conflict-free transportation constraints~\cite{vanos2026exact}. A feasible schedule \(\mathcal{S}^0\) is a given input;
how it was found does not affect how we delineate the occupancies to be rewritten.

\subsubsection{Shop floor and four groups of decisions}
\label{sec:shop}

The shop routing graph \(G=(V,E)\) is strongly connected. Each machine \(m\) processes through a robotic arm at node \(\mathrm{loc}(m)\), so a robotic-arm failure means a failure of that machine;
\(v_0\in V\) is the load/unload station. There are \(n\) jobs, a machine set \(M\), and a homogeneous fleet of unit-load vehicles \(K=\{1,\ldots,N_A\}\).
Job \(j\) has a fixed chain \(O_{j1}\to\cdots\to O_{jn_j}\); operation \(O_{ji}\) has candidate machines \(\Omega_{ji}\subseteq M\) and processing time \(t^P_{jim}\) on machine \(m\).
A schedule fixes (i)~the machine assignment \(x\); (ii)~the processing sequence \(\pi\) on each machine; (iii)~the vehicle assignment \(y\) of each transport; and (iv)~a conflict-free path for each vehicle move.
We write \(\mathcal{S}=(x,\pi,y,R)\), where the reservation table \(R\) records group (iv).
Transports are derived from the assignment: a transport arises when two consecutive operations are at different nodes, and it is split into an empty leg and a loaded leg, each with its own task label \(u\).
Loading and unloading times are zero. Rewritability, keeping, and rerouting are all decided at the granularity of legs, not whole operations.

\subsubsection{Corridor reservation and conflict freedom}
\label{sec:reservation}

Each corridor \(e\in E\) is an exclusive resource with traversal time \(\tau_e\), shared by both directions, which rules out head-on conflicts and overtaking.
Occupancies are half-open intervals, so a second vehicle may enter exactly at the right endpoint; nodes have ample parking capacity, so waiting at nodes is always allowed.
A reservation record \(r=(e,\,[t^s,t^e),\,k,\,u)\in R\) means that vehicle \(k\) occupies \(e\) during \([t^s,t^e)\) for leg \(u\), and distinct occupancies of the same corridor must be disjoint.
Time-window routing is the primitive shared by our method and all baselines: given origin, destination, earliest departure, and the current \(R\), it returns a path disjoint from existing occupancies.
We implement it as time-window Dijkstra~\cite{sun2023integrated} and change only \emph{which} legs are sent to it.
Unlike van Os, who reserves nodes, and Lyu, who additionally imposes node capacities~\cite{vanos2026exact,lyu2019approach}, we reserve edges.

\subsubsection{Operation-precedence graph and reservation dependency graph}
\label{sec:two_graphs}

The operation-precedence graph \(G_T=(T_T,E_T)\) has operations as vertices and job and same-machine precedence as edges; it does \emph{not} contain yielding relations between occupancies.
The reservation dependency graph \(G_R=(R,E_R)\) has occupancies as vertices and the dependencies induced by yielding, same vehicle, same job, and same machine as edges (Definition~\ref{def:dep}).
The vertex sets are disjoint, one representing processing and the other traversal; hence a disturbance that changes only corridor time windows yields no seed on \(G_T\) but a nonempty seed set on \(G_R\)
(Figure~\ref{fig:graphs}; notation in Table~\ref{tab:notation}).

\subsection{Execution-time assumptions}
\label{sec:assumptions}

A1--A4 are shared by all compared methods, so that differences can be attributed to the scope rather than the model; A5 constrains only our method.
\begin{enumerate}[label=\textbf{A\arabic*.},leftmargin=*,topsep=2pt,itemsep=1pt]
\item \textbf{Feasible initial schedule.} \(\mathcal{S}^0\) passes the conflict-freedom check before the disturbance.
\item \textbf{No backtracking on finished occupancies.} Occupancies with \(t^e\le t_{\mathrm{now}}\) are not rewritable.
\item \textbf{Single, fully observed disturbance.} Disturbance streams, prediction errors, and rolling responses are out of scope.
\item \textbf{Exclusive corridors, ample buffers, homogeneous unit-load fleet.} A blockage is injected into the routing layer as a no-entry window; finite buffers, charging, acceleration, and loading durations are not modeled.
\item \textbf{Permitted recovery actions.} For Class B, \(x\) and \(\pi\) are kept and only rerouting is performed, with scope escalation upon failure.
Class A additionally allows reassigning a failed vehicle's tasks to another vehicle, or a failed machine's unfinished operations to other feasible machines. \(\pi\) is never changed and the search is not restarted;
the global-rescheduling baseline may change \(x\) and \(\pi\) (Section~\ref{sec:vs_r0}).
\end{enumerate}

\subsection{A dichotomy of disturbances}
\label{sec:disturbance_classes}

\begin{definition}[Class A/B disturbances]
\label{def:ab}
A disturbance is of \textbf{Class A} if it directly invalidates the assignment or \emph{executability} of some operations (robotic-arm failure, processing-time deviation, rush-order insertion, vehicle failure).
It is of \textbf{Class B} if it only makes some corridor time windows unavailable without making any operation inexecutable (corridor blockage, corridor slowdown).
\end{definition}

\begin{remark}[Why vehicle failure is Class A]
\label{rem:agv_class}
A vehicle failure changes no machine assignment, but the operations the vehicle transports cannot start as planned. Through the mapping ``vehicle\(\to\)operations it transports'',
\(G_T\) still contains seed operations. This holds only if the method maintains a vehicle--task mapping; Section~\ref{sec:e6} reports results under this convention.
\end{remark}

\begin{definition}[Scopes on the operation-precedence graph and seed occupancies]
\label{def:task_impact}
\label{def:seeds}
\(T_{\mathrm{direct}}(\mathcal{D})\) is the set of operations that cannot be executed as planned; for Class B, \(T_{\mathrm{direct}}=\varnothing\) by convention.
\(T_{\mathrm{impact}}(\mathcal{D},\theta)\) collects the operations reached from \(T_{\mathrm{direct}}\) on \(G_T\) along job and same-machine successor edges within depth \(\theta\).
The seed set \(\mathrm{Src}(\mathcal{D})\subseteq R\) contains only occupancies with \(r.t^e>t_{\mathrm{now}}\) and is given by disturbance type:
(a)~\textbf{corridor blockage/slowdown} \(\mathcal{D}=(e,[t_a,t_b))\): \(\{\,r:\ r.e=e,\ [r.t^s,r.t^e)\cap[t_a,t_b)\neq\varnothing\,\}\) (for multiple windows, the union);
blockage and slowdown share this rule and differ only in rerouting, where a blockage is a no-entry window and a slowdown scales traversal progress inside the window;
(b)~\textbf{vehicle failure} \(\mathcal{D}=(k)\): \(\{\,r:\ r.k=k\,\}\);
(c)~\textbf{robotic-arm failure} \(\mathcal{D}=(m,F)\): for each job, all unfinished occupancies from its smallest operation index in \(F\) onward, so that the seeds are not shorter than the affected set on \(G_T\) when the inbound transport has already finished.
\end{definition}

\begin{prop}[The operation-precedence graph yields an empty scope for Class B]
\label{prop:miss}
Let \(\mathcal{D}\) be a corridor blockage. Then \(T_{\mathrm{impact}}(\mathcal{D},\theta)=\varnothing\) for every finite \(\theta\ge 0\).
If, in addition, \(\mathrm{Src}(\mathcal{D})\neq\varnothing\), then \(\mathcal{S}^0\) is infeasible under \(\mathcal{D}\).
\end{prop}

\begin{proof}
Since the blockage window is finite and buffers are ample (A4), vehicles can traverse outside the window, so no operation becomes inexecutable and \(\mathcal{D}\) is of Class B;
hence \(T_{\mathrm{direct}}=\varnothing\) and the \(\theta\)-step expansion is empty. If \(r\in\mathrm{Src}(\mathcal{D})\) exists, \(r\) overlaps the no-entry window on the same exclusive corridor,
which violates conflict freedom (A4); hence \(\mathcal{S}^0\) is infeasible.
\end{proof}

The first part follows from the convention; the nontrivial part is the second. Hence ``an empty scope on \(G_T\) \(\Rightarrow\) no rescheduling needed'' fails when corridors are reserved by time windows,
independently of any repair algorithm.

\subsection{The recovery problem}
\label{sec:recovery_problem}

\begin{problem}[Bounded rescheduling with the scope delineated on the reservation table]
\label{prob:recovery}
Given \(\mathcal{S}^0\), \(\mathcal{D}\), and \(t_{\mathrm{now}}\), find \(\mathcal{S}'\) such that
(i)~\(\mathcal{S}'\) is conflict-free under \(\mathcal{D}\); (ii)~occupancies outside the rewrite scope keep their corridors, intervals, and vehicles as in \(\mathcal{S}^0\) as far as possible;
(iii)~the runtime is subject to a budget. The secondary objective is the makespan \(C_{\max}(\mathcal{S}')\).
\end{problem}

Bounded rescheduling first delineates the rewritable set \(U\subseteq R\) and then reroutes only the transports in \(U\); we call the second step \emph{bounded repair} (Section~\ref{sec:repair}). We take \(U=\mathrm{Cl}(\mathrm{Src})\);
the baseline instead maps \(T_{\mathrm{impact}}\) to all occupancies whose task label lies in it and whose \(t^e>t_{\mathrm{now}}\), which is empty under Class B by Proposition~\ref{prop:miss}.
The two are denoted R2 and R1 in the experiments.

\section{The spatiotemporal reservation closure}
\label{sec:strc}
%% =====================================================================

\subsection{Reservation dependency edges}
\label{sec:closure_def}

\begin{definition}[Reservation dependency graph]
\label{def:dep}
The vertices are the occupancies in \(R\); an edge \(r\to r'\) means ``invalidating \(r\) may force \(r'\) to be rerouted''. There are four kinds of edges:
(1)~\textbf{yield edges} between occupancies of the same corridor by different vehicles whose intervals overlap \emph{or abut} (\(r.t^e=r'.t^s\)), from the earlier entrant to the later one---abutting is legal, but if the former is delayed the latter must give way;
(2)~\textbf{same-vehicle successors}, adjacent in time order;
(3)~\textbf{same-job successors}, from the occupancies of operation \(i\) to those of operation \(i+1\);
(4)~\textbf{same-machine successors}, between the occupancies induced by two operations adjacent on one machine.
This yields \(G_R=(R,E_R)\). The edge set is a modeling choice; its completeness is discussed in Remark~\ref{rem:minimality}.
\end{definition}

\begin{definition}[\STRC{}]
\label{def:strc}
Given seeds \(S\subseteq R\), a horizon \(H\), and \(t_{\mathrm{now}}\), let \(R^{\circ}=\{\,r\in R:\ r.t^e>t_{\mathrm{now}},\ r.t^s<H\,\}\) and let \(G_R^\circ\) be the subgraph induced by \(R^{\circ}\).
The reservation impact set is
\[
\mathrm{Cl}(S)=\bigl\{\,v\in R^{\circ}:\ \exists\,s\in S\cap R^{\circ}\ \text{such that}\ s\!\to^*\!v\ \text{in}\ G_R^\circ\,\bigr\},
\]
i.e., all unfinished occupancies reachable from the unfinished seeds, seeds included. We use \(H=C_{\max}(\mathcal{S}^0)+1\), so the horizon filters nothing and is kept only for rolling horizons.
With adjacency lists, \(\mathrm{Cl}(S)\) is computed by one breadth-first pass in \(O(|R^{\circ}|+|E_R^{\circ}|)\) time.
\end{definition}

\subsection{Containment}
\label{sec:containment}

\begin{prop}[Structural closure]
\label{prop:struct}
For any \(S\subseteq R\), \(G_R^\circ\) contains no edge \(u\to v\) with \(u\in\mathrm{Cl}(S)\) and \(v\in R^{\circ}\setminus\mathrm{Cl}(S)\).
\end{prop}

\begin{proof}
If such an edge existed, then \(s\to^* u\to v\) for some unfinished seed \(s\), so \(v\in\mathrm{Cl}(S)\), a contradiction.
\end{proof}

Closure is thus a corollary of the definition once the edge set is fixed; its physical completeness depends on the choice of edges.

\begin{remark}[The reservation impact set and the minimal rewritable set]
\label{rem:minimality}
Closure neither guarantees that the impact set suffices to restore feasibility nor that it is small.
First, a \emph{minimal} rewritable set is defined only relative to a repair capability (rerouting only, or also reassignment), whereas \(\mathrm{Cl}\) is determined by \(G_R\) alone and cannot be both.
Second, the edges over-include: a yield edge is created for any overlap without checking whether the later vehicle could detour, and same-vehicle edges may pull in chain tails the delay never reaches.
In the opposite direction, the known omission---abutting intervals---has been folded into the yield edges; a difference probe finds \ProbeLeaks\ leaks (\ProbeLeakPairs\ pairs), which tests this omission but does not prove completeness.
Third, empirically the impact set covers about \ClosureAliveFrac\ of the unfinished occupancies (Section~\ref{sec:e6}), less than one tenth below the trivial upper bound of rewriting all of them.
The savings of bounded repair therefore come mainly from \emph{not rewriting finished occupancies} and \emph{not restarting the search}; ``bounded'' does not mean ``small''.
Section~\ref{sec:cheap} nevertheless shows that this small difference in set size lowers the rewrite fraction significantly.
The impact-set share does not rise with instance size (Section~\ref{sec:instscale}), and static network indicators fail to predict it (Section~\ref{sec:e4}).
\end{remark}

\begin{prop}[A sufficient condition for unchanged fields outside the set]
\label{prop:outside}
Let \(U=\mathrm{Cl}(S)\), and let level-1 rerouting (Section~\ref{sec:level1}) satisfy:
(i)~the no-entry windows are written into the routing layer; (ii)~for every \(r\in R^{\circ}\setminus U\), its fields \((e,[t^s,t^e),k)\) are pre-committed to the new table and the pre-commit succeeds;
(iii)~the router generates new occupancies only for transports in \(U\); (iv)~the final schedule passes the conflict-free check.
Then the corridor, interval, and vehicle of every \(r\in R^{\circ}\setminus U\) in the recovered table agree with \(\mathcal{S}^0\).
The quantifier ranges over occupancies, not tasks.
\end{prop}

\begin{proof}
By (ii), occupancies outside the set enter the new table with their original fields before the replay; by (iii), the replay neither deletes nor rewrites them; the check in (iv) only rules out conflicts and alters no committed field.
\end{proof}

Premises (i)--(iv) are execution conditions that can be checked against Algorithm~\ref{alg:replay}; beyond them, the proposition relies on A1, A2, and A4.
A failed pre-commit indicates an incomplete seed set. If scope escalation enlarges \(U\), the proposition holds only for the occupancies finally left outside.
Premise (iii) is easily violated in practice when rerouting is decided at a unit coarser than an occupancy; Section~\ref{sec:e2} reports such a case.

\subsection{Level-1 rerouting}
\label{sec:level1}

Given \(U\), level-1 rerouting keeps the vehicle and machine assignments and replays in the original processing order (Algorithm~\ref{alg:replay}).
It operates at the granularity of corridor segments: segments traversed before \(t_{\mathrm{now}}\) are pre-committed unchanged, and planning starts from the vehicle's node at that time.
Delineating the scope takes one breadth-first pass, whereas the replay calls the router once per leg in \(U\); the latter dominates the runtime. No population-based search is launched.
Section~\ref{sec:e3} fixes this procedure and replaces only the source of \(U\), so that differences in feasibility can be attributed to the scope object.

\begin{algorithm}[t]
\caption{Level-1 rerouting replay \(\textsc{ReplayReroute}\)}
\label{alg:replay}
\begin{algorithmic}[1]
\Require schedule \(\mathcal{S}^0=(x,\pi,y,R)\), disturbance \(\mathcal{D}\), rewritable set \(U\), time \(t_{\mathrm{now}}\)
\Ensure schedule \(\mathcal{S}'\) or failure
\State write \(\mathcal{D}\) into the routing layer \Comment{blockage: no-entry window; slowdown: scaled \(\tau\)}
\State \(R'\gets\varnothing\)
\For{each occupancy outside \(U\), and each \(r\in U\) with \(r.t^e\le t_{\mathrm{now}}\)}
  \State pre-commit its original fields \((e,[t^s,t^e),k)\) to \(R'\); \textbf{if} it conflicts with a no-entry window \textbf{then return} failure
\EndFor
\For{each \(r\in U\), in the original processing order}
  \State route from the vehicle's node at \(t_{\mathrm{now}}\) on the current \(R'\) and commit the new occupancies
\EndFor
\State advance machine idle times and job ready times according to \(\pi\)
\State \textbf{if} independent check passes (no conflicts, fields outside \(U\) unchanged) \textbf{then return} \(\mathcal{S}'=(x,\pi,y,R')\) \textbf{else return} failure
\end{algorithmic}
\end{algorithm}

\subsection{Scope escalation after failure}
\label{sec:scope_escalation}

Escalating the scope has precedents: Local Rescheduling~\cite{kuster2007local} relaxes the time window step by step, and AOR adds successor operations (Section~\ref{sec:rw_aor}); we escalate along reservation dependencies.
When keeping the occupancies outside \(U\) is too restrictive, the replay may fail at a transport--operation hand-off; we then enlarge \(U\) and retry:
(i)~add the unfinished occupancies in the same-job suffixes of operations in \(U\); (ii)~add those in the same-vehicle suffixes of the vehicles involved; (iii)~set \(U\leftarrow R^{\circ}\).
Each round remains a deterministic single pass (Algorithm~\ref{alg:strc_repair}).

\begin{algorithm}[t]
\caption{Bounded repair on the reservation impact set (level-1 rerouting + scope escalation)}
\label{alg:strc_repair}
\begin{algorithmic}[1]
\Require schedule \(\mathcal{S}^0\), disturbance \(\mathcal{D}\), time \(t_{\mathrm{now}}\)
\Ensure schedule \(\mathcal{S}'\) or failure
\State \(U \gets \mathrm{Cl}(\mathrm{Src}(\mathcal{D}))\)
\For{round \(=0,1,2,3\)}
  \State \(\mathcal{S}' \gets \textsc{ReplayReroute}(\mathcal{S}^0,\mathcal{D},U,t_{\mathrm{now}})\); \textbf{if} \(\mathcal{S}'\) is feasible \textbf{then return} \(\mathcal{S}'\)
  \State update \(U\) by the scope-escalation rule \Comment{job suffix / same vehicle / all unfinished}
\EndFor
\State \Return failure
\end{algorithmic}
\end{algorithm}

\subsection{Comparison with global rescheduling}
\label{sec:vs_r0}

The global rescheduling baseline R0+ is a genetic algorithm that encodes \((x,\pi)\) as a chromosome, is warm-started from \(\mathcal{S}^0\), and searches under the same no-entry constraints within a wall-clock budget.
One \emph{decoding} routes all transports from scratch on the table with the no-entry windows written in; finished occupancies are pre-committed, and only operations not yet started are scheduled from \(t_{\mathrm{now}}\).
Because R0+ can reassign and resequence, it is more likely to shorten \(C_{\max}\), but its runtime is set by the budget.
Bounded repair is therefore not expected to win on makespan; its strength is runtime. To test whether scoping on the impact set matters \emph{within} a millisecond runtime,
Section~\ref{sec:cheap} adds three millisecond baselines (RS, RD, RA), of which RA differs from our method only in which occupancies are rewritable.

\subsection{Protocol}
\label{sec:protocol}

\textbf{Instances.}
The main batch has five instances: the small \texttt{example\_3x3x2}, the congested dumbbell \texttt{congested\_8x4x4}, and three generated \texttt{S8x4x4} layouts (\texttt{high}, \texttt{funnel}, \texttt{mid})
that share size and flexibility and differ only in corridor topology. Generator parameters and the generation seed (\(42\)) are encoded in the file names; the generation seed is independent of the run seeds.
We use ten run seeds (\(42,7,2024,99,123,13,1,777,31415,8\)), giving \(\NInst\times\NSeeds=\NPairs\) instance--seed pairs (``cells'').
All cell-wise comparisons and paired tests are aligned on the key (instance, seed), under which all methods read the same initial schedule, blockage, and decision time.
The initial schedule is obtained by replaying the time-window router in processing order and passes the independent check.

\textbf{Second batch with external layouts.}
To ensure that the layouts are not chosen by us, a second batch of \NPubInst\ instances (\NPubPairs\ pairs) transcribes the grid, station and machine placement, and missing edges from Appendix~A of Lyu et al.~\cite{lyu2019approach},
reconciled by script against the encoding shipped with the van Os toolkit. All other parameters are matched to the main batch, so the two batches differ only in layout source.
We omit the \(3\)-machine layout, which cannot give every operation two candidate machines at \(f=0.6\). The five remaining layouts lie on only \NPubNets\ distinct networks
(\(4\times4\) with \(4\) or \(5\) machines; \(5\times5\) with \(6\), \(7\), or \(8\) machines), so along network geometry there are \NPubNets\ independent samples.
Per-edge durations of these layouts were never published, so we use equal weights; the separate loading and unloading stations are merged into one; and their job data are not used,
because in public instance families transport takes only a few percent of processing time and corridor contention would be unobservable.
This batch therefore serves as a set of topologies not designed by us, not as a reproduction of published reference values.

\textbf{Disturbances.}
Unless noted otherwise, \(t_{\mathrm{now}}=0.35\,C_{\max}(\mathcal{S}^0)\). E1--E3, E5, and E7 block a busy corridor in a single window; E6 adds three further types; E4 blocks a corridor in the load/unload minimum cut;
the magnitude sweep takes the future reservation windows of the first fraction \(\varphi\) of future operations as micro-blockages.

\textbf{Metrics.}
An occupancy counts as \emph{rewritten} if its corridor, interval, or vehicle after repair differs from \(\mathcal{S}^0\); the \emph{rewrite fraction} is the share of rewritten occupancies in the whole table \(R\).
It differs from the \emph{rewritable share} \(|U|/|R^{\circ}|\), which counts the occupancies a method is allowed to change.
Makespan \emph{degradation} is \((C_{\max}(\mathcal{S}')-C_{\max}(\mathcal{S}^0))/C_{\max}(\mathcal{S}^0)\).
A \emph{finished-occupancy violation} is a rewritten occupancy with \(t^e\le t_{\mathrm{now}}\), which A2 forbids.

\textbf{Methods and conventions.}
Table~\ref{tab:baselines} lists the methods. R1 transplants AOR scoping~\cite{abumaizar1997rescheduling,subramaniam2003maor} into our reservation setting: the \(\theta\)-hop truncation and the mapping from operations to reservations are ours,
since the original setting has no reservation table; its results reflect the rule in this setting, not the original method in its own.
R1/R2 differ only in the scope \emph{object}, RA/R2 only in \emph{whether} the scope is restricted, and RD/R0+ only in how long they search.
Only R0+ terminates on a budget; all others are deterministic single passes, so the comparison among them in Section~\ref{sec:cheap} is the like-for-like one.
Scope escalation is disabled in E3, E5, and E7, so that a fallback to all unfinished occupancies cannot mask the difference between scope objects; its end point is RA, measured separately.
It is enabled in the magnitude sweep.
The main batch establishes the phenomena under full control of the instance parameters; the second batch only tests whether they depend on our layouts, and is pooled with the main batch only in E5.

\textbf{Implementation and statistics.}
All code is pure Python 3.7 (standard library only), run single-threaded on an Intel Xeon W-1270 with 64\,GB RAM under Windows~10; runtime conclusions are stated as ratios or orders of magnitude.
Code, instances, disturbance inputs, cell-wise CSV results, and the scripts generating every table and figure are available as an anonymous repository during review and will be archived with a DOI upon acceptance.
The paper contains two inferential tests, both in Section~\ref{sec:cheap}: R2 versus RA on rewrite fraction (primary) and R2 versus RD on makespan, each a two-sided Wilcoxon signed-rank test paired on the cell key;
Holm correction does not change either conclusion. For the primary test, the Hodges--Lehmann estimate is \(0.037\) (bootstrap \(95\%\) CI \([0.018,\,0.074]\), \(10^4\) resamples) and the mean paired difference is \RAStabMean\ (CI \([0.039,\,0.093]\)).
All other counts, means, and medians are descriptive.

\subsection{E4: static structure does not predict the impact-set size (exploratory)}
\label{sec:e4}

We test whether the impact-set share can be predicted from the network alone, using the load/unload minimum cut (LU cut), the funnel share, and corridors per node, while blocking a corridor in the LU cut.
On the in-house layouts the answer is inconclusive: in a heavier setting (\(12\) jobs, \(8\) machines, \(12\) vehicles, five seeds), \texttt{funnel} has a higher median share than \texttt{high} (\(0.254\) vs.\ \(0.204\)),
but the per-seed ranges overlap (\([0.180,0.309]\) vs.\ \([0.156,0.372]\)) and one seed reverses the order. Since these layouts differ little in geometry, ``the indicator is too coarse'' cannot be told apart from ``the instances are too similar''.
The external layouts separate the two (Table~\ref{tab:e4pub}). On the same \(4\times4\) network, moving from \(4\) to \(5\) machines changes the median share by \PubCloSpread; on the same \(5\times5\) network, three machine configurations span \PubCloSpreadBig;

and corridors per node takes only two values. \textbf{A constant indicator cannot explain a varying quantity}: static cuts do not determine the impact-set size, and the machine-configuration dimension cannot be ignored.
Because the in-house side varies only the network, this does not show that machine configuration matters more than geometry.
The result is negative and supports none of the contributions; Section~\ref{sec:future} points to schedule-dependent candidates.

\subsection{E5: trade-off against global rescheduling}
\label{sec:e5}

We test whether a \emph{crossover} exists, i.e., whether R0+ overtakes bounded repair in \(C_{\max}\) only once the budget is relaxed. R2 is a single deterministic computation, so its \(C_{\max}\) does not vary with the budget;
with the seed fixed, a larger budget lets R0+ run the same trajectory for more generations, so its best-so-far \(C_{\max}\) is non-increasing.

\textbf{The only faster feasible method is the right shift, and it is worse on both makespan and rewriting.}
RS needs \MsShift\,ms, about half of R2, but degrades the makespan by \(58.8\%\) versus \(49.8\%\) (R2 win/tie/loss \WinVsShift) and rewrites more (\ResFracShift\ vs.\ \ResFracCheapRtwo).
Making the shift selective would first require determining which occupancies are affected---precisely the scope delineated here. (R1 is faster still, but feasible in only \FeasRone\ cells.)

\textbf{Even the fastest global recomputation is slower.} RD takes \MsRedecode\,ms, \RedecodeRatio\ times R2, and any decoding-based search needs at least one decoding per candidate;
the speed gap in E5 is therefore not an artifact of a slow baseline.
On makespan, R2 and RD are indistinguishable (\WinVsRedecode; mean paired difference \(+0.006\), CI \([-0.007,\,0.019]\); Wilcoxon \(p=0.12\)), while RD rewrites more (\ResFracRedecode).

\textbf{The reduction in rewriting is established only by R2 versus RA.}
On average the impact set excludes only \(1-\ClosureShareMean\) of the unfinished occupancies (\ClosureShareLo--\(1.00\) per cell; in \(6\) cells the two sets coincide).
This small difference lowers the rewrite fraction from \ResFracAllFuture\ to \ResFracCheapRtwo\ (mean reduction \RAStabMean, median \RAStabMed, per cell \RAStabWTL\ for R2 fewer/equal/more rewrites, \(p=\RAStabP\);
excluding the \(6\) identical cells, \RAStabWTLNet\ with mean \RAStabMeanNet), while runtimes (\MsCheapRtwo\ vs.\ \MsAllFuture\,ms) and makespans (mean ratio \RACmaxRatio; R2 never worse) are nearly identical.
These results must be read together. \textbf{Equal runtime shows that the millisecond response comes from single-pass rerouting, not from the impact set; equal makespan shows that the impact set is not an optimization device;
the lower rewrite fraction is exactly the property guaranteed by Proposition~\ref{prop:outside}.}
At equal speed and makespan, forgoing the impact set rewrites about \(6\) percentage points more occupancies (about \(12\%\) relatively).
The reduction grows as the impact set excludes more: \(0.010\) on \texttt{congested\_8x4x4} (rewritable share \(0.94\)) versus \(0.118\) on \texttt{S8x4x4\_mid} (\(0.91\)).

\section{Conclusion}
\label{sec:conclusion}
%% =====================================================================

When a flexible job shop records corridor occupancies with time windows, the operation-precedence graph contains no yielding relations between occupancies and cannot capture disturbances that invalidate only occupancies:
under corridor blockage, operation-level scoping is empty although the original schedule is infeasible (\(\PassMiss\), C1).
Delineating the scope on the reservation dependency graph makes the occupancies to be rewritten uniquely determined by the given relations rather than by a heuristic radius (\(\PassClosed\), \(\PassInvar\), C2),
and with the same rerouting and only the scope object changed, feasibility goes from \(\FeasRone\) to \(\FeasRtwo\) (C3).
Rewriting all unfinished occupancies instead leaves runtime and makespan almost unchanged but raises the rewrite fraction from \ResFracCheapRtwo\ to \ResFracAllFuture.
Hence the millisecond response comes from single-pass rerouting, and \textbf{the benefit attributable to the impact set is that occupancies outside it are kept as planned} (Proposition~\ref{prop:outside});
this benefit shrinks as the impact set approaches the set of all unfinished occupancies.
Yielding relations, rerouting inside the set, and scope escalation are taken from existing practice.

\subsection{Limitations and future work}
\label{sec:limitations}
\label{sec:future}

We list four limitations in order of their impact, each followed by the corresponding direction.

\begin{enumerate}[leftmargin=1.6em,itemsep=0.3em]
\item \textbf{Makespan.} Bounded repair is worse than warm-started global rescheduling at every tested budget, with no crossover (Section~\ref{sec:e5}).
Since neither method rewrites finished occupancies, the gap concerns \(C_{\max}\) alone; narrowing it would require limited reassignment or resequencing, which drifts toward global rescheduling.

\item \textbf{Strength and tightness of the guarantee.} Proposition~\ref{prop:outside} is only a sufficient condition, the edge set has not been verified exhaustively, and the impact set covers about \ClosureAliveFrac\ of the unfinished occupancies.
The probe finds \ProbeLeaks\ leaks for the known abutting omission; other disturbance forms (shortened occupancies, longer delays) should be probed next.
Tightness calls for a minimal rewritable set defined for a fixed repair capability and a quantified gap to the impact set.
Static cut indicators cannot predict the impact-set size (Section~\ref{sec:e4}); the next candidates are schedule-dependent, e.g., the number of overlapping occupancies on the disturbed corridor near \(t_{\mathrm{now}}\) and its out-degree in the yielding graph.

\item \textbf{Scope of the implementation.} Class B is handled by rerouting only, Class A adds vehicle swapping and reassignment without resequencing, and only a single disturbance is handled (A3).
Size has been extended to \(\ScaleJobsHi\) jobs and \(\ScaleMachHi\) machines, but not enough to support asymptotic claims.
The next step is to relax A3 and examine whether the impact set inflates under continual disturbances and whether a restoration step is needed between repairs.

\item \textbf{External reference points.} The public instance families~\cite{homayouni2021production,bilge1995time} publish machine-to-machine travel-time matrices; none of their \(11\) layouts can be reconstructed as a corridor graph consistent with the matrix,
so \(R\), \(G_R\), \(\mathrm{Cl}(\cdot)\), and Class B disturbances cannot be defined on them. Our second batch externalizes only the layouts~\cite{lyu2019approach}; travel times and job data are still our own, so the reference values of Lyu et al.\ or van Os~\cite{vanos2026exact} cannot be reproduced.
An instance family publishing both exclusive corridors and per-leg durations is still needed, and a second implementation can be carried out together with such a reproduction.
\end{enumerate}
