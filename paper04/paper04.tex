\begin{abstract}
In flexible job shop scheduling that captures processing order with an operation-precedence graph and records the corridor occupancies of vehicles in a time-window reservation table,
the rescheduling scope after a disturbance is still delineated by affected-operation rescheduling (AOR): operations that can no longer be executed as planned are identified, and their successors on the operation-precedence graph are added.
Corridor blockage or slowdown acts only on corridors; machines and operations remain available, so AOR finds no affected operation and returns an empty scope, concluding that no rescheduling is needed.
Yet the planned occupancies inside the disturbed interval are already invalid and the original schedule is infeasible;
moreover, a corridor admits one vehicle at a time, so a vehicle planned to traverse it later must wait for the preceding one (a yielding relation), and a delay passes from vehicle to vehicle.
The problem is not detection (the blockage is known) but that the operation-precedence graph used by AOR contains only operations and their precedences, with neither corridor occupancies nor the yielding relations among them.

We instead delineate the rescheduling scope at the level of corridor occupancies and propose the spatiotemporal reservation closure (\STRC), whose output set of occupancies is called the reservation impact set.
Starting from the planned occupancies whose intervals overlap the disturbed interval, \STRC{} keeps adding successor occupancies along four dependency relations among occupancies---yielding on the same corridor, and the next occupancy of the same vehicle, of the same job, and on the same machine---until none can be added (the transitive closure).
Each occupancy is determined by its corridor (path), interval, and vehicle: occupancies inside the set may have their path and interval replanned (and, under vehicle failure, their vehicle replaced), while those outside keep all three.
Once the four relations are fixed, membership in the set depends only on reachability from the seeds and is independent of the rerouting algorithm.
Bounded repair first replans conflict-free paths for the occupancies inside the set with the original vehicles; if the schedule remains infeasible, it successively adds the subsequent occupancies of the same job, of the same vehicle, and finally all unfinished occupancies to the rewritable scope.

On \NPairs\ instance--seed pairs (\NInst\ instances \(\times\) \NSeeds\ random seeds that determine disturbance injection and search), the scope delineated by AOR under corridor blockage is empty on all pairs, although the original schedule is in fact infeasible on every one of them;
with the rerouting procedure unchanged and only the scope object replaced, the number of pairs repaired to a feasible schedule rises from \FeasRone\ to \FeasRtwo.
On all pairs the impact set is closed (no dependency edge leads from inside to outside), and every occupancy outside it keeps its original corridor, interval, and vehicle after repair.
Rewriting all unfinished occupancies instead leaves runtime and makespan almost unchanged but raises the fraction of rewritten occupancies from \ResFracCheapRtwo\ to \ResFracAllFuture\ (scoping by the impact set rewrites fewer/equally many/more on \RAStabWTL\ pairs; Wilcoxon \(p=\RAStabP\)).
Compared with warm-started global rescheduling that re-searches assignment and order within a time limit, bounded repair is two to three orders of magnitude faster, but its makespan is never better under any tested time limit and cannot overtake under longer limits.
Feasibility is thus restored by the scope object; the reduction in rewrites is limited because the impact set already covers about \ClosureAliveFrac\ of all unfinished occupancies.
Rerouting inside the set and enlarging the scope after failure follow existing practice; the contribution lies in delineating the rescheduling scope on corridor occupancies instead of operations.
\end{abstract}

\section{Introduction}
\label{sec:introduction}
%% =====================================================================

Flexible job shop scheduling with transportation usually takes transport times as constants indexed by location pairs~\cite{xin2025review,meng2025cp,qin2026knowledge}, assuming no corridor contention among vehicles.
When a finite fleet shares a sparse corridor network this no longer holds~\cite{kim2026congestion}, so existing work decides machine assignment jointly with conflict-free paths before execution~\cite{vanos2026exact,sun2023integrated,lyu2019approach,li2026framework},
and a schedule then also contains a time-window reservation table recording which vehicle occupies which corridor during which interval.
A disturbance may make operations unexecutable (e.g., machine or vehicle failure) or invalidate only some corridor occupancies without changing any operation (e.g., a corridor blocked or slowed down for some period).
These works answer how to build a conflict-free schedule when information is complete. Once the shop has executed up to time \(t_{\mathrm{now}}\) and a disturbance occurs, the questions become:
which corridor occupancies are invalidated; which must be rewritten so that the schedule again satisfies corridor exclusivity and the closure constraints and can continue to be executed;
and whether such a schedule can be obtained within milliseconds of computation time without restarting a population-based search.

\textbf{The gap.}
In dynamic scheduling of flexible job shops with transportation, the rescheduling scope is usually delineated on the operation-precedence graph:
operations that can no longer be executed as planned serve as seeds, the operations following them in the same job and on the same machine are added, possibly only up to \(\theta\) steps (a manually set upper bound on the expansion depth),
and only the operations in this scope are rescheduled.
Existing dynamic scheduling studies with AGV transport delineate the scope in this way~\cite{zhang2023energy,tang2026dynamic}, a practice represented by affected-operation rescheduling (AOR) and its modification MAOR~\cite{subramaniam2003maor}.
This is reasonable when the disturbance is an operation event, such as a machine failure.
When the schedule records corridor occupancies with time windows, however, a \emph{corridor blockage} closes a corridor during \([t_a,t_b)\) without modifying any machine assignment or processing order; machines and operations remain available.
The seed set of AOR (operations that can no longer be executed as planned) is therefore empty, so the scope is empty and the method concludes that no rescheduling is needed.
Yet the planned occupancies that overlap the blockage interval are no longer feasible.
Moreover, a corridor admits one vehicle at a time, so a vehicle planned to traverse it later must wait for the preceding one to leave (a yielding relation); a vehicle delayed by waiting or detouring therefore delays its follower, which delays its own follower, and the invalidation propagates across the reservation table.
The blockage itself is known, so the problem is not detection: the operation-precedence graph used by AOR has operations as vertices and job and machine precedences as edges,
and by definition contains neither corridor occupancies nor their yielding relations, so it cannot express this invalidation or its propagation;
the gap arises only in settings that record corridor occupancies with time windows.
We accordingly distinguish \textbf{Class A} disturbances, which make some operations unexecutable (robotic-arm failure, processing-time deviation, rush orders, vehicle failure),
from \textbf{Class B} disturbances, which act only on the reservation table (corridor blockage, corridor slowdown); under Class B, scoping on the operation-precedence graph returns an empty scope (Section~\ref{sec:disturbance_classes}).
Figure~\ref{fig:motivate} illustrates the gap.

\textbf{Stance.} The reservation impact set answers only \emph{which occupancies are already invalid}, not \emph{how the schedule should be changed}.
We use the dependencies only to decide invalidity: an occupancy reachable from the seeds belongs to the impact set, one that is not does not.
These relations are not used to steer the search or to change assignments and paths; that is a decision problem of schedule improvement outside our scope.
The impact set is not necessarily the minimal set needed to restore feasibility, because the minimal set depends on the permitted repair actions (Remark~\ref{rem:minimality}).
Its role also differs from that of global rescheduling: it answers whether feasibility can be restored \emph{quickly} while confining rewrites to the set, not whether a better makespan can be found.
Confining rewrites matters because every rewritten occupancy is a route or time window that must be reissued to a vehicle already executing the plan; keeping the rest unchanged is a form of schedule stability~\cite{vieira2003rescheduling}.

\textbf{Contributions.}
\begin{enumerate}[label=\textbf{C\arabic*.},leftmargin=2.2em,itemsep=0.3em]
\item \textbf{A class of invalidation the operation-precedence graph cannot capture.}
Under corridor blockage and slowdown, operation-level scoping returns an empty scope although the original schedule is infeasible (\(\PassMiss\), Section~\ref{sec:e1});
the root cause is that the operation-precedence graph has no yielding relations among occupancies (Proposition~\ref{prop:miss}).
\item \textbf{The reservation impact set as the rescheduling scope.}
\STRC{} delineates the scope by closure over yielding and same-vehicle, same-job, and same-machine succession. Membership is uniquely determined and no dependency edge leaves the set.
The set is nonempty under all four disturbance types and, under Class A disturbances, contains every occupancy already included by the operation-precedence graph (Section~\ref{sec:e6}).
With the same rerouting, it rewrites fewer occupancies than rewriting all unfinished ones (fewer/equal/more on \RAStabWTL\ pairs; Section~\ref{sec:cheap}).
\item \textbf{A matching local recovery with the sources of each result separated.}
Under the same network, router, and checker, scoping on the operation-precedence graph yields an executable schedule on \(\FeasRone\) corridor-blockage pairs, scoping on the impact set on \(\FeasRtwo\) (Section~\ref{sec:e3}).
Bounded repair takes milliseconds, but its makespan is no better than that of global rescheduling under every tested time limit, and relaxing the limit does not reverse this order (Section~\ref{sec:e5});
against rewriting all unfinished occupancies, runtime and makespan are almost identical, so the millisecond runtime comes from single-pass rerouting, not from the impact set (Section~\ref{sec:cheap}).
\end{enumerate}
Integrated scheduling before execution uses the reservation table to build a conflict-free plan; this paper uses the same table at execution time to locate the invalidated scope.

Section~\ref{sec:related_work} reviews related work; Section~\ref{sec:problem} states the setting and the recovery problem; Section~\ref{sec:strc} defines \STRC{} and its properties;
Section~\ref{sec:repair} describes bounded repair; Section~\ref{sec:experiments} reports the experiments; Section~\ref{sec:conclusion} concludes.

\section{Related work}
\label{sec:related_work}
%% =====================================================================

A basic question in dynamic scheduling is how to delineate the rescheduling scope: which operations, corridor occupancies, or vehicles must be replanned after a disturbance, while everything outside the scope keeps the original plan.
We review four classes of objects on which the scope has been delineated and compare them with this paper in Table~\ref{tab:position}.

\subsection{Local rescheduling in job shops}
\label{sec:rw_aor}

For operation-level events, delineating the scope by the affected operations is still common in dynamic scheduling with AGVs.
Zhang et al.~\cite{zhang2023energy} reschedule the operations not yet processed after a machine breakdown;
Tang et al.~\cite{tang2026dynamic} classify disrupted operations and delivery tasks as retained, continued, or reconstructed, and compare full rescheduling, partial rescheduling, and right shift.
AOR and MAOR~\cite{subramaniam2003maor} reschedule only the operations directly or indirectly affected.
Delineating the scope along the time axis and enlarging it after failure have also been studied, including match-up, which reschedules only up to a point where the original schedule can be resumed~\cite{qiao2012single,salido2017rescheduling},
and Local Rescheduling with incrementally enlarged time windows~\cite{kuster2007local}; right shift instead postpones the entire unfinished part.
Rolling-horizon methods solve overlapping shorter-horizon subproblems in sequence~\cite{li2025learning}, and decomposition methods split the job set along its precedence structure~\cite{margot2003decompositions}; see~\cite{vieira2003rescheduling,ouelhadj2009survey} for surveys.
Delineating a scope and rescheduling locally within it is thus a fairly general practice, but these works start the delineation from disturbed operations;
when a disturbance only makes a corridor impassable, there is no such operation, so the scope is necessarily empty although the schedule is infeasible.

\subsection{Occupancy order on exclusive resources}
\label{sec:rw_ag}

The alternative graph of Mascis and Pacciarelli~\cite{mascis2002alternative} generalizes the disjunctive graph: vertices are occupations of block sections,
fixed arcs encode route precedence, and paired alternative arcs encode which train passes first; D'Ariano et al.~\cite{dariano2007branch} use it for real-time train rescheduling.
An alternative arc captures the order in which two trains pass the same block section, the same kind of occupancy order as our yielding relation.
In the alternative graph this order is a decision variable, chosen so that no positive cycle arises and the objective is optimized;
railways treat block sections as machines, so an unavailable section appears directly on the graph and the problem studied here does not arise.
We instead use the already fixed order only to determine which occupancies must be replanned after the disturbance.

\subsection{Local replanning in conflict-free multi-vehicle routing}
\label{sec:rw_mapf}

In multi-agent path finding (MAPF), replanning only the affected agents is standard.
\v{S}vancara et al.~\cite{svancara2019online} compare Replan All, Replan Single, and Replan Affected, determining the affected agents by independence detection;
Malka et al.~\cite{malka2024online} replan only the agents affected by observed map changes; lifelong MAPF treats spatiotemporal occupancy as a first-class constraint~\cite{zhang2024guidance}.
MAPF, however, has no job--operation--machine assignment, so operation-level scoping cannot miss a blockage there,
and its affected set is the output of a detection algorithm that varies with the implementation, whereas the reservation impact set is fixed once the edges are given (Section~\ref{sec:containment}).

\subsection{Flexible job shop scheduling with transportation}
\label{sec:rw_position}

Much recent work still takes travel times as a constant matrix~\cite{xin2025review,meng2025cp,qin2026knowledge} or as load-dependent times with an aggregate congestion delay~\cite{jafarian2026integrated}; neither records corridor occupancies, so a corridor blockage has no counterpart.
Congestion-aware dispatching selects vehicles by proxies such as local density~\cite{kim2026congestion}.
Van Os and Basten~\cite{vanos2026exact} formalize flexible job shop scheduling with conflict-free transportation and solve most benchmark instances to optimality;
two-stage schemes first fix production and then resolve vehicle conflicts~\cite{sun2023integrated}; a learning-based scheduling layer can be coupled with a conflict-resolving routing layer~\cite{li2026framework}.
These works build a conflict-free schedule \emph{before} execution and do not handle execution-time disturbances (e.g., Sun et al.~\cite{sun2023integrated} assume that AGVs are always available),
whereas the dynamic scheduling works with AGVs in Section~\ref{sec:rw_aor} do not model corridor contention (e.g., Zhang et al.~\cite{zhang2023energy} ignore AGV collisions).
In flexible job shop scheduling with transportation, a reservation table and execution-time disturbances have thus not yet appeared together;
when both are present, the only directly applicable practice is operation-level scoping, which yields an empty scope for a corridor blockage (\PassMiss, Section~\ref{sec:e1}).

The channels must match those along which invalidation actually propagates: AOR follows only jobs and machines and thus obtains an empty scope under a blockage,
while relations that do not propagate invalidation would only enlarge the scope.

inside the scope, routes and intervals (and, under a vehicle failure, vehicles) may change, while machine assignment and processing sequence stay fixed.

\section{The corridor-reservation setting and the execution-time recovery problem}
\label{sec:problem}
%% =====================================================================

\subsection{System setting and notation}
\label{sec:system_brief}

The problem belongs to flexible job shop scheduling with conflict-free transportation constraints, so we build on the formulation of van Os and Basten~\cite{vanos2026exact}; the two differ in what is reserved (Section~\ref{sec:reservation}).
The pre-disturbance schedule \(\mathcal{S}^0\) is a given input; delineation depends only on \(\mathcal{S}^0\) itself (assignment, sequence, and reservation table), not on how it was obtained, so \(\mathcal{S}^0\) may come from any scheduling method.

\subsubsection{Shop floor and four groups of decisions}
\label{sec:shop}

The shop routing graph \(G=(V,E)\) is strongly connected. Each machine \(m\) processes through a robotic arm at node \(\mathrm{loc}(m)\), so a robotic-arm failure means a failure of that machine;
\(v_0\in V\) is the load/unload station. There are \(n\) jobs, a machine set \(M\), and a homogeneous fleet of unit-load vehicles \(K=\{1,\ldots,N_A\}\).
Job \(j\) has a fixed chain \(O_{j1}\to\cdots\to O_{jn_j}\); operation \(O_{ji}\) has candidate machines \(\Omega_{ji}\subseteq M\) and processing time \(t^P_{jim}\) on machine \(m\).
A schedule fixes (i)~the machine assignment \(x\); (ii)~the processing sequence \(\pi\) on each machine; (iii)~the vehicle assignment \(y\) of each transport; and (iv)~a conflict-free path for each vehicle move.
We write \(\mathcal{S}=(x,\pi,y,R)\), where the reservation table \(R\) records group (iv).
Transports are not fixed parameters but are determined by the machine assignment: a transport is needed only when two consecutive operations of a job are assigned to machines at different nodes.
Each transport is split into an \emph{empty leg}, in which the vehicle travels unloaded from its current position to the machine of the preceding operation to pick up the job, and a \emph{loaded leg}, in which it carries the job to the machine of the succeeding operation; each leg has its own task label \(u\).
Loading and unloading times are zero. Rewritability, keeping, and rerouting are all decided per transport leg, not per transport or operation.

\subsubsection{Corridor reservation and conflict freedom}
\label{sec:reservation}

Each corridor \(e\in E\) is an exclusive resource with traversal time \(\tau_e\), treated as a single lane: a vehicle in either direction occupies the whole corridor, so neither head-on encounters nor overtaking can occur,
as with the narrow aisles and zone control common in AGV shops (a two-lane corridor can be modeled as two corridors).
Occupancies are half-open intervals, so a following vehicle may enter exactly when the preceding one leaves; vehicles wait only at nodes, which have ample parking capacity, and never inside a corridor.
A reservation record \(r=(e,\,[t^s,t^e),\,k,\,u)\in R\) means that vehicle \(k\) occupies \(e\) during \([t^s,t^e)\) for leg \(u\), and distinct occupancies of the same corridor must be disjoint.
Paths use only time slots not yet occupied in \(R\), so the table stays conflict-free without a posterior check.
Time-window routing is the basic module shared by our method and all baselines: given origin, destination, earliest departure, and the current reservation table \(R\), it returns a path whose occupancies overlap no existing one.
We implement it as time-window Dijkstra~\cite{sun2023integrated} and change only \emph{which} legs are handed to it.
Van Os et al.\ reserve nodes~\cite{vanos2026exact} and Lyu et al.\ add node capacities~\cite{lyu2019approach}; we reserve only corridors (network edges), so our results are not directly comparable with their reported values (Section~\ref{sec:limitations}).

\subsubsection{Operation-precedence graph and reservation dependency graph}
\label{sec:two_graphs}

The operation-precedence graph \(G_T=(T_T,E_T)\) has operations as vertices and two kinds of directed edges: job precedence, from \(O_{ji}\) to \(O_{j,i+1}\), and same-machine precedence, from an operation to the one processed immediately after it on the same machine; it contains no occupancies and hence no yielding relations.
The reservation dependency graph \(G_R=(R,E_R)\) has corridor occupancies as vertices; an edge \(r\to r'\) means that invalidating \(r\) may force \(r'\) to be rerouted.
Its yield and same-vehicle edges link consecutive occupancies of the same corridor and of the same vehicle, and its same-job and same-machine edges carry the precedences of \(G_T\) over to the \emph{transport occupancies} of operations, i.e., the occupancies of the legs that move the job for that operation (Definition~\ref{def:dep}).
The vertex sets are disjoint; hence a disturbance that changes only when corridors are passable yields no seed on \(G_T\), whereas on \(G_R\) every planned occupancy overlapping the disturbed interval---exactly what makes the schedule infeasible---is a seed
(Figure~\ref{fig:graphs}; notation in Table~\ref{tab:notation}).

\subsection{Execution-time assumptions}
\label{sec:assumptions}

A1--A4 are shared by all compared methods, so that differences can be attributed to the scope rather than the model; A5 constrains only our method, while the global-rescheduling baseline may also change the machine assignment and processing sequence.
\begin{enumerate}[label=\textbf{A\arabic*.},leftmargin=*,topsep=2pt,itemsep=1pt]
\item \textbf{Feasible initial schedule.} \(\mathcal{S}^0\) passes the conflict-freedom check before the disturbance.
\item \textbf{No backtracking on finished occupancies.} Occupancies with \(t^e\le t_{\mathrm{now}}\) are not rewritable.
\item \textbf{Single, fully observed disturbance.} Successive disturbances, estimation errors in disturbance information, and repeated rescheduling as new information arrives are out of scope.
\item \textbf{Exclusive corridors, ample buffers, homogeneous unit-load fleet.} A blockage is injected into the routing layer as an interval during which the corridor may not be entered (the \emph{blockage window}); finite buffers, charging, acceleration, and loading durations are not modeled.
\item \textbf{Permitted recovery actions.} For Class B, \(x\) and \(\pi\) are kept and only rerouting is performed, with scope escalation upon failure.
Class A additionally allows reassigning a failed vehicle's tasks to another vehicle, or a failed machine's unfinished operations to other feasible machines. \(\pi\) is never changed and the search is not restarted;
the global-rescheduling baseline may change \(x\) and \(\pi\) (Section~\ref{sec:vs_r0}).
\end{enumerate}

\subsection{A dichotomy of disturbances}
\label{sec:disturbance_classes}

\begin{definition}[Class A/B disturbances]
\label{def:ab}
A disturbance is of \textbf{Class A} if it directly invalidates the assignment or \emph{executability} of some operations (robotic-arm failure, processing-time deviation, rush-order insertion, vehicle failure).
It is of \textbf{Class B} if it only makes some corridors unavailable for some period without making any operation inexecutable (corridor blockage, corridor slowdown).
\end{definition}

\begin{remark}[Why vehicle failure is Class A]
\label{rem:agv_class}
A vehicle failure changes no machine assignment, but the operations the vehicle transports cannot start as planned. Through the mapping ``vehicle\(\to\)operations it transports'',
\(G_T\) still contains seed operations. This holds only if the method records which operations each vehicle transports; otherwise vehicle failure also yields an empty scope. The baseline in Section~\ref{sec:e6} records this correspondence.
\end{remark}

\begin{definition}[Scopes on the operation-precedence graph and seed occupancies]
\label{def:task_impact}
\label{def:seeds}
\(T_{\mathrm{direct}}(\mathcal{D})\) is the set of operations that cannot be executed as planned; for Class B, \(T_{\mathrm{direct}}=\varnothing\) by convention.
\(T_{\mathrm{impact}}(\mathcal{D},\theta)\) collects the operations reached from \(T_{\mathrm{direct}}\) on \(G_T\) within at most \(\theta\) steps along job and same-machine successor edges (including \(T_{\mathrm{direct}}\)).
The seed set \(\mathrm{Src}(\mathcal{D})\subseteq R\) contains only occupancies not yet finished at \(t_{\mathrm{now}}\) (\(r.t^e>t_{\mathrm{now}}\)) and is given by disturbance type:
(a)~\textbf{corridor blockage/slowdown} \(\mathcal{D}=(e,[t_a,t_b))\): \(\{\,r:\ r.e=e,\ [r.t^s,r.t^e)\cap[t_a,t_b)\neq\varnothing\,\}\) (for multiple windows, the union);
blockage and slowdown share this rule and differ only in rerouting: a blocked corridor is impassable, while a slowed one stays passable with the traversal time inside the interval lengthened;
(b)~\textbf{vehicle failure} \(\mathcal{D}=(k)\): \(\{\,r:\ r.k=k\,\}\);
(c)~\textbf{robotic-arm failure} \(\mathcal{D}=(m,F)\): for each job, all unfinished occupancies from its smallest operation index in \(F\) onward, because the inbound transport may have finished, and taking only the operation itself would make the impact set cover fewer operations than the affected set on \(G_T\).
\end{definition}

\begin{prop}[The operation-precedence graph yields an empty scope for Class B]
\label{prop:miss}
Let \(\mathcal{D}\) be a corridor blockage. Then \(T_{\mathrm{impact}}(\mathcal{D},\theta)=\varnothing\) for every finite \(\theta\ge 0\).
If, in addition, \(\mathrm{Src}(\mathcal{D})\neq\varnothing\), then \(\mathcal{S}^0\) is infeasible under \(\mathcal{D}\).
\end{prop}

\begin{proof}
Since the blockage window is finite and buffers are ample (A4), vehicles can wait at nodes until the blockage ends, so no operation becomes inexecutable and \(\mathcal{D}\) is of Class B;
hence \(T_{\mathrm{direct}}=\varnothing\) and the \(\theta\)-step expansion is empty. If \(r\in\mathrm{Src}(\mathcal{D})\) exists, \(r\) overlaps the blockage window on the same exclusive corridor,
which violates conflict freedom (A4); hence \(\mathcal{S}^0\) is infeasible.
\end{proof}

The first part follows from the convention; the nontrivial part is the second. Hence ``an empty scope on \(G_T\) \(\Rightarrow\) no rescheduling needed'' fails when corridors are reserved by time windows,
independently of any repair algorithm; Section~\ref{sec:e1} verifies this on \(\PassMiss\) pairs.

\subsection{The recovery problem}
\label{sec:recovery_problem}

\begin{problem}[Bounded rescheduling with the scope delineated on the reservation table]
\label{prob:recovery}
Given \(\mathcal{S}^0\), \(\mathcal{D}\), and \(t_{\mathrm{now}}\), find \(\mathcal{S}'\) such that
(i)~\(\mathcal{S}'\) is conflict-free under \(\mathcal{D}\); (ii)~occupancies outside the rewrite scope keep their corridors, intervals, and vehicles as in \(\mathcal{S}^0\) as far as possible;
(iii)~the runtime is subject to a budget. The secondary objective is the makespan \(C_{\max}(\mathcal{S}')\).
\end{problem}

Bounded rescheduling first delineates the rewritable set \(U\subseteq R\) and then reroutes only the transports in \(U\); we call the second step \emph{bounded repair} (Section~\ref{sec:repair}). We take \(U=\mathrm{Cl}(\mathrm{Src})\);
the baseline instead takes the transport occupancies of the operations in \(T_{\mathrm{impact}}\) that are unfinished at \(t_{\mathrm{now}}\), which is empty under Class B by Proposition~\ref{prop:miss}.
The two are denoted R2 and R1 in the experiments.

\section{The spatiotemporal reservation closure}
\label{sec:strc}
%% =====================================================================

This section determines \(U\): we build a dependency graph over occupancies and take all occupancies reachable from the seeds \(\mathrm{Src}(\mathcal{D})\) along its edges.

\subsection{Reservation dependency edges}
\label{sec:closure_def}

\begin{definition}[Reservation dependency graph]
\label{def:dep}
The vertices are the occupancies in \(R\); an edge \(r\to r'\) means that once \(r\) is rewritten, \(r'\) may have to be rewritten as well. There are four kinds of edges:
(1)~\textbf{yield edges} between occupancies of the same corridor by different vehicles whose intervals overlap \emph{or abut} (\(r.t^e=r'.t^s\)), from the earlier entry time \(t^s\) to the later one---meeting end to start is legal, but if the former is delayed the latter must give way;
(2)~\textbf{same-vehicle successors}, adjacent in time, from the earlier to the later;
(3)~\textbf{same-job successors}, from the transport occupancies of operation \(i\) to those of operation \(i+1\);
(4)~\textbf{same-machine successors}, from the transport occupancies of an operation to those of the operation processed next on the same machine.
This yields \(G_R=(R,E_R)\). The edge set is a modeling choice that may over-include or miss dependencies (Remark~\ref{rem:minimality}).
\end{definition}

\begin{definition}[Reservation impact set and \STRC{}]
\label{def:strc}
Given seeds \(S\subseteq R\) and \(t_{\mathrm{now}}\), let \(R^{\circ}=\{\,r\in R:\ r.t^e>t_{\mathrm{now}}\,\}\) be the unfinished occupancies and \(G_R^\circ\) the subgraph that keeps only them and the edges among them.
The reservation impact set is
\[
\mathrm{Cl}(S)=\bigl\{\,v\in R^{\circ}:\ \exists\,s\in S\cap R^{\circ}\ \text{such that}\ s\!\to^*\!v\ \text{in}\ G_R^\circ\,\bigr\},
\]
i.e., all unfinished occupancies reachable from the unfinished seeds, seeds included; computing it is called the spatiotemporal reservation closure (\STRC).
With adjacency lists, one breadth-first search computes \(\mathrm{Cl}(S)\) in \(O(|R^{\circ}|+|E_R^{\circ}|)\) time.
\end{definition}

\subsection{Closure}
\label{sec:containment}

\begin{prop}[Structural closure]
\label{prop:struct}
For any \(S\subseteq R\), \(G_R^\circ\) contains no edge \(u\to v\) with \(u\in\mathrm{Cl}(S)\) and \(v\in R^{\circ}\setminus\mathrm{Cl}(S)\).
\end{prop}

\begin{proof}
If such an edge existed, then \(s\to^* u\to v\) for some unfinished seed \(s\), so \(v\in\mathrm{Cl}(S)\), a contradiction.
\end{proof}

Closure is thus a corollary of the definition once the edge set is fixed; its physical completeness depends on the choice of edges.

\begin{remark}[The reservation impact set and the minimal rewritable set]
\label{rem:minimality}
Closure neither guarantees that the impact set suffices to restore feasibility nor that it is small; we relate it to the minimal rewritable set in three points.
First, a \emph{minimal} rewritable set is defined only relative to a repair capability (rerouting only, or also reassignment), whereas \(\mathrm{Cl}\) is determined by \(G_R\) alone and is not meant to coincide with any of them.
Second, the edges over-include: a yield edge is created for any overlap without checking whether the later vehicle could detour, and same-vehicle edges may pull in chain tails the delay never reaches.
In the opposite direction, the known omission---abutting intervals---has been folded into the yield edges; a difference probe (on the \(\NPairs\) pairs of E3, each impact-set occupancy is delayed alone by one time unit, and a leak is counted whenever it newly overlaps an occupancy outside the set on the same corridor) finds \ProbeLeaks\ leaks (\ProbeLeakPairs\ pairs; in \ProbeOutsidePairs\ of them the set leaves occupancies outside), which tests this omission but does not prove completeness.
Third, empirically the impact set covers about \ClosureAliveFrac\ of the unfinished occupancies (Section~\ref{sec:e6}), less than one tenth below rewriting all of them.
Bounded repair is fast mainly because it does not restart the search, not because far fewer occupancies are to be rewritten; ``bounded'' does not mean ``small''.
This small difference still lowers the rewrite fraction by \RAStabMean\ on average (Section~\ref{sec:cheap}).
The impact-set share does not rise with instance size (Section~\ref{sec:instscale}), and static network indicators fail to predict it (Section~\ref{sec:e4}).
\end{remark}

\subsection{Single-pass rerouting}
\label{sec:level1}

Given \(U\), single-pass rerouting keeps the vehicle and machine assignments and reschedules the transports in \(U\) one by one in the original processing order (Algorithm~\ref{alg:replay}).
It works per occupancy: the part of a trip traversed before \(t_{\mathrm{now}}\) is finished and pre-committed unchanged, and planning starts from the vehicle's node at that time.
By complexity, delineation needs one breadth-first search, whereas the replay calls the time-window router once per leg in \(U\), which dominates the runtime. No population-based search is launched.
Section~\ref{sec:e3} fixes this procedure and replaces only the source of \(U\), so that differences in feasibility can be attributed to the scope object.

\begin{algorithm}[t]
\caption{Single-pass rerouting \(\textsc{ReplayReroute}\)}
\label{alg:replay}
\begin{algorithmic}[1]
\Require schedule \(\mathcal{S}^0=(x,\pi,y,R)\), disturbance \(\mathcal{D}\), rewritable set \(U\), time \(t_{\mathrm{now}}\)
\Ensure schedule \(\mathcal{S}'\) or failure
\State write \(\mathcal{D}\) into the routing layer \Comment{blockage: blockage window; slowdown: traversal time inside the window lengthened}
\State \(R'\gets\varnothing\)
\For{each occupancy not in \(U\) (including all finished occupancies)}
  \State pre-commit its original fields \((e,[t^s,t^e),k)\) to \(R'\); \textbf{if} it conflicts with a blockage window \textbf{then return} failure
\EndFor
\For{each \(r\in U\), in the original processing order}
  \State route from the vehicle's node at \(t_{\mathrm{now}}\) on the current \(R'\) and commit the new occupancies
  \State update the machine idle time and job ready time concerned according to \(\pi\)
\EndFor
\State \textbf{if} independent check passes (no conflicts, fields outside \(U\) unchanged) \textbf{then return} \(\mathcal{S}'=(x,\pi,y,R')\) \textbf{else return} failure
\end{algorithmic}
\end{algorithm}

\begin{prop}[A sufficient condition for unchanged fields outside the set]
\label{prop:outside}
Let \(U=\mathrm{Cl}(S)\), and let single-pass rerouting (Algorithm~\ref{alg:replay}) satisfy:
(i)~the blockage windows are written into the routing layer; (ii)~for every \(r\in R^{\circ}\setminus U\), its fields \((e,[t^s,t^e),k)\) are pre-committed to the new table and the pre-commit succeeds;
(iii)~the time-window router replans only the occupancies in \(U\); (iv)~the final schedule passes the conflict-free check.
Then the corridor, interval, and vehicle of every \(r\in R^{\circ}\setminus U\) in the recovered table agree with \(\mathcal{S}^0\).
The proposition holds per occupancy, not per whole transport.
\end{prop}

\begin{proof}
By (ii), occupancies outside the set enter the new table with their original fields before the replay; by (iii), the replay neither deletes nor rewrites them; the check in (iv) only rules out conflicts and alters no committed field.
\end{proof}

Premises (i)--(iv) are execution conditions that can be checked against Algorithm~\ref{alg:replay}; beyond them, the proposition relies on A1, A2, and A4.
A failed pre-commit indicates an incomplete seed set. If scope escalation enlarges \(U\), the proposition holds only for the occupancies finally left outside.
Premise (iii) fails if rerouting is decided at a unit coarser than an occupancy, so the implementation must decide it per occupancy, and for a leg spanning \(t_{\mathrm{now}}\) must keep the segments already traversed (otherwise finished occupancies are rewritten, which a check of the fields outside \(U\) cannot detect).

\subsection{Scope escalation after failure}
\label{sec:scope_escalation}

Escalating the scope has precedents: Local Rescheduling~\cite{kuster2007local} relaxes the time window step by step, and AOR adds successor operations (Section~\ref{sec:rw_aor}); we escalate along reservation dependencies, called \emph{scope escalation}. E3 disables this step (Section~\ref{sec:e1}).
If, with all occupancies outside \(U\) fixed, those in \(U\) find no feasible path and interval (e.g., a transport cannot arrive when its operation requires), the replay fails; we then enlarge \(U\) and retry:
(i)~add the unfinished occupancies in the same-job suffixes of operations in \(U\); (ii)~add those in the same-vehicle suffixes of the vehicles involved; (iii)~set \(U\leftarrow R^{\circ}\), the rewritable set of RA.
Each round remains a deterministic single pass (Algorithm~\ref{alg:strc_repair}).

\begin{algorithm}[t]
\caption{Bounded repair on the reservation impact set (single-pass rerouting + scope escalation)}
\label{alg:strc_repair}
\begin{algorithmic}[1]
\Require schedule \(\mathcal{S}^0\), disturbance \(\mathcal{D}\), time \(t_{\mathrm{now}}\)
\Ensure schedule \(\mathcal{S}'\) or failure
\State \(U \gets \mathrm{Cl}(\mathrm{Src}(\mathcal{D}))\)
\For{round \(=0,1,2,3\)}
  \State \(\mathcal{S}' \gets \textsc{ReplayReroute}(\mathcal{S}^0,\mathcal{D},U,t_{\mathrm{now}})\); \textbf{if} \(\mathcal{S}'\) is feasible \textbf{then return} \(\mathcal{S}'\)
  \State update \(U\) by the scope-escalation rule \Comment{job suffix / same vehicle / all unfinished}
\EndFor
\State \Return failure
\end{algorithmic}
\end{algorithm}

\subsection{Baselines}
\label{sec:vs_r0}

The global rescheduling baseline R0+ is a genetic algorithm that encodes \((x,\pi)\) as a chromosome, is warm-started with \(\mathcal{S}^0\) as one individual of the initial population, and searches under the same blockage windows within a wall-clock budget.
One \emph{decoding} routes all transports from scratch on the table with the blockage windows written in; finished occupancies are pre-committed, and only operations not yet started are scheduled from \(t_{\mathrm{now}}\).
Because R0+ can reassign and resequence, it is more likely to shorten \(C_{\max}\), but its runtime is set by the budget.
Bounded repair is therefore not expected to win on makespan; its strength is runtime. To test whether scoping on the impact set matters \emph{within} a millisecond runtime,
Section~\ref{sec:cheap} adds three millisecond baselines (RS, RD, RA), of which RA differs from our method only in which occupancies are rewritable.

\subsection{Experimental setup}
\label{sec:protocol}

\textbf{Instances.}
The main batch has five instances (jobs \(\times\) machines \(\times\) AGVs): a small hand-crafted \(3\times3\times2\) instance, a congested hand-crafted \(8\times4\times4\) instance, and three generated \(8\times4\times4\) spine layouts, funnel, high, and mid.
In a spine layout, a main corridor runs through the machine area, machines hang on two hubs via branches, and the load/unload station sits at one end with one or two parallel exits~\cite{suh2022spine}, so all transports share the same exit and middle section; the congested instance also has this layout.
The three spine layouts differ only in the number of parallel lanes (funnel: one exit and one middle lane; high: two exits; mid: two exits and two middle lanes), i.e., in capacity, not in distance.
We use ten run seeds fixed before the experiments (\(42,7,2024,99,123,13,1,777,31415,8\); E5 uses the first three), giving \(\NInst\times\NSeeds=\NPairs\) instance--seed pairs.
All per-pair comparisons and paired tests use the instance--seed pair as the unit: in the same pair, all methods read the same initial schedule, blockage, and decision time.
The initial schedule is obtained by replaying the time-window router in processing order and passes the independent check.

\textbf{Second batch with published layouts.}
To test whether the conclusions depend on the layouts we constructed, a second batch of \NPubInst\ instances (\NPubPairs\ pairs) transcribes the grid size, the nodes of the station and machines, and the adjacent node pairs without a corridor from Appendix~A of Lyu et al.~\cite{lyu2019approach},
checked by script against the encoding shipped with the van Os toolkit. All other parameters are matched to the main batch, so the two batches differ only in the layouts.
Its six layouts (layouts 1--6, with \(3\) to \(8\) machines) are used except layout 1, which cannot give every operation two candidate machines at \(f=0.6\). The five remaining layouts lie on only \NPubNets\ distinct networks
(layouts 2--3: a \(4\times4\) grid of \(16\) nodes with \(23\) of its \(24\) corridors present; layouts 4--6: a \(5\times5\) grid with \(38\) of \(40\)), so along network shape there are \NPubNets\ independent samples.
Lyu et al.\ give per-edge durations only for one example, so we use equal weights; following the single load/unload station common in joint machine--AGV scheduling~\cite{fontes2023hybrid}, the loading and unloading stations are merged into one, which leaves the network unchanged; and their job data are not used,
because in public instance families transport takes only a few percent of processing time and corridor contention would be unobservable.
We therefore borrow only their networks and do not compare with the values they report.

\textbf{Disturbances.}
All experiments use \(t_{\mathrm{now}}=0.35\,C_{\max}(\mathcal{S}^0)\), fixed in advance: about \(40\%\) of the occupancies have then finished and \(60\%\) remain (no sensitivity analysis on this value). E1--E3, E5, and E7 block the corridor with the most unfinished occupancies at \(t_{\mathrm{now}}\), in one continuous window covering all of them (a \emph{busy-corridor blockage}); E6 adds three further types; E4 blocks a corridor in the load/unload minimum cut.
The magnitude sweep sorts operations with unfinished occupancies by their earliest such occupancy, takes the first fraction \(\varphi\), and blocks each of their unfinished occupancies on its own corridor and interval, without merging blockages, so that no unselected occupancy is covered.

\textbf{Metrics.}
An occupancy counts as \emph{rewritten} if its corridor, interval, or vehicle after repair differs from \(\mathcal{S}^0\); the \emph{rewrite fraction} is the share of rewritten occupancies in the whole table \(R\).
It differs from the \emph{rewritable share} \(|U|/|R^{\circ}|\), which counts the occupancies a method is allowed to change.
Makespan \emph{degradation} is \((C_{\max}(\mathcal{S}')-C_{\max}(\mathcal{S}^0))/C_{\max}(\mathcal{S}^0)\).
A \emph{finished-occupancy violation} is a rewritten occupancy with \(t^e\le t_{\mathrm{now}}\), which A2 forbids.

\textbf{Methods and conventions.}
Table~\ref{tab:baselines} lists the methods in increasing order of their difference from R2. In R1, \(\theta\) is the maximum number of forward hops along the job precedence; it matters only for Class A, since a Class B disturbance hits no operation and the scope is empty for any \(\theta\) (Proposition~\ref{prop:miss}). R1 transplants AOR scoping~\cite{subramaniam2003maor} into our reservation setting: the \(\theta\)-hop truncation and the mapping from operations to reservations are ours,
since the original setting has no reservation table; its results reflect the rule in this setting, not the original method in its own.
R1/R2 differ only in the scope \emph{object}, RA/R2 only in \emph{whether} the scope is restricted; RD decodes the original chromosome once, whereas R0+ searches repeatedly within its budget.
Only R0+ terminates on a budget; all others are deterministic single passes and can be compared with one another directly.
Scope escalation is disabled in E1--E3, E5, and E7, so that a fallback to all unfinished occupancies cannot mask the difference between scope objects; its end point is RA, measured separately.
It is enabled only in the magnitude sweep and in E8.
The main batch establishes the phenomena under full control of the instance parameters; the second batch only tests whether they depend on our layouts, and is pooled with the main batch only in E5.

\textbf{Implementation and statistics.}
All code is pure Python (standard library only), run single-threaded on an Intel Xeon W-1270 with 64\,GB RAM under Windows~10; runtime conclusions are stated as ratios or orders of magnitude.
The paper contains two inferential tests, both in Section~\ref{sec:cheap}: R2 versus RA on rewrite fraction (primary) and R2 versus RD on makespan, each a two-sided Wilcoxon signed-rank test paired by instance--seed pair;
Holm correction does not change either conclusion. The primary test is accompanied by a Hodges--Lehmann estimate with a bootstrap \(95\%\) CI (\(10^4\) resamples).
All other counts, means, and medians are descriptive.

\subsection{E6: disturbance types crossed with scope objects}
\label{sec:e6}

On the same \(\NPairs\) pairs we test whether the conclusions of E1--E3 hold under corridor slowdown (traversal time doubled during the slowdown window), vehicle failure, and robotic-arm failure; the results are shown in Table~\ref{tab:e6}.
\textbf{First}, the A/B dichotomy holds without exception: scoping on \(G_T\) is empty for both Class B types and nonempty for both Class A types in every pair.
Blockage and slowdown share the seed rule and hence give identical impact sets, so there are \(150\) independent scoping measurements, not \(200\).
\textbf{Second}, over all \(100\) Class A measurements \(U_{R1}\subseteq\mathrm{Cl}\), strictly in \(\StrictlyLarger\) pairs: switching to the reservation impact set never misses an occupancy already included by \(G_T\).
For robotic-arm failure this holds by construction (the seed rule takes the whole job suffix, while R1 truncates at \(\theta=2\)); for vehicle failure it is an empirical result.
The price is more rewritable occupancies on average: from \(31.1\) (scoping on \(G_T\)) to \(60.6\) (impact set) under vehicle failure, and from \(42.8\) to \(65.9\) under robotic-arm failure.
\textbf{Third}, all four types are repaired in every pair without escalation, Class A by vehicle swapping or machine reassignment.
\textbf{Fourth}, under blockage the impact set contains about \ClosureAliveFrac\ of the unfinished occupancies, leaving out fewer than \(10\%\); the \(\mathrm{Cl}/|R|\) of \EoneCloLo--\EoneCloHi\ in Table~\ref{tab:e1} has all occupancies as denominator, about two fifths of which are finished before \(t_{\mathrm{now}}\).
These results extend the conclusions on C1 and C2 from corridor blockage to four disturbance types.

\subsection{E7: comparisons within the millisecond range}
\label{sec:cheap}

E5 leaves open how much of the speed advantage is due to the impact set and how much merely to a slow baseline. We therefore compare R2 with three millisecond baselines (Table~\ref{tab:baselines}).
\textbf{RS} postpones all unfinished occupancies by the smallest delay that clears the blocked corridor; because the shift is uniform, all ``\(\ge\)'' constraints remain satisfied without rerouting.
\textbf{RD} keeps the chromosome and runs one fixed-prefix decoding, the fastest global recomputation in our implementation.
\textbf{RA} makes all unfinished occupancies rewritable and runs the \emph{identical} replay as R2; it is the only baseline that isolates the effect of the impact set.

RS needs \MsShift\,ms, about half of R2, and is the only feasible method faster than R2 (R1 is faster still, but feasible in only \FeasRone\ pairs);

Making the shift selective would first require determining which occupancies are affected---precisely the scope delineated here. \textbf{The right shift is fast because it gives up selectivity.}

RD takes \MsRedecode\,ms, \RedecodeRatio\ times R2, and any decoding-based search needs at least one decoding per candidate.
On makespan, R2 and RD are indistinguishable (\WinVsRedecode; mean paired difference \(+0.006\), CI \([-0.007,\,0.019]\); Wilcoxon \(p=0.12\)), while RD rewrites more (\ResFracRedecode).
\textbf{Even the fastest global recomputation is slower, so the speed gap in E5 is not an artifact of a slow baseline.}

On average the impact set excludes only \(1-\ClosureShareMean\) of the unfinished occupancies (\ClosureShareLo--\(1.00\) per pair; in \(6\) pairs the two sets coincide).
This small difference lowers the rewrite fraction from \ResFracAllFuture\ to \ResFracCheapRtwo\ (mean reduction \RAStabMean, median \RAStabMed, per pair \RAStabWTL\ for R2 fewer/equal/more rewrites, \(p=\RAStabP\); Hodges--Lehmann estimate \(0.037\), CI \([0.018,\,0.074]\); CI of the mean \([0.039,\,0.093]\);

\textbf{Whether scoping reduces rewriting can be answered only by R2 versus RA: R2 rewrites less.}
The reduction grows as the impact set excludes more: \(0.010\) on the congested instance (rewritable share \(0.94\)) versus \(0.118\) on the mid layout (\(0.91\)).

above \(\WorthVanish\) the reduction is zero (necessarily so in the \(6\) pairs with share \(1.00\), where R2 and RA coincide; empirically in the rest). The threshold is in-sample and not meant for extrapolation.
Taken together, equal runtime shows that the millisecond response comes from single-pass rerouting, not from the impact set; equal makespan shows that the impact set is not an optimization device;
and R2 rewrites less because occupancies outside the impact set keep the original plan by Proposition~\ref{prop:outside}.
\textbf{The benefit of the impact set lies in rewrite volume, not in speed or makespan}: at equal runtime and makespan, the share of rewritten occupancies is \ResFracAllFuture\ for RA and \ResFracCheapRtwo\ for R2, about \(6\) percentage points apart; RA rewrites about \(12\%\) more occupancies.

\section{Conclusion}
\label{sec:conclusion}
%% =====================================================================

When a flexible job shop records corridor occupancies with time windows, the operation-precedence graph contains no yielding relations between occupancies and cannot capture disturbances that invalidate only occupancies:
under corridor blockage, operation-level scoping is empty although the original schedule is infeasible (all \(\NPairs\) pairs, C1).
Delineating the scope on the reservation dependency graph makes the occupancies to be rewritten uniquely determined by the given relations rather than by a heuristic radius (closure and outside invariance in all \(\NPairs\) pairs, C2),
and with the same rerouting and only the scope object changed, feasibility goes from \(\FeasRone\) to \(\FeasRtwo\) (C3).
Rewriting all unfinished occupancies instead leaves runtime and makespan almost unchanged but raises the rewrite fraction from \ResFracCheapRtwo\ to \ResFracAllFuture; this difference shrinks as the impact set approaches the set of all unfinished occupancies.
Hence the millisecond response comes from single-pass rerouting, and \textbf{scoping on the impact set serves to reduce rewriting: occupancies outside it are kept as planned} (Proposition~\ref{prop:outside}).
Yielding relations, rerouting inside the set, and scope escalation are taken from existing practice.

\subsection{Limitations and future work}
\label{sec:limitations}
\label{sec:future}

We list four limitations in order of their impact, each followed by the corresponding direction.

\begin{enumerate}[leftmargin=1.6em,itemsep=0.3em]
\item \textbf{Makespan.} Warm-started global rescheduling is no worse than bounded repair on \(C_{\max}\) at every tested budget, with no crossover (Section~\ref{sec:e5}).
Since neither method rewrites finished occupancies, narrowing the gap would require limited reassignment or resequencing, which drifts toward global rescheduling; this limitation concerns the benefit of scoping, not the conclusions on the scope object (C1, C2).

\item \textbf{Guarantee and size of the impact set.} Proposition~\ref{prop:outside} is only a sufficient condition, and the edge set has not been verified exhaustively. The impact set is not the minimal set needed to restore feasibility: it covers about \ClosureAliveFrac\ of the unfinished occupancies, so the reduction in rewriting is limited.
The probe finds \ProbeLeaks\ leaks for the known abutting omission; other disturbance forms (shortened occupancies, longer delays) should be probed next.
A minimal rewritable set defined for a fixed repair capability would quantify the gap.
Static network indicators cannot predict the impact-set size (Section~\ref{sec:e4}); the next candidates are schedule-dependent, e.g., the number of overlapping occupancies on the disturbed corridor near \(t_{\mathrm{now}}\). This limitation does not affect the conclusion of C1.

\item \textbf{Scope of the implementation.} Class B is handled by rerouting only, Class A adds vehicle swapping and reassignment without resequencing, and only a single disturbance is handled (A3).
Size has been extended to \(\ScaleJobsHi\) jobs and \(\ScaleMachHi\) machines, but E8 has only seven levels, too few to infer the trend at larger sizes.
The next step is to relax A3 and examine whether the impact set grows cumulatively under continual disturbances.

\item \textbf{External reference points.} No public benchmark can be substituted in: the public instance families~\cite{homayouni2021production,fontes2023hybrid} publish machine-to-machine travel-time matrices; none of their \(11\) layouts can be reconstructed as a corridor graph consistent with the matrix,
so \(R\), \(G_R\), \(\mathrm{Cl}(\cdot)\), and Class B disturbances cannot be defined on them. Our second batch takes only the layouts from Lyu et al.~\cite{lyu2019approach}; travel times and job data are still set by us, so the reference values of Lyu et al.\ or van Os~\cite{vanos2026exact} cannot be reproduced.
An instance family publishing both a network and per-leg travel times is still needed; our edge-weight sweep in E3 tests only robustness and cannot replace it.
Hence only the networks come from the literature and external validity is limited; relative comparisons within the same implementation are unaffected.
\end{enumerate}
