# 小论文写作参考：工业生产调度层注入攻击检测

## 一页速览

- **题目**：基于时序半马尔可夫与参考模型可行性约束的工业生产调度层注入攻击检测
- **题目-英**：Timed Semi-Markov Consistency and Reference-Model Constraints for Detecting Scheduling-Layer Injection Attacks in Cyber-Physical Production Systems
- **核心洞见**：攻击者控制"消息何时发出"与"消息内容"，但**不控制物理过程何时推进**；而"哪台设备允许做哪个操作、从哪个前驱可达"是工艺参考模型规定的、**不可能从日志里学出来**的先验。因此物理节拍与参考模型的可行性约束共同构成一张零密码学开销的"隐式凭证"。
- **一句话方法**：把状态标签链升级为"标签 + 停留时长 + 命令上下文"的半马尔可夫过程，判据由几何距离改为负对数似然；参考模型导出的可行性掩码作**硬层一票否决**（覆盖 100%、良性违反 0），时序与结构两个统计通道各自经 conformal 校准（时序喂标准化残差、结构喂预测概率，都不能喂 p 值），三路**并行**各分 $\alpha/3$、任一触发即报，经序贯累积后判决，误报预算由用户直接指定为 $\alpha$。跨设备互锁通道与 Fisher 合成路**已被剔除**：前者由只用良性数据的天花板判据剔除，后者由威胁模型声明剔除。
- **三层创新**：问题层＝生产调度层这个攻击面；机制层＝时间维不可伪造 + 可行性约束不可学习；理论层＝一个不可能性结果 + 一个攻击者影响上界。
- **实验骨架**：主验证是 **Fischertechnik Trier IoT 事件日志（gold standard）+ 自建注入层**——真实多工位、真实命令日志、随数据集发布的 16 个 BPMN 可自动导出 $\mathbf F$ 与 $\mathcal I$；自建离散事件仿真降级为"可控扫描"用途（A/B 两配置），HAI 作跨域外部效度。主基线是学习型计时自动机（Maier/BUTLA）、TABOR 式与 HSMM 似然，不是原来的流量类稻草人；主指标是同 $\alpha$ 下的 DR/FPR、**以消息数计的检测延迟**、ARL$_0$、以及理论界的实证吻合度。完整场景分工见"修订后的场景表"。
- **定位**：IEEE IoT-J / TII / Computers & Security / JISA，或《自动化学报》《通信学报》。

## 场景与系统模型

**系统构成。** 一个中央**调度系统** $\mathcal{C}$ 与一组异构**现场设备** $\mathcal{D}=\{d_1,\dots,d_M\}$（AGV 与机械臂）通过工业网络互联，构成一个生产系统。研究对象是这个整体，**不涉及设备间的自治协商**——设备不自主决策，只执行命令并上报状态，所有耦合都经由调度系统。这一点决定了攻击面的位置：攻击者要破坏生产，最经济的方式是**污染调度系统的状态视图**，使其做出错误派工。

**双向消息回环。** 下行是命令 $u_t$（派工、参数、目标位置）；上行是状态上报 $s_t$（设备当前状态标签）。关键结构：**上报本应是命令的响应**，因此调度系统天然持有一份"我下发了什么"的账本，这份账本是检测器可以免费使用而攻击者难以对齐的信息。

**两种上报语义**（必须在方法里分开处理）：
- 事件驱动：状态发生跳变时上报一条（自建仿真属于此类）
- 周期轮询：固定周期采样上报，同一状态会被重复上报（HAI 属于此类，1 Hz）

**状态空间**（以自建仿真场景 A/B 的实施例为准，共 7 个状态）：
- AGV（5 态）：`AGV_idle`、`AGV_MovingToRobotArm`、`AGV_AtRobotArm`、`AGV_MovingToOrigin`、`AGV_AtOrigin`
- 机械臂（2 态）：`RobotArm_idle`、`RobotArm_Producing`

**必须废弃的是"联合状态链"**：原方法把两类设备的事件流交织成 7 维联合链，会产生"AGV 在移动 → 机械臂空闲"这类语义串味的转移项，且停留时长在联合语义下无物理意义。这一条无条件成立。

**但"拆成什么链"取决于设备语义，不是固定答案**（此条按 Trier 实测修订）。判据是**设备是否具有跨作业持续的内部状态机**：

| 设备语义 | 结构链粒度 | 依据 |
|---|---|---|
| **有状态设备**：设备自身有跨作业演化的内部状态（AGV 的空闲/移动/装载/返程），单作业内被多次观测 | **(设备, case) 链** | 停留时长与转移概率都在单设备语义下有意义；场景 A/B 属此类 |
| **无状态服务端点**：设备是被调用的服务，每个作业只被调用一到两次，无跨调用内部状态 | **case 级工作流链** | Trier 属此类——设备级链 65.1% 长度为 1，结构 p 值取值唯一，信息量为零（结论十二） |

判别可自动化：在正常日志上统计每条 (设备, case) 链的**平均长度与结构 p 值的取值基数**，若平均长度 $<2$ 或取值基数为 1，则该设备的结构通道退化，应上移到 case 级。**注意这只影响结构通道 M3 的粒度**——时序通道 M4 无论哪种语义都在 (设备, 操作) 分组上建模，互锁通道 M5 无论哪种语义都是跨设备的，两者不受影响。**在线检测器一律按 (设备, case) 维护链上下文**（$\mathbf F$ 来自工作流内可达性，跨 case 边界不适用；日志的 `case` 字段与命令 URL 的 `business_key` 使之工程可行），只是结构通道消费哪一层的序列可配置。

## 系统被利用的结构性特点

这一节是全文立论的根基，Introduction 必须先把这七条讲清楚，方法的每个模块都对应其中一条。

1. **状态有限且离散。** 设备运行状态由工艺流程定义，可由领域知识穷举（AGV 5 态、机械臂 2 态），无需从连续信号中学习状态抽象。
2. **状态可直接观测。** 状态标签直接来自上报消息，不是隐变量——这是不用 HMM/Viterbi 的理由（省去 $O(n^2T)$ 的隐状态推断）。
3. **转移规律含三类硬约束。** 这是"物理可行性掩码"的来源：
   - *禁止转移*：同一台 AGV 不可能从 `AGV_MovingToRobotArm` 直接跳到 `AGV_idle`（未到达就凭空空闲），也不可能从 `AGV_idle` 直接跳到 `AGV_AtRobotArm`（凭空传送）
   - *必然转移*：`AGV_AtRobotArm` 完成投料后必然进入 `AGV_MovingToOrigin`
   - *概率转移*：其余合法转移按历史频次估计
4. **转移耗时受物理规律限定。** 每条合法转移的停留时长有确定的物理量纲与可学习的分布：行驶时间由距离/速度决定，加工时长由工艺决定（实施例为 3–15 s）。**这是既有工作丢掉、而本文使用的核心信息**——标签序列合法但耗时错位的消息，纯标签模型概率约为 1，原理上不可检测。
5. **跨设备存在硬耦合（互锁）。** 机械臂进入 `Producing` 必须有某台 AGV 已完成投料；两台 AGV 不能占据同一栅格；在执行任务数必须等于调度队列计数；物料守恒。这些是**单过程 ICS 系统里不存在的结构**，是 S1 的立足点。
6. **命令–状态存在因果配对。** 调度系统没派任务却收到 `MovingToRobotArm`，是"无因之果"，一步即毙。
7. **数据与算力约束。** 正常运行日志易得、攻击样本稀缺且标注昂贵 → 必须无监督；边缘控制器无 GPU、毫秒级时延预算 → 必须轻量（$O(1)$/消息）。

## 威胁模型

**攻击者能力**（Dolev-Yao，作用于状态上行链路）：窃听全部通信；重放捕获的历史消息；注入伪造消息；丢弃或延迟消息；已知系统状态机结构，甚至已知转移矩阵 $\hat P$。

**攻击者不能**：攻破调度系统本体；攻破设备固件；改变物理世界（不能让 AGV 真的瞬移）；不能读取调度系统的内部命令账本（若能，则退化为内部人威胁，超出范围）。

**攻击目标**：使调度系统的状态视图与物理现实脱节，从而提前/错误派工，违反工艺互锁，导致碰撞、死锁、设备损伤或产线停摆。典型手法是在 AGV 尚在途中时重放 `AGV_AtRobotArm`，骗调度系统提前下发下一任务。

**根本非对称性（全文反复引用）**：攻击者控制消息的**内容**与**发送时刻**，但不控制物理过程的**推进速度**，也不掌握调度系统的**命令账本**与**其他设备的真实状态**。前者产生时序残差，后者产生互锁矛盾。

● 提升 ≥0.25；○ 提升 ≥0.05；✗ 无实质提升。A7 **不实现即不报告**——它需要攻击者同时伪造多设备并与命令账本对齐，是本方法声明的能力边界，实现一个弱版本再声称"我们也能抓"是不诚实的。

序贯@10 一列的误报在 0.05–0.12，**高于逐通道列，且不是真实的良性误报率**：攻击流里 CUSUM 被攻击消息抬高后会在随后的良性消息上触发，这是序贯检测固有的记账问题，论文里必须与纯良性流的 ARL$_0$ 分开报告。A2 硬层那一格的 0.06 误报同理——A2 是**原地改写**操作名，于是同一 (case, 设备) 的后继良性消息会被拿去和一个伪造的前驱比对，二元 F 因此落空。这在部署中是"察觉到了攻击、只是归因到了错的那条消息"，不是虚警；论文报告时要与纯良性流的误报分开算。

**被实测推翻的 12 格，按重要性：**

1. **A4 互锁 ●→○（0.12）。** "只有互锁通道能抓"在**定性上成立**——面对知模型的攻击者，时序（0.00）与结构（0.02）都归零，互锁是唯一有提升的通道。但单消息只有 0.12，序贯累积后 0.49。这条主张要改成"只有互锁**看得见**"，不能写成"互锁能可靠抓住"。**注入器强度决定这条结论**：早先版本让攻击者复制当前操作，制造异常重复，结构通道立刻拿到 0.19，头条主张当场作废；换成攻击者按转移模型挑最可能的下一步（knowledge=model）后才归零。论文必须写明 A4 的攻击者知识等级，否则这个数字不可复现。**（后续追加订正：E2 进一步把这一格判废——0.12 的"看得见"进不了端到端指标，M-b 整条移入局限。此处保留原始测量值，但不得据此写任何主张。）**
2. **A6 时序 ●→✗（0.04），结构 ✗→○（0.17）。** 完全反了。看门狗在活动**开始**时布防，而整条活动被抹掉时它压根没布防，所以时序看不见；真正察觉的是下游——被删活动本该产出的物料令牌不存在，后继活动的结构与互锁检查落空。这也印证了把 A6 移出"既有方法结构性无能"主张的决定。
3. **A2 硬层：先测出 0.29，查明是实现缺了一元检查，补上后 0.98。** 这一格是全表唯一"手写声称正确、实测对不上是因为实现不全"的例子，值得单独记一笔：**实测与文档分歧有两种成因，主张错与实现不全，不能默认前者。** 原实现的 F 只做二元的转移可达性，而它只在同一 case 内同设备有前驱时可查——实测 3,062 个活动只产生 953 次检查（953/3062 = 0.311），恰好等于测出的 0.29。补上一元检查（"这台设备允不允许做这个操作"，不需要前驱、覆盖 100%）后升至 0.98，序贯@10 达 1.00。详见结论三十二。
4. **A2 互锁 ○→✗、A3 互锁 ○→✗。** 这两类攻击不扰动物料流，互锁本就无从下手。原表给 ○ 是想当然。
5. **A1 时序 ●→✗（0.03）。** 朴素重放照搬历史时长，时序通道看到的是一个完全正常的时长。要靠时序抓重放，得攻击者不复制时长才行——那已经不是"朴素"重放了。
6. **A1 结构 ●→○（0.19）、A5 结构 ○→✗、A5 互锁 ○→✗。**
7. **A5 时序 ○→●（0.48）。** 唯一被**低估**的一格：渐变漂移在时序通道上比预想显著得多，序贯@10 达 0.97，是全表最高。原因是漂移作用于连续一段活动，正是 CUSUM 的最优场景。

**A2 的启示：结构通道是设备盲的，但补救的地方不是结构通道。** case 级链的状态是操作名而非 (设备, 操作)，因此"错误的设备做了正确的操作"对结构通道不可见。看似显然的修法是把状态换成二元组——**实测证明这条路走不通，正确的修法是给 F 补一元检查**，见结论三十二与三十三。

## 剩下什么真正站得住

有三条，其中第一条是我检索后认为**最该抬成头条**的，而它恰好是我上一轮建议降级的那条。

> **⚠️ 全节订正（E1/E2 实测后）：S1 的问题域立论成立，但它原先指定的兑现机制已被推翻。**下文把 S1 的价值落在"跨设备不变量 + 命令–响应因果配对"上，其中**跨设备不变量（物料令牌守恒）作为统计通道已被证伪**——E2 净贡献 $+0.01$、功效天花板在部署 $q=0.047$ 下仅 0.21（结论四十二、四十七）。**存活下来的是同一份参考模型的另一半：可行性掩码 $\mathbf F$**（一元 F 覆盖 100%、良性违反 0、E2 $-0.07$），以及命令–响应因果配对（硬层的一部分）。
>
> 所以 S1 现在应当这样陈述：**先行工作为可学性丢弃的那部分跨设备信息，本文并不是用它做统计判据，而是用它做硬约束**——因为"没见过"与"不允许"在日志里无法区分（M-f，时间序下 3.9% 的良性活动是训练折未见组合，参考模型拒绝其中 0 条）。这个陈述比原版更强：它不但说明先行工作没覆盖，还说明**为什么数据驱动方法原则上覆盖不了**。阅读下文时请按此订正理解"跨设备不变量"的角色。

**S1（强，已核实原文）：调度协同层这个问题域几乎是空的。**
这是检索里最清晰的空白。AGV/多智能体的攻击防御文献**全部集中在连续控制层**——事件触发安全路径跟踪、集员滤波抗重放、鲁棒卡尔曼滤波抗 FDI/DoS、车队编队抗重放，处理的是位置/速度这类连续状态估计。而离散自动机那一脉分两个子支，**都不是本文的层次**：TABOR、Modbus DFA、SWaT/水处理/燃气处理的是**单一工艺过程**；DCTA、IEC-104 被动监测处理的是**网络报文会话**。生产线计时自动机（Maier & Niggemann）虽面对多模块产线，但按网络拓扑**分解**后逐组件独立建模判决。三者都没有"多台设备被中央调度器按任务耦合起来"的协同结构。

也就是说：**"生产调度层（调度系统–现场设备的命令/状态回环 + 跨设备互锁）的注入攻击检测"这个问题本身没被系统研究过。** 这里能立住的具体机制是我之前列的 C 与 B：跨设备不变量（机械臂进入 Producing 必须有 AGV 完成投料；任务数守恒；栅格互斥）与命令–响应因果配对。攻击者可以把单台设备的状态标签和时序都伪造得天衣无缝，但**要让整个车间同时自洽，他必须同时伪造多台设备的消息流并与调度系统自己的命令记录对齐**——这是一个比"抢跑量受限"强得多的约束，而且是这个域独有的、SWaT 那类单过程系统里不存在的结构。

#### 已核实：三篇最近先行工作均不覆盖跨设备耦合（S1 的风险已关闭）

这曾是待决事项里唯一的高优先级风险（"若 TABOR/DCTA 已触及跨设备耦合，S1 立即崩塌"）。逐篇精读原文后，**S1 成立，且可以用比原先更强、更可证的方式陈述**。

**（一）Maier & Niggemann (ICINCO 2011) —— 最关键的一篇，且证据方向对本文有利。**
表面上它最危险：题目就是"生产线"，且第一步就"学习拓扑与并行结构"。但精读后发现其用途是**相反的**：

- Definition 1 明确假设 "we assume a global time base and a deterministic, discrete system; from this it follows that ... **a component behaves sequentially**"。学并行结构的目的是把系统**分解**为互相独立的顺序组件以规避状态爆炸——原文举例，两个各含 1000 状态的异步组件若不知并行结构，联合建模可能学出 $10^6$ 个状态。
- 所学的"拓扑"是 **PROFINET 网络拓扑**（DCP 收集 IP → LLDP/SNMP 取邻居 → 合并成拓扑图），即"哪些设备在网络上相邻"，被用作**信号独立性的代理**，**不是物料流或任务耦合**。
- Definition 2 虽然形式化了组件间连接映射 $z$，但它只服务于分解；**检测算法（Fig. 7）在单个自动机 $A$ 上迭代**，逐观测检查符号（功能错）、时间（时序错）、转移频率（概率错）三项，**全文没有任何跨组件一致性检查**。案例研究学了两个模块两个自动机，最后只是 "combining all signal outputs from the components" 做并集。

**可写进 Related Work 的一句话**：这一脉为了让模型可学，**主动丢弃**了跨组件耦合；而本文正是把被丢弃的那部分耦合当作检测信号。这比"他们没做"有力得多——是"他们的方法论前提排除了它"。

**（二）TABOR (AsiaCCS 2018) —— 贝叶斯网络是严格站内的。**
它的 BN "discover dependencies between sensors and actuators" 听起来跨部件，但 Table 1 的 sub-model split 逐条都限制在**同一 stage 内**（子模型 1 = LIT101 + MV101/FIT101/P101/P102，全属 P1；子模型 5 = DPIT301 + FIT301/MV301–304/P302，全属 P3），正文原话是学 "the sequential behavior, as well as their dependencies on the actuators **in the same stage**"。此外它显式声明 "we focus on the detection of physical process; network traffic data are ignored"，**没有任何命令账本**，因此命令–响应因果配对在其框架内不可表达。

**一个可直接引用的缺口**：SWaT 的官方攻击分类里本就含 **2 个 MSSP（多阶段单点）+ 4 个 MSMP（多阶段多点）跨 stage 攻击**，即该社区**已经承认跨过程攻击的存在**，但 TABOR 的模型结构中没有任何跨 stage 成分，只能依靠各站独立检测的并集去碰。"攻击分类学已承认、检测模型未覆盖"这个错位，是本文问题层立论最干净的引用支撑。

**（三）DCTA (TNSM 2024) —— 层次判断需更正，不构成撞车。**
它是智能电网 SCADA 的 **IEC-104 网络报文层**确定性计数计时自动机，约束对象为报文属性、事件定时与协议状态计数器，建模单元是 MTU–RTU 通信会话。其 single-message / message-sequencing / time-based 三类**命名法**与本文的通道划分有表述重合，须显式引用并划清，但它与工艺层、设备协同、调度语义均无关。

**（四）两个额外收获，直接加固 M7 与 M8 的必要性。**
- Maier 那篇在结论中自陈未解决的问题："Sometimes a correct behavior was recognized as an error... we would need an infinite number of test samples"，其阈值是人工设定的容差 $\alpha$，**无任何无分布误报保证**。这使 M8 的 conformal 校准从"锦上添花"升格为**回应基线谱系中一个明写的开放问题**。
- 该脉络的判决是**逐观测立即返回 anomaly**（Fig. 7 的 return anomaly），没有任何证据累积机制。这为 M7 序贯检验提供了明确对照：在 $\rho=0.15$ 这类弱信号下，逐观测判决结构上无法达到 CUSUM 的 86.8%（结论二十一）。

**S2（中→强，已在 Trier 上构造性验证）：不可能性结果（原观察 1）。**
原表述是"$\delta_{\max}=\sqrt2<\varepsilon_{\text{idle}}=1.58$，故该族检测器对高频状态检出概率恒为零"，依赖 $k=10.25$ 与 $\mathcal P_{\mathrm{BN}}(\text{idle})=0.154$ 这组具体系数，评审一句"重新标定系数即可"就能挡回来。**实测后已升级为一个与系数无关的结论**，见"已实测：原方法不可检测集合的构造性枚举"。核心是：$\delta$ 是 (前驱, 观测标签) 的确定性函数，与消息是良性还是注入无关，因此该族检测器对**标签自洽的注入**判别力恒为零，任何阈值函数、任何系数都改变不了。这条既是 Motivation 里的引理，也直接推出 M-c（判据必须从几何换成信息量）。

**S3（中）：定量界的离散事件实例化。**
$\rho^*(\alpha,\sigma)=1-e^{-\sigma z_{1-\alpha}}$（**单侧**，抢跑是有方向的备择假设，见结论十九），以及 $k$ 次重复注入下的 $\sqrt k$ 收紧。体裁（隐蔽攻击基本极限）不新，但**用"重放状态消息的相对时间抢跑量"表述、且闭式只依赖 $(\sigma,\alpha,k)$ 三个量**的版本我没找到对应工作。这是"已知体裁 + 新实例"，可以立住，但论文里必须明确承认体裁归属并说清与连续 LTI 版本的区别（离散事件、无系统矩阵、界只依赖时序变异）。

## 由此产生的三个硬性要求

**1. 基线必须换掉。** 现在的 FMM / STBAD / SMLC 是三个稻草人，评审一眼能看出。**必须加入学习型计时自动机（Maier 2011 那类）与 TABOR 式的"计时自动机 + 贝叶斯网络"作为主基线**，最好再加一个 HSMM 似然基线。如果打不过这些，方法就不成立；如果打得过，赢在哪里必须归因到 S1 的跨设备机制上（因为单设备时序那部分他们也有）。

**2. 必引且必须显式区分的文献**：TABOR（AsiaCCS'18）、DCTA（TNSM'24）、Maier & Niggemann（2011）、Lin & Nadjm-Tehrani（2018）、Tan & Xi（AMC'08）、Li/Yılmaz/Wang（TSG'15）、RESS 2026 那篇 conformal ICPS、Mo & Sinopoli 水印一脉。Related Work 的对照结构应按**三个层次**写，而非笼统的"单过程 vs 多设备"：（i）网络报文层（DCTA、IEC-104 被动监测）——约束协议会话；（ii）单工艺过程层（TABOR、Modbus DFA、SWaT 系）——约束一个过程内的传感器–执行器依赖；（iii）多模块产线层（Maier 一脉）——面对多设备但**按网络拓扑分解后逐组件独立判决**。本文是第（iv）层：**任务耦合的设备协同 + 调度器命令账本**。这样写的好处是每一层都能指出它"为什么表达不了 A4/A7"，而不是只说"它们没做"。

**3. 期刊定位要放实。** 以现在的组件构成，冲顶会（CCS/NDSS/S&P）或 TIFS/TDSC 是不够的——组件全是已知的，新意在问题域和两个中等强度的理论结果。合理的目标是 IEEE IoT-J / TII / Computers & Security / JISA 这个层次，或国内的《自动化学报》《通信学报》。这不是坏结果：一篇"问题域新 + 有两个可证结论 + 基线选得硬"的工程理论文章在这个层次是站得住的。


## 新标题考虑

研究对象是"调度系统 + AGV + 机械臂"构成的**一个**生产系统，攻击目标是调度决策，不涉及设备间自治协商，因此弃用"多智能体"框架，统一改为"生产调度层 / 现场设备"。

**定稿（2026-08，据 E1/E2 实测重定）：**

中文：**基于时序半马尔可夫与参考模型可行性约束的工业生产调度层注入攻击检测**（32 字）

英文：**Timed Semi-Markov Consistency and Reference-Model Constraints for Detecting Scheduling-Layer Injection Attacks in Cyber-Physical Production Systems**（18 词）

**为什么把"跨设备互锁一致性"换成"参考模型可行性约束"。** 旧标题的第二个方法词是 E2 里净贡献 $+0.01$ 的那一路（结论四十二），即去掉它端到端不变甚至略好；继续留在标题里会与自己的消融表正面矛盾，是审稿人一眼能看出的内部不一致。换上来的一元 $\mathbf F$ 覆盖 100%、良性违反 0、E2 净贡献 $-0.07$，是仅次于时序通道的第二承重模块。两者都从同一份 BPMN 导出，故"参考模型"这个词把跨设备信息保留了下来——只是兑现方式从软通道换成了硬层。

**方法侧与实测配置是精确的一一对应**，这是这个标题最值得保留的性质。良性天花板判据最终选出的三条路，被标题的两个方法词完整覆盖，不多不少：

| 标题里的词 | 对应的检测路 | E2 净贡献 |
|---|---|---|
| 参考模型可行性约束 | 硬层 $\mathbf F$（一元 + 二元）+ 命令–响应因果配对 | $-0.07$ |
| 时序半马尔可夫的"时序" | 时序通道（停留时长分布） | $-0.11$ |
| 时序半马尔可夫的"马尔可夫" | 结构通道（转移概率） | $-0.04$ |
| （标题里没有） | 互锁通道、Fisher 合成路 | $+0.01$、$+0.03$ |

**"半马尔可夫"这四个字不可替换成"停留时长一致性"或"时序一致性"。** 判据是本文档第 225 行自己立的规矩——单纯的时序一致性不是创新点，计时自动机/HSMM 已做十五年。标题里的时序词必须当场挡回"计时自动机不是早做过了吗"这个反问，而只有"半马尔可夫 / 时长分布 / 分级证据"这类词能挡：它们指向**分布型**时长，而 BUTLA/TABOR 是**区间型 clock guard**。这正是 A3 抢跑重放那一格 B2 精确为 $-0.01$、本方法 0.18 的机理来源（M-d）。已比较过的四个备选及其判定见下表。

| 备选 | 时序词能否挡住"计时自动机已做过" | 长度 | 判定 |
|---|---|---|---|
| **半马尔可夫 + 参考模型可行性约束** | 能 | 32 字 / 18 词 | **定稿** |
| 停留时长一致性 + 工艺可行性约束 | 不能，听起来就是 clock guard | 29 字 / 18 词 | 否 |
| 时序与可行性双判据 | 不能，"时序"最泛 | 25 字 / 16 词 | 否（最短，但代价太大） |
| 可行性否决 + 分级时序证据 | 能 | 28 字 / 17 词 | 留作**摘要第一句**的骨架 |
| 参考模型约束 + 停留时长分布一致性 | 能 | 32 字 / 19 词 | 否，比定稿更拗口 |

**这个标题装不下的东西，以及必须在哪里补。** T-a（不可能性）与 T-b（影响上界）是清单上最硬的两条，方法+场景式标题在语法上装不下负面结果与上界。这是格式的结构性代价，换词解决不了，只能靠标题相邻的位置补：

- **T-a 必须是 Intro 的第一个动作**，而不是放在 Related Work 里当一段评述。
- **T-b 必须进摘要前两句。** 具体风险是：标题落在"检测"上，审稿人就按检出率量它，而净检出率是 0.48 不是 0.95；真正硬的那条（攻击者能偷到的时间有上界）却隐形。故摘要顺序必须是**不可能性 → 上界 → 检出率**，检出率放第三位当支撑证据。倒过来先报 0.48 会显出标题承诺与结果之间的落差。

**两处措辞纪律，否则标题会被误读。**

1. **"参考模型"在全文里只指可行性掩码 $\mathbf F$ 与命令账本，不含物料令牌不变量 $\mathcal I$。** 两者都从 BPMN 导出，而 $\mathcal I$ 已被判定撑不起通道；标题写了"参考模型"，读者会顺势期待令牌那部分，正文若不划清界限，等于隔着一层把已死的 M-b 又请回来。$\mathcal I$ 只在"局限与未来工作"里作负面结果出现。
2. **"可行性约束"会招来"这不就是 conformance checking 吗"。** 挡它的不是标题而是 M-f（可行性约束不可从日志学出），故 M-f 必须是一条正式编号的机制层主张，且出现在摘要第二句。

### 术语选择

- **生产调度层 / Scheduling Layer**：直接点出被欺骗的对象是调度决策，且与既有两支（连续控制层、单过程 ICS 时序）形成清晰的第三层对照。若担心与实时操作系统的任务调度混淆，可用 `Task-Scheduling Layer` 或 `Dispatch Layer`。
- **Cyber-Physical Production Systems (CPPS)**：Industrie 4.0 既有术语，天然覆盖"调度系统 + 多台异构设备 = 一个生产系统"，且不含"agent"。若嫌其偏架构语境，可换 `Scheduler-Coordinated Industrial Systems`（自解释性更强）或 `Networked Production Systems`。
- **跨设备互锁 / Cross-Device Interlock**：标题用 `interlock`（工业工程通用词，工程读者一看就懂）；正文术语表用 `coordination invariants`，以显式声明这是把 SWaT 那一脉的 `process invariants` 从单过程扩展到跨设备协同。
- **一致性 / Consistency vs Conformance**：投 IoT-J/TII 这类偏工程期刊用 `Consistency`；投偏形式化方法或离散事件系统方向用 `Conformance`（conformance checking 是该领域行话，更显内行）。
- 标题内不出现 CPPS、FDIA、CPS 等缩写，也不塞框架首字母缩写名（正文里用无妨）。

### 问题层

**Q1｜生产调度层作为独立攻击面。** 首次把"调度系统–现场设备的命令–状态回环 + 跨设备任务耦合"形式化为一个独立的攻击面与检测层。既有工作分裂为两支且都不覆盖它：一支是**连续控制层的 AGV 安全**（事件触发安全路径跟踪、集员滤波抗重放、鲁棒卡尔曼滤波抗 FDI/DoS、编队抗重放），处理位置/速度的连续状态估计；另一支是**单过程 ICS 的计时一致性**（TABOR、DCTA、Modbus DFA、SWaT/燃气），处理单一工艺流程。调度层的特征是"多台设备被中央调度器按任务耦合"，两支都没有它。

**Q1 的强化陈述（已核实原文，见查新章）**：不能只说"他们没做多设备"，而要说**他们的方法论前提排除了它**。生产线计时自动机一脉（Maier & Niggemann）为规避状态爆炸，先按网络拓扑把系统**分解**为互相独立的顺序组件（Def. 1 明确假设 "a component behaves sequentially"），再逐组件建模、逐组件判决——**跨组件耦合是被主动丢弃的建模代价**；TABOR 的贝叶斯网络虽学依赖，但严格限制在同一 stage 内，且显式忽略网络与命令数据。也就是说，本文用作检测信号的那部分信息，恰是先行工作为了可学性而牺牲掉的。与此同时，SWaT 攻击分类中已含 MSSP/MSMP 两类跨阶段攻击——**该社区承认这类攻击存在，却没有能表达它的模型结构**。这个错位是问题层立论最干净的支撑点。

**Q1 的论据换基（E1/E2 实测后必须改，否则与消融表矛盾）。** 原版把 Q1 的兑现落在"跨设备不变量作统计通道"上，而那一路已被证伪（M-b 判废）。**换基后的陈述反而更强**：先行工作丢弃的那部分跨设备信息，本文不是拿它做统计判据，而是拿它做**硬约束**——因为"日志里没见过"与"参考模型不允许"无法区分，而时间序下"没见过"会以 3.9% 的比例良性发生，远超 $\alpha$（M-f）。于是问题层的立论从"他们没覆盖"升级为"**数据驱动方法原则上覆盖不了，必须外挂参考模型**"，这同时解释了 B4 TABOR 为何打不过 B3 BUTLA（其站内 BN 给未见组合的极端负对数似然在良性数据里已经出现）。

**Q2｜检测对象从状态标签扩展为带时间与命令上下文的事件。** 合法行为的模型从标签序列上的分布，改为 $(\text{标签},\ \text{停留时长},\ \text{命令上下文})$ 三元组上的标记点过程。（注意：单纯的"时序一致性"不能作为创新点，计时自动机/HSMM 已做十五年；这里的表述重点在**命令上下文**与**调度语义**。）

**Q3｜安全目标从"检出所有攻击"改为"可检测或无害"。** 不追求 100% DR，而是给出攻击者可获得影响的上界：规避检测的注入其时间抢跑量被限制在 $\rho^*$ 以内。评价标准从经验 DR 抬升为定量安全保证。

### 机制层

**M-a｜纵向不可伪造性（时间维）。** 攻击者控制消息发出时刻，但不控制物理推进。想要收益就必须抢跑，抢跑就产生时序残差——**攻击收益与时序隐蔽性在机理上直接冲突**，且该冲突可被量化（见理论层）。

**M-b｜横向不可伪造性（设备维）。**（❌ **已被结论四十二、四十七判废，不得作为主张出现在方法章**）原表述：跨设备不变量与命令–响应配对要求攻击者让整个车间的账目同时自洽，是比 M-a 强得多的约束，也是唯一能对付 A4 的机制。**实测推翻了它的可用性而非它的正确性**——A4 上确实只有互锁**看得见**（时序 0.00、结构 0.02、互锁 0.12），但 0.12 进不了端到端指标：$\mathcal I$ 因 1.7% 良性违反只能做软层，二值通道功效被 $\min(1,\alpha/q_{\text{部署}})$ 封顶，而部署 $q=0.047$ 使天花板只有 0.21。已试过跨 case 全局令牌池把 $q$ 压到 0.22%，但攻击触发率同步腰斩，端到端打平。**保留下来的只有这一句：命令–响应因果配对**（设备上报了调度器从未下发的操作），它属于硬层、不属于互锁通道。整条 M-b 移入"局限与未来工作"，并给出定量部署门槛：要让它够用需把部署 $q$ 压到 $\alpha$ 量级（约 1%），近似身份解析只做到 2.3%，剩下一半必须靠真正的 NFC/RFID 工件标识。

**M-f｜可行性约束不可从日志学出，这是外挂参考模型的唯一硬理由。**（本轮新增编号，证据强度与 M-a 同级）日志只能告诉你"哪些组合出现过"，无法区分"没见过"与"不允许"；而在时间序口径下"没见过"是一个**良性高频事件**——测试折有 3.9%（20/508）的良性活动是训练折未见的 (设备, 操作) 组合，远超 $\alpha=0.01$，故任何数据驱动模型都不能把未见组合当作证据。参考模型拒绝了这 20 条中的 **0** 条，即它精确地把"未见"与"不允许"分开了。三条推论，都已实测：（1）一元 $\mathbf F$ 覆盖 100% 的消息且良性违反为 0，是仅次于时序通道的第二承重模块（E2 $-0.07$）；（2）**试图用统计通道代替它会失败**——把结构状态细化成 (设备, 操作) 本应恢复设备敏感性，实际因未见组合触发**弃权**而使 A2 检出从 0.35 归零，且 FPR 涨到名义值的 5 倍（结论三十三）；（3）B4 TABOR 打不过 B3 BUTLA 的根因就是这一条。**方法论层的推论更值得写进论文**：弃权语义会把改进悄悄吞掉，且在指标上伪装成"模型不够好"。

**M-c｜判据由几何距离改为信息量，可行性掩码由此真正生效。** $\ell_2$ 判据被证明只是被 $\|p\|^2$ 污染的一步似然检验（见理论层引理）；改用 $-\log \tilde P_{ij}$ 后，掩码中的零概率转化为**一票否决**，漏报概率恒为零。这同时否掉了 VAE 路线——问题不在于"需要更好的几何"，而在于**根本不需要几何**。

**M-d｜分级证据可累积，二值判断不可。** 单条落在正常区间内侧的注入逐次都能过关，但系统性同向偏差在对数似然比上表现为恒定漂移，必被 CUSUM 捕获。这是"必须用 p 值而非区间判断"的机理原因。

**M-e｜协变量条件化把已知信息换成更硬的保证。**（⚠️ 已被结论四十四大幅降级，机制表述保留、量级必须改写）用调度系统自己派发的任务参数（起终点路线、产品型号、负载）条件化停留时长，可压缩 $\sigma$；而由 $\rho^*=1-e^{-\sigma z_{1-\alpha}}$ 单调，$\sigma$ 变小直接意味着攻击者可获影响上限被压低。机制成立且收益可被定理量化，**但在本产线上量级只有 1 个百分点**：逐组加权、时间序口径下 $\sigma$ 由 0.236 降到 0.228，$\rho^*$ 由 42.2% 收到 41.2%；端到端消融甚至倒亏 0.04。此前记录的"$\sigma$ 由 0.355 降至 0.116、$\rho^*$ 由 56.2% 收到 23.7%"只在**多路线搬运类分组内**成立（29 个分组里具名路线合计 34 条，多数分组单一路线、条件化是空操作），不可作全局陈述。

### 理论层

**T-a｜不可能性结果（S2）。** 分三级陈述，强度递增，后两级与系数取值无关：

- **T-a.1（数值级）**：在给定系数下存在 $\varepsilon_i>\delta_{\max}=\sqrt2$ 的行，该行任何观测都不报警。Trier 实测：专利线性版（$k=10.25$）有 **10/20** 个前驱状态整行全盲。
- **T-a.2（结构级）**：展开 $\delta_j^2=\|\mathbf e_j-\mathbf p\|^2=1-2p_j+\|\mathbf p\|^2$，可见 $\|\mathbf p\|^2$ 对同一行的所有 $j$ 是常数，**$\delta$ 只是 $p_j$ 的单调减函数**——所谓"$\ell_2$ 几何距离"退化为对预测概率的一元变换，几何结构完全冗余。由此立即得到：攻击者的**最优规避目标** $\arg\min_j\delta_j=\arg\max_j p_j$，**恰好也是最有攻击价值的目标**（调度器正等着这个状态，伪造它即可推进调度）。**在原方法下规避与收益是对齐的**，而本文方法（M-a）让二者在机理上冲突。这一条是 M-c 的直接依据。
- **T-a.3（不可能性，与系数无关）**：$\delta$ 是 $(i,j)$ 的确定性函数，与该消息是良性还是注入无关，故在行 $i$ 上"能检出注入 $j$"$\iff$"每一次良性的 $j$ 都报警"，即 $\mathrm{DR}(\text{注入 }j)>0\Rightarrow \mathrm{FPR}_i\ge p_j$。**推论：零误报前提下可标记的集合恰为 $\{j:p_j=0\}$，即可行性掩码已零成本拒绝的那些转移。马尔可夫层与贝叶斯阈值层对标签自洽的注入贡献恒为零。**

**T-b｜影响–可检测性界（S3）。** $\rho^*(\alpha,\sigma)=1-e^{-\sigma z_{1-\alpha}}$（单侧），重复注入 $k$ 次收紧为 $\rho^*_k\approx1-e^{-\sigma z_{1-\alpha}/\sqrt k}$。**全文的 $z$ 一律取单侧分位数**：抢跑是方向性备择，双侧在同一 $\alpha$ 下白白损失约一半功效（$\rho=0.5$ 时实测 DR 0.874 对 0.338，结论十九）；"滞留/抑制"由 M4 的右删失生存函数分支单独覆盖，不靠双侧兜。已实测验证：$\alpha=0.01$ 单侧下理论预测与实测检出率全区间平均绝对偏差约 0.03（结论十七）。

**T-c｜引用性保证。** 序列检验部分的延迟渐近最优性（Lorden/Lai）与 conformal 的无分布 FPR 保证——这两条是引用既有结论，不作为自己的贡献，但使整套方法"有保证"而非"仅实验有效"。

## 方法层与模块衔接

### 总体架构

离线阶段（仅用正常运行日志 + 领域知识，无攻击标签）：

```
正常日志 ──┬─→ [M1 事件流解析：按设备分链 + 命令对齐 + 任务参数提取]
           │        ├─→ [M3 跳转链估计 P̃：Dirichlet 后验预测 + 掩码置零]
           │        └─→ [M4 停留时长估计：NIG→Student-t 后验预测 + AFT 协变量 + 层次收缩]
领域知识 ──┴─→ [M2 可行性掩码 F + 互锁不变量集 I]
                        ↓
           [M8 校准：留出正常数据 → conformal 阈值 τ_α + CUSUM 门限 h(ARL₀)]
```

在线阶段（每条消息 $O(1)$）：

```
消息(设备ID, 状态, 到达时刻) 
   → [M0 归属：取该设备上一确认状态 i 与时间差 τ]
   → [M2' 硬约束层：F_ij = 0 或违反不变量 I → 立即报警 + 可读原因]
   → [M3' 结构 p 值 p_struct ← P̃]   ┐  各自过 M8 conformal
   → [M4' 时序 p 值 p_time ← 四分支]  ├→ 校准（必须在合成之前）
   → [M5' 互锁 p 值/布尔 ← I]        ┘        ↓
                                    ┌─────────┴─────────┐
                        [M6 Fisher 合成]        [逐通道单独判决]
                                    └─────────┬─────────┘
   → [M7 CUSUM 累积 −log p → 越界报警]（两路并行，α 预算二分）
   → [M9 正常则：状态锚定 + EWMA 参数更新 + 重置看门狗定时器]
```

### 各模块要点

**M1 事件流解析与按设备分链。** 把原始日志解析为每设备的事件序列 $(d, s_k, t_k)$，并与命令序列 $(d, u_l, t_l)$ 做时间对齐，提取任务参数作为协变量。这是前置重构：放弃交织的 7 维联合链。

**M2 可行性掩码与互锁不变量。** 掩码 $\mathbf F\in\{0,1\}^{n\times n}$ 编码禁止/必然/概率三类转移；不变量集 $\mathcal I$ 编码跨设备约束（投料前置、栅格互斥、任务数守恒、物料守恒）。**两者均可从参考过程模型自动导出，无需手工编造**（已在 Trier 的 16 个 BPMN 上验证，见实验章"$\mathbf F$ 与 $\mathcal I$ 能否自动导出"）。但**只有 $\mathbf F$ 是"硬"的**（实测正常数据违反率 0.00%）；物料流不变量在缺少工件级身份标识时残余约 1.7% 良性违反，须作软证据处理。

**M3 结构通道。** $\tilde P_{ij}$ 用 Dirichlet 先验的后验预测（消除小样本下的伪零概率，同时保留掩码强制的真零）。结构 p 值 $p^{\text{struct}}=\sum_{j':\tilde P_{ij'}\le\tilde P_{ij}}\tilde P_{ij'}$，**且必须取随机化（平滑）形式**：$p=\sum_{j':\tilde P_{ij'}<\tilde P_{ij}}\tilde P_{ij'}+U\!\sum_{j':\tilde P_{ij'}=\tilde P_{ij}}\tilde P_{ij'}$，$U\sim\mathrm{Unif}(0,1)$；否则 p 值原子化会使 conformal 校准彻底失效（实测 FPR 达 1.000，见结论十四）。**链的粒度是 case 级工作流序列，不是设备级**：实测设备级链 65.1% 长度为 1、结构 p 值取值唯一，信息量为零（结论十二、十三）。

**M4 时序通道。** 半马尔可夫核分解 $Q_{ij}(\tau)=P_{ij}F_{ij}(\tau)$，其中 $P_{ij}$ 正是既有转移矩阵（严格向后兼容）。停留时长取对数正态 $\log\tau\sim N(\mu_{ij},\sigma^2_{ij})$，NIG 共轭先验 → 闭式 Student-t 后验预测（小样本时尾部自动变厚，避免误报风暴），先验中心向状态级与全局逐层收缩，同型号设备共享上层先验。协变量用 AFT，形态由实测定为**加性参数化** $\log\tau=\mu+a_{\text{start}}+b_{\text{end}}+\beta^\top x+\epsilon$：路线协变量解释 89.3% 的方差（$\sigma$ 由 0.355 降至 0.116），且因物料流路线图是森林，加性参数化与逐路线饱和模型残差完全相等，可省参数而不损拟合。**未见路线回落到以 $\log(\text{plan})+\hat c$ 为中心的先验**（实测 $\sigma=0.159$，优于加性模型外推的 0.279）；森林拓扑下邻近路线无统计强度可借，故层次收缩必须依赖计划值与设备型号两个上层，不是可选项。四种观测情形对应四个分支：
- 状态跳变 → **左侧** p 值 $T_\nu(t)$（只查"太快"，即抢跑）。实测单侧对双侧在 $\rho=0.5$ 时 DR 为 0.874 对 0.338（结论十九）；"太慢"由下面的生存函数分支单独覆盖，两者机制不同，合并成双侧白白损失一半功效
- 心跳重报（同状态） → 右删失生存函数 $-\log(1-F(\tau))$，只在"待太久"时报警
- 超时无消息 → 同一生存函数，由定时器在 99.9% 分位触发（覆盖 A6）
- 周期轮询 → 区间删失 $\log[F(\tau+\Delta)-F(\tau)]$（HAI 必需，否则量化误差系统性污染似然）

**M5 互锁通道。** 分两层：**硬层**只放实测零违反的约束——$\mathbf F$ 违反、以及"状态上报无前置命令事件"这类因果缺失，直接报警并输出人类可读原因（如"机械臂声称在生产，但无 AGV 投料记录"）。**软层**放物料流令牌不变量与任务数偏差，转成 p 值参与 M6 合成。若产线具备 RFID/NFC 工件身份（Trier 数据集的 `use_nfc` 参数表明这在真实产线可得），软层可上升为硬层——这是一条明确的部署条件，应在论文中写成命题而非回避。

**M6 融合。**（本条已按实测全面改写，推翻了结论十六）不直接相加负对数似然，因为三通道量纲不同且不可解释，必须先各自转成 p 值。实测定下三条：

- **必须先逐通道 conformal 校准，再合成；不能先合成再统一校准。** 原始参数化 p 值远非均匀——8.1% 的良性活动时序 p 值直接触到数值下界，且其中 89.8% 是训练折**已见过该路线**的真·模型失配（只有 10.2% 是冷启动外推）。这些点在 Simes/最小 p 值这类 min 型统计量的底部形成原子，末端校准无法分辨，实测 FPR 卡在 0.074 且对 $\alpha$ 不敏感（0.05 与 0.01 给出同一个数，这正是原子的特征）。改为先逐通道校准后，四种合成器在名义水平下都有效（FPR 0.010~0.013）。
- **逐通道校准之后不需要第二层校准。** "先逐通道校准后按名义零分布判定"与"再对合成统计量校准一次"的经验 FPR 相当（0.010 对 0.013），而后者要多吃一份校准集，与 M8 的规模硬约束直接冲突。取前者。
- **合成方式取 Fisher。** 见下条对结论十六的推翻。

**M6 补充：合成不是免费的，必须与逐通道判决并行。** 在只触碰时序的 A4 抢跑（$\rho=0.2$）下，仅时序通道的功效是 0.110，而任何三通道合成都只有 0.042~0.060——合成把功效**稀释了约 2.5 倍**（min 型统计量要付 $k$ 倍 $\alpha$ 的代价，Fisher 则被两个无信息通道摊薄）。合成的价值在**覆盖面**而非功效：换成同时伪造工序位置的多通道攻击后，Fisher 0.413、Simes 0.187，而仅时序通道仍停在 0.108。故在线检测器必须同时跑"合成"与"逐通道"两路、$\alpha$ 预算在两者间划分，只报合成结果会在单通道攻击上白白损失一半以上功效。

**M7 序列检验。** 对 $-\log p_{\text{comb}}$ 或对数似然比做 CUSUM：$S_t=\max(0,S_{t-1}+\log\frac{f_1}{f_0})$，越 $h$ 报警；$h$ 由目标 ARL$_0$ 反解。每设备只需一个标量状态。

**M8 conformal 校准。** 留出正常数据的经验分位数定阈值，得无分布 $\mathrm{FPR}\le\alpha$；序列部分用 e-detector + Ville 得 anytime-valid 控制。**这一步同时修掉旧方法"号称无监督却用 $F_1$ 网格搜索（需要攻击标签）"的自相矛盾**，并把玄学系数 $k=10.25$ 换成用户直接指定的 $\alpha$。**兑现该保证有两个必要条件，均已实测**：一是所有离散通道取随机化 p 值（否则 FPR 达 1.000）；二是校准集与部署数据可交换——工作流间转移集合的 Jaccard 重合度中位数仅 0.324，故**新产品型号必须重新校准或按型号分层校准**。满足这两条后实测经验 FPR 为 0.053 / 0.012（名义 0.05 / 0.01）。

**M9 闭环更新。** 以实际观测锚定状态（消除多步预测漂移，沿用原方法的设计）；EWMA 更新 $(\mu,\sigma)$ 与 $\tilde P$（$\alpha_{\text{EWMA}}\in[0.9,0.95]$）；重置看门狗。**更新必须门控**：仅当该消息通过全部通道、且隔离窗口内无告警时才允许进入基线。这不是工程细节而是与原专利的实质架构差异——实测无门控时攻击者可用 200 条抢跑注入把基线拖走、白拿 26.4% 的调度提前量，门控后降到 1.4%（结论二十八）。看门狗能覆盖"活动已开始、完成事件被抑制"，但覆盖不到"整条活动被完整抹掉"（那需要活动**间隔**模型，本文的时长模型不提供，且 Trier 主流程 77% 的变体率使间隔模型学不紧）——这是 A6 不能列进头条主张的第二个理由。

### 模块为什么这样衔接（这是架构论证，要单独写一小段）

1. **硬约束在最前**：零成本、零漏报、可解释。先把"物理不可能"滤掉，也避免它们污染后续统计通道的校准集。
2. **结构与时序并列而非串联**：两者独立提供证据，合成后才能同时覆盖"标签错"与"标签对但时间错"两类。串联会让任一通道成为单点故障。
3. **三通道覆盖两个正交方向**（此条已按实测修订）：时序通道是单设备**纵向**（时间维）证据；结构与互锁通道都是**横向**证据——结构问"这个活动序列是否常见"，互锁问"物料流是否物理自洽"。A4 状态模仿攻击在纵向上完全隐形，只有横向能抓，这仍是需要三通道的理由。原先"结构属纵向"的论证基于设备级链，而实测表明设备级链信息量为零（结论十二），故该论证作废。**但"横向的两个通道因而不独立"这一推论也被实测推翻**：三通道证据的两两相关只有 $-0.030$ / $-0.008$ / $+0.056$（结论二十三）。"同属横向"说的是信息**种类**相近，不等于统计**取值**相关——这两件事在原论证里被混为一谈了。
4. **序列检验在最后**：它消费的是分级 p 值，所以前面各通道必须输出连续分数而非布尔值（M-d）。
5. **conformal 贯穿全局**：把三个不同量纲的通道统一到"误报预算 $\alpha$"这一个用户参数上，是整套方法可工程交付的关键。

### 复杂度与边缘部署

每条消息 $O(1)$：四次查表 + 两次对数 + 常数次不变量检查。注意可以明确写"新增时序与互锁能力的同时，把在线复杂度从 $O(n^2)$ 降到 $O(1)$"——因为原方法算全分布 $\ell_2$ 范数是多余的，只需要一个矩阵元素。存储 $4n^2$ 浮点 + 不变量表；按设备拆链后单链状态数降到 5 与 2。多设备 $O(M)$ 线性、可并行。

## 实验设计

### 数据集策略：add-on 是可行且推荐的路线

**关键前提：本方法是无监督的，只用正常数据训练，因此不需要"带攻击标注的多设备数据集"（那种确实不存在），只需要"结构合适的正常运行日志"，攻击由我们自己按参数注入。** 这把数据集问题从"找不到"变成"找得到"。所需结构是四件事：① 多台设备各自的离散状态可提取；② 有接收侧时间戳；③ 有调度/工作流引擎的**命令日志**；④ 设备间存在任务耦合。

自行注入攻击在本领域是标准做法（原论文在 HAI 上也是这么做的），且对**新攻击类**是唯一选择——没有任何公开数据集包含"调度层状态模仿攻击"，因为没人研究过它，这正是本文的立论。要让它站得住必须做三件事：攻击**参数化**（扫描 $\rho$、$k$、注入间隔）而非手挑个例；纳入知道 $\hat P$ 的**自适应/全知攻击者**；**开源注入器**。

#### Trier 版为什么是首选，以及必须如实记录的两个风险

三个关键料正好补齐三个模块的缺口：**生命周期三态**补 M4 的命令–响应因果配对；**任务参数（起终点位置、槽位、产品选项）**提供 AFT 所需的协变量（`planned_operation_time` 亦可用，但只宜作冷启动先验，见下文结论二）；**15 个 resource + 工件跨线流转**补 M5 互锁不变量的权威来源，避免"领域知识是为了好看而设计的"这一致命质疑。

**已核对官方 README，生命周期语义比预期更契合。**每个活动在 `MainProcess.xes` 中对应**三个**顶层事件，且 transition 与 state 双重标注：

| XES transition | XES state | 语义（README 原文） | 对应我们的量 |
|---|---|---|---|
| `scheduled` | `assigned` | **资源收到下发的命令并放入其队列** | 命令到达时刻 $t_{\text{cmd}}$ |
| `start` | `inProgress` | 资源上操作开始 | 操作开始时刻 $t_{\text{start}}$ |
| `complete` | `success` / `failure` | 执行结束（含成败） | 操作结束时刻 $t_{\text{end}}$ |

每个事件同时带 `time:timestamp`（该阶段开始）与 `operation_end_time`（该阶段结束），因此可导出两个区间：**派发阶段** $[t_{\text{cmd}},\,t_{\text{cmd}}^{\text{end}}]$ 与**执行阶段** $[t_{\text{start}},\,t_{\text{end}}]$。也就是说本数据集**原生自带闭环的"命令→响应→完成"三元组**，M1 的时间对齐前置重构在此几乎是免费的。

实测字段样例（WF_101_0 首个活动）：`org:resource=hbw_2`、`concept:name=/hbw/unload`、时间戳精度到**微秒**、`planned_operation_time=0 days 00:00:52`、`requested_service_url` 含完整命令与参数、`parameters` 列表给出 `parameter_start_position`/`parameter_end_position`（**AGV 类设备的行程协变量直接可用**）、`response_status_code`、`complete_service_time`、`identifier:id`（BPMN 活动 ID，可回连 `process_model_id` 指定的模型）。

配套资源已确认可用：**16 个 BPMN 模型**（`WF_101`…`WF_122`，对应 16 个工作流）随数据集发布，是可行性掩码 $\mathbf F$ 与不变量集 $\mathcal I$ 的权威来源；**FTOnto 领域本体**（gitlab.rlp.net/iot-lab-uni-trier/ftonto，复用 SOSA/SSN/MASON）给出各传感器**值域**与执行器–传感器归属关系，是状态离散化规则的权威来源。两者都让"领域知识非自证"这一点有第三方出处。

工程注意事项：解压后为 `MainProcess.xes` 顶层 + 每个 `inProgress` 活动一个 `<SubProcessID>.xes` 子文件（清洗版 3,120 项、含错版 2,796 项），靠 XES 属性 `SubProcessID` 关联；IoT 传感器数据以列表内嵌于子事件中，单个子文件最大达 687 MB。ProM / Fluxicon Disco 可读控制流部分，但**均无法直接使用 IoT 传感器数据**，该部分需自写解析。

#### 已实测：时序通道的功效（决定方法可行性的核心数字）

用 `database/ft_trier_iot_log/probe_timing.py` 解析清洗版 `MainProcess.xes`，实测 301 traces / 9,471 events / 3,157 活动实例 / **15 resource / 21 活动 / 16 工作流**（与论文 Table 1 完全一致，数据完整）。资源命名直接映射到本文场景，且**双线并行**（后缀 `_1`/`_2`）：`vgr_1,vgr_2`（真空吸盘机器人，带 `pick_up_and_transport(start,end)`，即 AGV 类比）、`wt_1,wt_2`、`sm_1,sm_2`（分拣）、`hbw_1,hbw_2`（高架仓库）、`mm_1,mm_2`（铣削）、`ov_1,ov_2`（烤炉）、`pm_1`（冲压）、`dm_2`（钻孔）、`hw_1`（人工工位）。

**结论一（正面，且是全项目最关键的一个数）：$\sigma_{\log\tau}$ 中位数 0.207，多组低至 0.01–0.11，时序通道功效充足。** 在 $\sigma\approx0.1$ 下，抢跑量 $\rho=10\%$ 即约 $1\sigma$，$\rho=30\%$ 约 $2.6\sigma$，配合 CUSUM 累积数条消息即可近乎确定检出。这实证了整套方法的立论前提，也给理论界 $\rho^*(\alpha,\sigma)$ 提供了真实的 $\sigma$ 取值范围。

**结论二（修正）：`planned_operation_time` 不能当作 AFT 的期望值锚点。**实际/计划比值从 0.11（`ov/burn`：计划 222 s，实际 26 s）到 1.19（`wt_1`）跨越一个数量级，说明它是**保守的名义预算而非校准估计**。且在同一分组内该值基本恒定，条件于分组后不提供额外信息。正确用法是把它当作**冷启动先验**（未见活动按 $\text{plan}\cdot\hat c$ 定中心，$\hat c$ 为全局偏置因子），而非残差基准。此前"可直接与计划工时作比构成残差"的说法要改掉。

**结论三（设计细化）：必须按 `success`/`failure` 分层建模。**`hbw_2 /hbw/unload` 出现 $\sigma_{\log\tau}=1.798$ 而变异系数仅 0.294 的矛盾组合，是典型的**重左尾/多峰**——少量极短时长（疑为中止或失败执行）把对数方差抬高，而均值稳定。若用单一对数正态硬拟合，$\sigma$ 被严重高估、检测功效白白牺牲。数据集自带 `lifecycle:state` 的 `success`/`failure` 与 `response_status_code`，正好用于分层或混合建模。`hw_1/human_review`（人工工位，$cv=1.31$）建议单独给宽先验或排除，并在论文中说明理由。

**结论四（设计细化，且为协变量必要性提供实证）：同型号设备 `vgr_1`（$\sigma=0.480$，$n=620$）与 `vgr_2`（$\sigma=0.110$，$n=293$）相差四倍。**合理解释是 `vgr_1` 覆盖了更多样的起终点组合。这正是**AFT 协变量（`parameter_start_position`→`parameter_end_position` 行程对）必要性的直接证据**：条件于路线后 `vgr_1` 的离散度应显著收缩。**已实测证实（见下文结论九至十一）：条件化后 `vgr_1` 的 $\sigma$ 降至 0.149，路线解释了 90.4% 的方差。**

**结论五（修正，影响 M4 通道定位）：派发阶段时长不可作为统计检测通道。**实测 $n=3{,}125$，中位 4.31 s 但 **p95 达 253.6 s**、$\sigma_{\log\tau}=1.475$——该延迟由调度器排队竞争主导而非物理规律，作时长检验会淹没信号。因此**命令–响应通道应定位为结构/因果检查（`scheduled` 事件是否存在、顺序是否正确、状态上报是否有前置命令），而非时长检验**。"注入的状态上报若无前置 `scheduled` 事件即为硬互锁违反"这条仍然成立且有力，但"响应时延短于物理下界"这条要撤回。

#### 已实测：$\mathbf F$ 与 $\mathcal I$ 能否从 BPMN 自动导出（互锁通道的可行性）

这是"领域知识非自证"这一质疑的正面回应。脚本见 `database/ft_trier_iot_log/`：`extract_vocab.py`（词表抽取）、`derive_invariants.py`（v1 朴素版）、`derive_invariants_v2/v3/v4.py`（逐步精化）。

**BPMN 里编码了什么。**每个 serviceTask 都带 Camunda `http-connector`，其 `url` 输入参数是一条完整命令，形如
`/vgr/pick_up_and_transport?resource=vgr_1&start=dm_2_sink_pos&end=ov_1_pos`。也就是说**设备、操作、起点、终点四元组直接写在模型里**。从 16 个模型自动抽出：**15 个资源**（与日志完全一致）、**23 个位置**、**31 条物料流转移边**、21 类操作。位置在活动间首尾相接（前一活动的 `end` 即后一活动的 `start`），跨设备交接也在其中（`VGR_2` 送到 `dm_2_sink_pos`，`VGR_1` 从 `dm_2_sink_pos` 取走）——**这就是跨设备互锁不变量的原始形态，无需手工编造**。

**导出方式。**把物料流建模为带时长的 Petri 网：活动在 $t_{\text{start}}$ 消耗其 `start` 位置的令牌，在 $t_{\text{end}}$ 在 `end` 位置产出令牌；$\mathbf F$ 则取 BPMN 顺序流上同设备任务的可达闭包。

**验证结果（清洗版全部 282 个有效 case、3,062 个活动、排除 failure）：**

| 版本 | 精化内容 | $\mathcal I$ 违反率 | $\mathbf F$ 违反率 |
|---|---|---|---|
| v1 | 朴素：单一令牌类型、$\mathbf F$ 取直接后继 | **14.87%** | 14.73% |
| v2 | + 双令牌（工件/料桶）、$\mathbf F$ 取传递可达、分拣机位置别名 | 2.96% | 1.36% |
| v3 | + 别名闭包含日志位置、重试自环 | 1.42%（完整轨迹） | **0.00%** |
| v4 | + 带时长的 Petri 网触发语义（起时消耗、终时产出） | 1.70%（全部） | **0.00%** |

**结论六：$\mathbf F$ 完全可自动导出，且在正常数据上违反率为 0.00%（953 次检查）**，可以直接作为零成本、零漏报的硬约束——这一条完全兑现了 M2 的设计假设。

**结论七：$\mathcal I$ 只能做软通道，不能做硬约束。**残余 1.70%（47/2768）已定位成因：**29 次"NEVER"（该位置在整个 case 内从未被任何活动产出，即清洗版仍有缺失事件）、17 次"LATE"（令牌确由本 case 稍后产出，即真实乱序）、1 次生产者失败**。1.7% 的逐活动误报率对硬约束不可接受，但作为参与 M6 合成的软 p 值贡献完全可用。M5 的定位要相应从"硬违反直接报警"改为"硬违反仅限 $\mathbf F$ 层，物料流不变量降级为软证据"。

**结论八（给出了让 $\mathcal I$ 变硬的路径）：17 次 LATE 的根因是位置是跨 case 共享的物理地点，而令牌模型是逐 case 的。**并发 case 会互相干扰（v1 统计到 453 个从未入库的遗留令牌）。要消除它必须做**工件身份解析**——而数据集恰好带 `use_nfc=true` 参数，NFC/RFID 标签在物理上可用。这可以写成一条明确的设计条件："互锁不变量要成为硬约束，需要工件级身份标识；在具备 RFID/NFC 的产线上可满足，否则只能作软证据。"这是一个诚实且有价值的边界条件，而不是缺陷。

**领域知识用量的精确核算**（回应"你手工塞了多少先验"）：自动导出的部分是 23 个位置、31 条物料流边、16 组设备内操作对；**手工指定的只有 6 条规则**——4 条仓库操作的令牌语义（`unload` 同时释放工件与料桶、`get_empty_bucket` 产出料桶、`store_empty_bucket` 消耗料桶、`store` 同时消耗两者）、1 条分拣机输出位置别名（`sm_N_automatic_pos` ≡ `sm_N_sink_{1,2,3}_pos`）、1 条同操作重复即重试。每条都是关于产线的一句陈述，不含可调参数。

#### 已实测：AFT 协变量的必要性与冷启动（`probe_aft.py`、`probe_aft_v2.py`）

结论四只是推测"条件于路线后 `vgr_1` 的离散度应显著收缩"，现已实测确认，并附带两个未预期的发现。

设三个嵌套模型拟合每个 (resource, operation) 分组内的对数时长：**M0 池化** $\log\tau=\mu+\epsilon$；**M1 加性 AFT** $\log\tau=\mu+a_{\text{start}}+b_{\text{end}}+\epsilon$；**M2 饱和** 逐路线均值。仅用 success 样本，1,781 个带路线的活动实例。

| resource / operation | $n$ | 路线数 | M0 池化 | M1 加性 | M2 饱和 | 方差解释 |
|---|---|---|---|---|---|---|
| `vgr_1` `/vgr/pick_up_and_transport` | 595 | 10 | 0.480 | **0.149** | 0.149 | **90.4%** |
| `vgr_2` `/vgr/pick_up_and_transport` | 281 | 5 | 0.107 | 0.052 | 0.052 | 76.7% |
| `mm_2` `/mm/drill` | 59 | 2 | 0.544 | 0.108 | — | 96.1% |
| `mm_2` `/mm/mill` | 29 | 2 | 0.286 | 0.020 | — | 99.5% |
| `mm_2` `/mm/deburr` | 28 | 2 | 0.207 | 0.023 | — | 98.8% |
| `sm_1` `/sm/sort` | 53 | 3 | 0.287 | 0.251 | 0.251 | 23.5% |
| 样本量加权合计 | | | **0.355** | **0.116** | | **89.3%** |

**结论九：路线协变量是必需的，不是可选项。**$\sigma_{\log\tau}$ 从 0.355 降到 0.116，解释了 89.3% 的方差；`vgr_1` 单独从 0.480 降到 0.149，与 `vgr_2` 条件后的 0.052 已属同一量级。这证实结论四的推测：同型号设备的四倍差异是**路线异质性而非噪声**。不做条件化就等于把可解释的系统性差异当成随机噪声，白白牺牲检测功效。按既定口径 $\rho^*=1-e^{-\sigma z_{1-\alpha}}$（单侧 $\alpha=0.01$，$z=2.326$）估算，**单消息可检出的抢跑量从 56.2% 收紧到 23.7%**——攻击者能偷到的时间少了一半以上；`vgr_1` 单独看是 67.3% → 29.3%。序贯层的收益更大：证据累积速率正比于 $1/\sigma^2$，$(0.116/0.355)^2\approx0.107$，即达到同等置信所需的消息数减少约一个数量级。这是消融实验 E2 里一个独立且有力的子项。

（**订正说明**：此处早先误用 $z=3.29$（双侧 $\alpha=0.001$）算出"33.8% → 31.8%"，与结论十八、十九确立的单侧 $\alpha=0.01$ 口径不一致，且严重低估了协变量的收益。已按单侧口径重算；结论十八的 1.6%／98.6% 两个端点与 $z=2.326$ 精确吻合，可作为口径正确性的交叉验证。**全文 $\rho^*$ 一律用单侧。**）

**结论十（未预期，且是一个结构性发现）：M1 加性模型与 M2 饱和模型的残差完全相等（差值 0.000），原因是物料流路线图是森林。**实测 7 个分组的起点→终点二部图**全部为森林**（`vgr_1`：10 条路线、9 个起点、5 个终点、无环）。森林意味着每条路线都是桥。这一条同时带来一好一坏：好处是加性参数化（`vgr_1` 仅 15 个参数）在统计上等价于饱和模型，可以既省参数又不损失拟合；坏处是**留一路线交叉验证下加性模型几乎失效**——`vgr_1` 的 10 条路线中只有 2 条在移除后仍可打分，且残差 0.416，与不做条件化的 0.480 相差无几。移除一条桥就使其端点效应不可辨识，所以"加性模型能推广到未见路线"这个原本合理的期望在本产线拓扑下不成立。

**结论十一：`planned_operation_time` 正是未见路线的冷启动预测器，实测显著优于加性模型外推。**以 $\log\tau\approx\log(\text{plan})+\hat c$（$\hat c$ 为训练集上学得的全局偏置）预测未见路线，$\sigma_{\log\tau}=0.159$，而加性模型外推是 0.279；在 `vgr_1` 上更悬殊（0.172 对 0.416），且 0.172 已接近其已见路线的 0.149。这**从实验上确证了结论二给它安排的角色**：该字段作为绝对残差基准是错的（实际/计划比值跨一个数量级），但它编码了路线的相对难度，作为冷启动先验极为有效。因此 M4 的最终形态应是：**已见路线用加性 AFT 的后验，未见路线回落到以 $\log(\text{plan})+\hat c$ 为中心的先验**，两者由 NIG 层次先验统一。森林拓扑使层次收缩从"锦上添花"变成"不可或缺"——因为邻近路线之间没有可借的统计强度，先验必须来自计划值与设备型号两个上层。

**边界条件（须在论文中写明）：**两个分组上冷启动先验也失效——`mm_2 /mm/drill` 的 0.499 与 `sm_1 /sm/sort` 的 0.493。前者只有 2 条路线，留一后计划值无从区分；后者的方差本就不是路线造成的（$\sigma=0.287$ 但稳健 MAD 估计仅 0.157，说明是重尾离群点主导），应交由结论三的分层/混合建模处理而非条件化处理。另外满足 $n\ge15$ 且路线数 $\ge2$ 的分组只有 7 个，多数 (resource, operation) 只有单一路线，条件化对它们无意义也无损害。

**已固化为实现（2026-08）：**M4 已落地为 `slid/algorithm/timing.py`，含加性 AFT 拟合、NIG→Student-t 闭式后验预测、四分支 `dwell_pvalue`、$\rho^*$ 与理论检出率，以及支撑 T4–T6 的诊断函数。Student-t 的分布函数由正则化不完全 Beta（Lentz 连分式）自带实现，使在线检测器不必为一个分布函数拖进 SciPy；其正确性由 T0b 对照标准分位数表并检验 $\nu\to\infty$ 的正态极限。`py -m tools.timing_diag` 复现全部四个聚合尺度（0.355／0.116／0.279／0.159）、森林判定与"加性−饱和残差差 = 0.000000"。

**新增量化：分层与协变量各自贡献了多少。**此前只报告了两端，未拆分中间。按逐组 $\sigma_{\log\tau}$ 的中位（全部 31 个 $n\ge5$ 分组，与结论一同口径）：

| 口径 | 分组数 | 中位 $\sigma_{\log\tau}$ | 中位 $\rho^*$（单侧 $\alpha{=}0.01$） |
|---|---|---|---|
| 不分层、不条件化（起点） | 31 | 0.207 | 38.2% |
| + 按 `success` 分层 | 31 | 0.197 | 36.7% |
| + 路线协变量条件化（M4 实用口径） | 31 | 0.139 | 27.7% |

**分层单独只买到 0.5 个百分点的 $\rho^*$，真正的收益全在路线条件化。**这与结论三并不矛盾：分层的价值不在压缩中位，而在防止 `hbw_2 /hbw/unload` 那类"$\sigma_{\log}=1.798$ 而变异系数仅 0.294"的分组被单一对数正态严重高估——它是**防止个别组失真**，而非**全线提效**。消融实验 E2 应据此把两者列为独立子项并分别归因，不能合并成一句"预处理"。

**一处口径混用已订正。**骨架阶段的 `timing.py` docstring 曾把 `probe_bound.py` 的端点（路线条件化、$n\ge30$、20 个可建模分组，$\sigma$ 跨度 0.007–1.843）与 `probe_timing.py` 的中位（不条件化、31 个分组，0.207）拼在一句话里，还把 `sm_1 /sm/sort` 的 51.9% 误写成不条件化口径下的 48.7%。正文结论一、九、十八本身无误，问题只在实现侧的注释。现已按"引用 $\rho^*$ 必须连同口径给出"改写，并由 T6b 断言钉死两个中位不可混用、条件化必须是收紧方向。

#### 已实测：结构通道与 conformal 校准（`probe_structural.py` v1–v3）

这一组实测推翻了 M3 的原始形态，并给 M8 的无分布保证补上了两个必要条件。

**结论十二：按设备拆链的结构通道在本产线上是空的。**把每台设备的状态链按 case 切分后，2,109 条 (设备, case) 链中 **65.1% 长度为 1**（根本没有转移）、28.5% 长度为 2（只有一次转移），3,062 个活动只产出 953 次可用转移。更致命的是**全部结构 p 值取值唯一**（`uniq_p = 1`）——因为每个 (设备, case) 链内发生的转移几乎就是该行唯一见过的转移。该通道在此数据集上携带的信息量为零。根因是本产线的设备是**无状态的服务端点**，每个作业只被调用一到两次；原方法设想的"AGV 空闲/移动/装载"式设备内状态机在这个粒度上并不存在，它其实位于子日志的 109 个细粒度子活动里。

**结论十三：结构通道必须从设备级上移到 case 级工作流链。**以 case 内的活动序列建链：**21 个状态、2,780 次转移、282 个 case、140 个变体**，样本量与状态数之比健康，Dirichlet 后验预测不再被先验主导。这是 M3 唯一可行的形态。

**顺带再次确认结论六。**v1 曾报出"仅 48.6% 的观测转移落在 $\mathbf F$ 内"，这是链定义错误所致——当时用的是设备的**全局**时间线，相邻两次操作分属不同 case，而 $\mathbf F$ 来自工作流内可达性，跨 case 边界本就不适用。按 case 切分后 $\mathbf F$ 的符合率是 **100.0%（953/953）**，与 `derive_invariants_v4.py` 的 953 次检查零违反完全一致。**推论：在线检测器必须按 (设备, case) 维护链，不能按设备全局维护**；日志的 `case` 字段与命令 URL 的 `business_key` 参数使这在工程上可行。

**结论十四（重要，直接威胁 M8 的核心主张）：离散通道必须用随机化 p 值，否则 conformal 校准完全失效。**结构 p 值是高度原子化的（单状态设备恒为 1.0），经验分位数会正好落在某个原子上，导致该原子处的全部样本被判为异常。实测：设备级链上朴素 conformal 在名义 $\alpha=0.05$ 与 $0.01$ 下的经验 FPR **双双为 1.000**；改用随机化（平滑）p 值后变为 **0.051 与 0.010**，几乎精确。这一条必须写进方法：**$\mathbf F$ 违反、互锁指示、结构 p 值这些离散量参与 conformal 时一律取随机化形式**；时序通道因 p 值连续不受影响。这是"把玄学系数换成用户指定 $\alpha$"这一卖点能否兑现的前提，不能只在文字上声称。

**结论十五：conformal 有效性依赖校准集与部署数据的可交换性，新产品型号会破坏它。**case 级链上的四组对照：

| 切分方式 | 随机化 p 值 | 名义 $\alpha=0.05$ | 名义 $\alpha=0.01$ |
|---|---|---|---|
| 按字典序（等价于按工作流切分） | 否 | 0.073 | 0.028 |
| 按字典序 | 是 | 0.058 | 0.010 |
| 随机切分（可交换），20 次平均 | 否 | 0.063 | 0.013 |
| 随机切分，20 次平均 | 是 | **0.053** | **0.012** |

两处修正各自贡献且都必要。按工作流切分之所以超标，是因为 16 个工作流之间的**转移集合 Jaccard 重合度中位数仅 0.324**——不同产品型号的工艺路线差异很大，用旧型号校准的阈值对新型号不成立。论文中应把它写成明确的部署条件：**引入新产品型号时必须重新校准，或按型号分层校准**。这同时也是一个诚实的泛化边界，比笼统声称"无分布保证"更可信。

**结论十六（⚠️ 后半段已被结论二十三用实测推翻，保留原文以存档推理过程）：M3 上移到 case 级后，它与 M5 互锁通道都变成了"横向"证据，原先"纵向 vs 横向"的正交性论证不再成立。**两者仍携带不同信息（结构通道问"这个活动序列是否常见"，互锁通道问"物料流是否物理自洽"），但**统计上不再可假定独立**，而 Fisher 合并法 $-2\sum\log p_c\sim\chi^2_{2C}$ 恰恰依赖独立性，相关时会**反保守**（实际误报高于名义）。M6 需改为对相关性稳健的合成方式——候选是 Simes/Bonferroni（保守但稳），或调和平均 p 值，或直接对合成统计量本身做 conformal 校准（最省事且与 M8 一致）。这一项必须在实验中实测验证，不能沿用 Fisher 了事。

> **订正（结论二十三）**：上面这段的最后一句是对的——确实必须实测；但实测结果与预期相反。三通道近似独立，Fisher 前提成立且功效最高，而"直接对合成统计量做 conformal 校准"这个原本的首选方案恰恰是**唯一失效**的方案。详见结论二十三。

#### 已实测：影响–可检测性理论界的验证（`probe_bound.py`）

|---|---|---|---|---|
| 0.05 | 0.051 | 0.21 | 0.060 | 0.051 |
| 0.10 | 0.105 | 0.44 | 0.105 | 0.127 |
| 0.15 | 0.163 | 0.68 | 0.199 | 0.226 |
| 0.20 | 0.223 | 0.93 | 0.288 | 0.317 |
| 0.30 | 0.357 | 1.49 | 0.452 | 0.497 |
| 0.40 | 0.511 | 2.14 | 0.712 | 0.701 |
| 0.50 | 0.693 | 2.90 | 0.874 | 0.851 |

全区间平均绝对偏差约 0.03。这意味着论文可以给出一条**可预测的**攻击者收益上界，而不只是一条经验曲线——审稿人问"你的界准不准"时有直接答案。

**结论十八：$\rho^*$ 高度异质，必须按组陈述，且产线整体可检测性由最弱环节决定。**20 个分组的 $\rho^*(\alpha{=}0.01,\text{单侧})$ 从 **1.6%**（`dm_2 /dm/lower`，$\sigma=0.007$）到 **98.6%**（`hw_1 /hw/human_review`，$\sigma=1.843$）。其中 13 组 $\rho^*\le40\%$，剔除人工工位后最差为 `sm_1 /sm/sort` 的 51.9%。这给出一个干净的表述："检测能力等于最易变工序的检测能力"，并**从数据上支持把人在回路工序排除出时序通道**（结论三已提出，此处给出量化理由：它的 $\rho^*$ 接近 100%，即攻击者可任意抢跑而不被时序通道发现，只能靠互锁通道兜住）。

**结论十九：时序通道应使用单侧检验，不是双侧。**抢跑是有方向的备择假设，单侧在同一 $\alpha$ 下功效显著更高——$\rho=0.5$ 时实测 DR 为 **0.874（单侧）对 0.338（双侧）**，$\rho=0.3$ 时 0.452 对 0.204。M4 中"状态跳变取双侧 p 值（太快太慢都算）"这条要改：**抢跑走左侧检验，滞留/抑制（A6）已由右删失生存函数分支单独覆盖**，两者本就是不同机制，合并成双侧只会白白损失一半功效。需说明的是双侧的劣势有一部分来自阈值估计噪声（见结论二十），但即使排除该因素，方向性备择下单侧仍占优。**（订正：0.874 对 0.338 是单个折划分种子的结果；30 种子下双侧为 0.722 ± 0.165、范围 [0.326, 0.880]，平均优势仅 +0.150，$\alpha{=}0.05$ 下更只有 +0.018。结论不变但理由须改为"单侧阈值稳定"，详见本节末"已固化为实现"的订正一。）**

**结论二十：conformal 的价值被量化，但校准集规模是硬约束。**若改用高斯参数阈值，实测 FPR 为 **0.0196（双侧）与 0.0140（单侧）**，而名义值是 0.01——参数假设会让误报接近翻倍，这是 M8 存在必要性的直接证据。但同时暴露一个限制：双侧 conformal 阈值算出 $\vert z\vert>5.626$，而测试集残差的 $q_{99}$ 实际只有 2.64（上尾）与 2.39（下尾），说明**在 $n_{\text{cal}}=701$、$\alpha=0.01$ 下分位数估计极不稳定**（超越点仅约 7 个）。推论：**本数据集能可信支撑的最低 $\alpha$ 约为 $10^{-2}$，$\alpha=10^{-3}$ 需要约万条校准样本而全日志仅 3,033 条**。论文报告 conformal 结果时必须给出校准集规模并限制 $\alpha$ 范围，否则是不诚实的；单条消息够不到的误报预算，应当由序贯检验的 ARL$_0$ 去承担。

**结论二十一：序贯检验是把弱信号变成可用检测的关键，且延迟可接受。**CUSUM（设计位移 $1\sigma$，阈值 $h=7.81$ 按 ARL$_0\ge500$ 在正常数据上标定）：

$\rho=0.15$ 时单消息只有 19.9%，CUSUM 达 86.8% 且中位仅需 10 条消息。这正是"以消息数计的检测延迟"这一指标要展示的效果，也是相对逐消息阈值类基线（含原方法）的核心优势。检出率在 0.962 处饱和，未检出的部分来自 $\sigma$ 极大的分组（主要是人工工位），与结论十八一致。

**已固化为实现（2026-08），并订正了结论十九的量级。**M8（`conformal.py`）、M3（`structural.py`）、M7（`sequential.py`）已落地，`tools/calib_diag.py` 与 `tools/bound_curve.py` 把上述实测重跑为**多种子对照**。重跑推翻了一处、限定了一处、并新增两处否定性结果。

**订正一（重要）：结论十九的"0.874 对 0.338"是单个折划分种子的结果，不能作为单侧优势的量级。**原实验只跑了 `seed=7`。跑 30 个种子后：

**订正二（否定性结果）：NIG → Student-t 后验预测并不能修好它。**原本预期后验预测把 $\sigma$ 的估计误差折进更厚的尾部即可稳住阈值，实测**无效**（双侧 DR 0.729 ± 0.152，对插值 $\sigma$ 的 0.722 ± 0.165）。原因是后验是从**同一批**残差算出的，$\sigma$ 被低估时它一并继承；且组内 $n$ 达数十条时自由度已大到接近高斯。**NIG 层的价值在冷启动小样本，不在修复混合校准的异质性**——这两件事此前被混为一谈。

**订正三（否定性结果）：Mondrian 逐组校准同样不是解药，且与规则 3 正面冲突。**$\alpha{=}0.01$ 时 **95.0%** 的分组因 $n_{\text{cal}}+1<1/\alpha$ 而不可达、只能回落到混合校准，双侧 DR 仅从 0.722 ± 0.165 改善到 0.758 ± 0.109；$\alpha{=}0.05$ 时不可达比例降到 40.0%，但经验 FPR **反而超出名义值**（单侧 0.062、双侧 0.069，名义 0.05），因为回落组用的混合阈值对它们并不合适。**结论：在本数据集规模下，条件覆盖率与有限样本可达性无法同时满足，论文必须把这条张力写成显式的适用边界，而不是声称 Mondrian 解决了异质性。**

**限定一：结论十四"必须随机化 p 值"的适用范围要收窄。**四臂对照（20 种子，均值 ± 标准差）：

#### 已实测：原方法不可检测集合的构造性枚举（`slid/tools/mbdf_undetectable.py`）

这是 T-a 从"两行代数 + 一组具体系数"变成"在真实数据上点名哪些转移永远抓不到"的一步，也是实验 E3 的核心产出。

**判据录自原文**（`paper02_old/Latex/paper02.tex` 的 Eq.(prediction)、Eq.(threshold)、Algorithm 2）：预测 $\hat{\mathbf s}=\mathbf P^\top\mathbf e_i$ 是**概率分布**，观测 $\mathbf e_j$ 是 one-hot，$\delta=\|\mathbf e_j-\hat{\mathbf s}\|_2$，阈值 $\varepsilon_i=\gamma/h(\hat c)$（论文惊异版，$h=-\ln\mathcal P_{\mathrm{BN}}$）或 $\varepsilon_i=k\,\mathcal P_{\mathrm{BN}}(\hat c)$（专利线性版），$\hat c=\arg\max\hat{\mathbf s}$ 是**预测主状态**。

**测试设置对原方法是有利的**（须在论文中写明，否则会被质疑构造不公）：在 case 级链上评测，21 个状态、2,780 次转移、20 个有出边的前驱状态。设备级链才是原方法设想的粒度，但结论十二已证明它在本数据集上几乎不产生转移，case 级给了原方法最多的可用信息。

**T-a.1 数值级。** 专利线性版在 $k=10.25$ 下 $\varepsilon$ 取值达 $[0.1105,\,2.9458]$，远超 $\delta$ 的理论上界 $\sqrt2=1.4142$，**20 个前驱状态中有 10 个整行全盲**。论文惊异版 $\gamma=0.73$ 下 $\varepsilon\in[0.1611,\,0.5855]$，无整行全盲。**这说明惊异加权确实修掉了线性版的一个真实缺陷**，论文中应如实承认——但它修不掉下面两条。

### 已实测：融合层的三个问题，两个答案与预期相反

（工具：`slid/tools/fusion_diag.py`；断言：T17–T21；10 个划分种子，Trier gold standard）

此前 M6 的全部设计都建立在**推理**而非测量上，这一轮把三个问题量化了，其中两个的答案与原设计相反。

**结论二十三：三通道近似独立，"不可用 Fisher"的前提不成立，且 Fisher 实际是最优选择。** 三通道证据 $-\log p$ 的两两 Pearson 相关实测为：时序–结构 $-0.030\pm0.055$、时序–互锁 $-0.008\pm0.038$、结构–互锁 $+0.056\pm0.035$。原论证的漏洞在于把"同属横向证据"（信息**种类**相近）等同于"统计相关"（取值相关）——结构通道问的是工序序列在训练分布下有多罕见，互锁通道问的是物料令牌是否配平，两者在良性数据上恰好几乎不共变。

更进一步，在通道各自校准之后，**Fisher 在多通道攻击下的功效（0.413）是 Simes（0.187）与最小 p 值（0.176）的两倍以上**，误报率同样合规（$\alpha=0.01$ 下实测 0.013）。机理很直白：三个通道各带 $p=0.05$ 的中等证据时，Fisher 累积成 $0.006$ 而触发，Simes 最好也只能还原到单通道的 $0.05$，最小 p 值还要再付 3 倍。**min 型统计量只看最极端的那一个通道，累积型统计量才能把分散的弱证据合起来**——而调度层攻击恰恰倾向于在多个通道上各留一点痕迹。

**注意这是一个必须逐现场复测的前提，不是可移植的结论。** `fusion.dependence()` 给出可检查量，相关度超过 0.15 就应退回 Simes。论文里要把它写成"可检验的部署条件"，与 M5 软层升硬层的条件并列。

**结论二十四：必须先逐通道校准再合成；原本首选的"对合成统计量整体校准"是唯一失效的方案。** 三种架构的经验 FPR（名义 0.05 / 0.01）：

| 合成 | 先合成后校准 | 先逐通道校准（名义） | 逐通道校准+合成后再校准 |
|---|---|---|---|
| Simes | 0.074 / **0.074** | 0.048 / 0.010 | 0.049 / 0.013 |
| 最小 p 值 | 0.074 / **0.074** | 0.047 / 0.010 | 0.049 / 0.013 |
| 调和均值 | 0.047 / 0.015 | 0.056 / 0.011 | 0.048 / 0.013 |
| Fisher | 0.047 / 0.014 | 0.052 / 0.013 | 0.052 / 0.012 |

min 型统计量在"先合成后校准"下彻底失效，且**两个 $\alpha$ 给出同一个 0.074**——这是分布有原子的判定性特征。成因已定位：**8.1% ± 2.3% 的良性活动其原始时序 p 值直接触到数值下界**，合成后在底部堆成一个原子，校准分位数落进原子内部就再也分不开。而这 8.1% 里 **89.8% 是训练折已见过该路线的真·模型失配**，只有 10.2% 是冷启动外推——即参数化 Student-t 尾部在自己的训练分布上就已经不可信，不是外推的锅。这条同时是 M8 存在必要性迄今最强的证据：**原始参数化 p 值在尾部错了近两个数量级，而尾部正是检测唯一关心的地方。**

第三层校准（"再校准一次"）没有额外收益（0.013 对 0.010），却要多吃一份校准集，与结论二十的规模硬约束直接冲突，故舍弃。

**结论二十五：合成不是免费的，单通道攻击下它把功效稀释约 2.5 倍，因此必须与逐通道判决并行。** $\alpha=0.01$、误报率对齐后：

| 攻击 | 仅时序通道 | Fisher | Simes | 最小 p 值 | 调和均值 |
|---|---|---|---|---|---|
| A4 抢跑（只碰时序） | **0.110** | 0.060 | 0.042 | 0.042 | 0.044 |
| A4 + 伪造工序位置（多通道） | 0.108 | **0.413** | 0.187 | 0.176 | 0.220 |

这张表应当直接进论文，因为它同时给出了三通道架构的**理由**和**代价**，而单看任何一行都会得出错误结论。合成的价值是**覆盖面**：多通道攻击下 Fisher 把 0.108 抬到 0.413；代价是**单通道攻击下的稀释**：两个无信息通道摊薄了证据，min 型还要额外付 $k$ 倍 $\alpha$。

推论直接改架构：**在线检测器必须同时跑"合成"与"逐通道"两路，$\alpha$ 预算在两者间划分**，只报合成结果会在单通道攻击上白白损失一半以上功效。这也意味着实验章的每个攻击类型都要同时报告两路结果，消融表里"去掉某通道"的行必须区分"从合成中去掉"与"连独立判决一起去掉"——前者有时反而会**提高**该类攻击的检出率，这个反直觉现象若不预先说明会被审稿人当成实现错误。

### 已实测：在线回放——随机折验证出来的保证，在时间序部署下还剩多少

（工具：`slid/tools/online_diag.py`；断言：T22–T24；5 个种子，Trier gold standard）

在此之前**全部结论都建立在随机折划分上**，而 M8 规则 3 恰恰要求随机划分来保交换性——可现场部署只能用过去拟合、对未来判定。这两件事直接冲突，是本项目唯一一个**效度**问题而非性能问题，只能实测。

**结论二十六：时间序划分会让误报控制退化，且退化是通道特异的——时序通道幸存，结构通道不幸存。** 逐通道 conformal 的经验 FPR（名义 0.05 / 0.01）：

| 通道 | 随机折 | 时间序 |
|---|---|---|
| 时序 | 0.049 / 0.010 | 0.056 / 0.007 |
| 结构 | 0.044 / 0.007 | 0.064 / **0.015** |
| 互锁 | 0.048 / 0.010 | 0.056 / 0.011 |
| Fisher 合成 | 0.048 / 0.011 | 0.068 / **0.018** |

**报告口径提醒：`main.py` 打印的那个 FPR 与本表不同量纲，别拿来对照。** 它是**并行各路的并集**（硬层、三通道、合成、序贯，任一触发即计），故必然高于逐通道值——时间序下实测 0.0391（名义 0.01），而同一配置的逐通道值是时序 0.026 / 结构 0.014 / 互锁 0.012。论文里凡引用经验 FPR 必须声明是逐通道还是并集，否则并集那个数看起来就像校准坏了。

合成通道在 $\alpha=0.01$ 下从 0.011 涨到 0.018（1.8 倍名义），主因是结构通道从 0.007 涨到 0.015（2.1 倍）。**时序通道反而略偏保守（0.007）**，这与物理规律不随时间漂移、而工序序列会漂移的直觉一致——Trier 主流程变体率 77%，新产品变体在日志后段才出现，正是 Stertz 在同一数据集上记录的概念漂移。

三个推论：（1）论文报告 conformal 保证时**必须同时给出时间序口径的数字**，只报随机折是不诚实的，因为部署时没有随机折这个选项；（2）退化是温和的（1.8 倍而非数量级），说明方法可用，但 $\alpha$ 的实际含义要按时间序口径解释；（3）**结构通道需要周期性重校准，时序通道不需要**——这是一条可直接写进部署建议的、由数据得出的运维规则，而不是泛泛的"建议定期更新模型"。

**结论二十七（E8）：逐消息处理时延中位 81 μs，单核等效吞吐约 12,300 消息/秒。** p95 为 116 μs，p99 为 159 μs。（早先记录的 91–107 μs / 9,300–11,000 消息每秒是时序通道走 Student-t CDF 时的数字；结论二十九把不符合度分数换成标准化残差后省掉了每消息一次不完全贝塔函数求值，时延随之下降。两组数都成立，报告时取现行实现的一组。）$O(1)$ 由复杂度论证给出——四次查表 + 两次对数 + 常数次不变量检查，与状态数和设备数均无关——实测只提供常数因子。**未做硬件平台实测**，原计划的"树莓派/工业边缘控制器"已从指标表中撤回。以 Trier 全日志 3,062 个活动跨越的时间尺度衡量，百微秒级的单消息开销距离产线消息率有三个数量级余量，"边缘可部署"这个论断由复杂度 + 常数因子共同支撑，不需要伪造硬件平台。

**结论二十八：M9 的门控更新挡住了基线投毒，无门控时攻击者能把 26.4% 的抢跑喂成新常态。** 攻击者不求单条不被发现，而求把自己的行为喂进基线——这正是原专利"无条件 EWMA 更新"的结构性弱点。在 `vgr_1 / pick_up_and_transport`（样本最多的可建模分组）上持续注入 200 条 $\rho=0.30$ 的抢跑：

| 配置 | 位置参数漂移 | 等效被吸收的抢跑量 | 更新生效 / 被拦 |
|---|---|---|---|
| 门控（本文） | $-0.0137$ | **+1.4%** | 4 / 157 |
| 无门控（原专利） | $-0.3071$ | **+26.4%** | 200 / 0 |

无门控时基线被拖走近 19 倍，攻击者白拿 26.4% 的调度提前量且此后同幅度抢跑不再异常。这条给了论文一个干净的、与既有专利正面对照的机制性差异，且**不依赖任何统计功效上的优势**——它是架构差异，不是调参差异。

### 已实测：覆盖矩阵，以及一个差点毁掉核心主张的实现缺陷

（工具：`slid/tools/coverage_matrix.py`；断言：T25–T27）

**结论二十九：时序 p 值的数值下界会摧毁核心攻击的可检测性，不符合度分数必须用标准化残差 $z$ 而非 p 值。** 首次实测覆盖矩阵时，A3 抢跑（$\rho=0.30$）的时序检出率只有 **0.03**（误报 0.01）——而结论二十一记录同一 $\rho$ 下单消息 DR 应为 0.452。病因是 `dwell_pvalue` 把 p 值裁剪在 $10^{-12}$：8.1% 的良性活动本就落在这个下界上（结论二十四），于是尾部**完全没有分辨率**，conformal 校准无法把"30% 抢跑"与"良性模型失配"区分开，两者被压成同一个值。把不符合度分数换成 $z$（连续、无界、保留尾部次序）后，A3 时序检出率从 0.03 回到 **0.43**，与结论二十一吻合；A5 从 0.06 回到 0.48。

这条的普遍教训值得写进论文：**conformal 的有效性依赖不符合度分数在尾部保有分辨率，而 p 值天然在尾部饱和。**用 p 值作为 conformal 的输入分数是很自然的写法，也正因此这个缺陷极隐蔽——它不报错、不影响误报率（仍然合规）、只是安静地把检出率削掉一个数量级。凡"conformal + 参数化 p 值"的组合都该检查这一点。

**结论三十：二值通道的单消息功效有一个与不变量质量无关的硬天花板 $\min(1,\alpha/q)$。** 互锁软层是二值的，良性违反率 $q$；随机化 p 值在违反时均匀落在 $[0,q]$，故 $P(p\le\alpha)=\alpha/q$。这意味着**即使不变量完美、每次攻击都触发违反**，$\alpha<q$ 时单消息检出率也不可能超过 $\alpha/q$。训练折实测 $q=0.0054$，$\alpha=0.01$ 时天花板不生效；但 $\alpha=10^{-3}$ 时上界只剩 **0.185**，而 $q$ 随训练折波动（诊断口径下测得 0.017，对应 $\alpha=0.01$ 的上界 0.588）。

两条推论：（1）**论文声称的 $\alpha$ 范围必须与 $q$ 一起给**，否则"互锁通道检出率低"会被误读成不变量设计得差；（2）这给"软层升硬层"的部署条件（RFID/NFC 工件身份使 $q\to0$）**装上了定量理由**——不再是"有身份标识更好"，而是"没有身份标识时互锁通道的功效被 $\alpha/q$ 封顶"。

**结论三十一：注入器的强度直接决定头条主张成不成立，A4 必须按"知模型"实现。** 早先的 A4 注入器复制当前操作，制造出异常重复，结构通道立刻拿到 0.19，"只有互锁能抓 A4"当场作废。换成攻击者按转移模型挑概率最大的下一步、用真正做过该操作的设备、取该分组的中位时长之后，结构降到 0.02、时序降到 0.00，互锁的 0.12 成为唯一提升。**这说明该主张不是方法的性质，而是方法与攻击者强度的联合性质**，论文必须写明攻击者知识等级，否则数字不可复现，也经不起审稿人换一个弱注入器来质疑。同理，A7 不实现即不报告。

**结论三十二：$\mathbf F$ 必须分一元与二元两部分，一元部分覆盖 100% 的消息而二元只有 31%。** 原实现只做二元的转移可达性 $\mathbf F(d, o_{\text{from}}, o_{\text{to}})$，它需要同一 case 内同设备有前驱，实测覆盖率 953/3062 = **31.1%**——这就是 A2 硬层只有 0.29 的全部原因。但 BPMN 还蕴含一个**一元**约束："这台设备到底允不允许做这个操作"，它不需要任何前驱，**覆盖率 100%**（15 台设备全部有能力声明）。补上之后 A2 硬层 0.29 → **0.98**、序贯@10 → 1.00，且良性违反 **0/3062**。

一元能力集必须按**设备类**（去掉实例后缀，`sm_2 → sm`）归并而非按实例：16 个 BPMN 只实例化了一台分选机，按实例归并会把 `sm_2` 的 44 次 `/sm/sort` 误判为违反（1.44%，恰是副产品一记录的同一处模型不完备），按类归并后归零。9 个设备类，每类 1–4 个操作。这与已有的分选机位置别名类是同一条规则，物理上也成立——同型设备当然承担同样的操作。代价是失去"`sm_2` 做了只有 `sm_1` 该做的事"这种区分，但参考模型本就没有这个信息。

**结论三十三（负面结果）：把结构通道的状态细化为 (设备, 操作) 在三项指标上全部变差，这条看似显然的改进不能做。** 面对"结构通道设备盲"，最自然的修法是细化状态。实测（`tools/struct_diag.py`，5 个种子，时间序划分）：

| 粒度 | 状态 | 转移 | 中位支撑 | FPR@0.05 | FPR@0.01 | A2 结构 DR | A4 结构 DR |
|---|---|---|---|---|---|---|---|
| 操作名（现行） | 21 | 48 | 22.0 | 0.056 | **0.017** | **0.350** | 0.024 |
| (设备, 操作) | 31 | 60 | 15.5 | 0.085 | **0.050** | **0.000** | 0.022 |

三项全负：（1）**校准失效**，$\alpha{=}0.01$ 下 FPR 由 0.017 升到 0.050，是名义值的 5 倍——粒度变细后测试折里出现训练折未见的转移变多，时间序的非交换性咬得更狠；（2）**A2 检出从 0.350 归零**，机理很有意思：粗粒度下被注入的操作仍在词表内（别的设备做过），于是罕见转移被判为异常；细粒度下 `设备|操作` 组合从未出现过，成了**词表外状态**，`struct_pvalue` 于是**弃权**而非告警。也就是说细化状态把"可检测的异常"变成了"未知因而放过"；（3）A4 无收益。

推论有两层。方法层：**"错误的设备做了正确的操作"根本不属于统计通道，它属于硬约束**——未见组合应当由参考模型判定为不允许（一元 $\mathbf F$），而不是靠统计通道的低概率。让统计通道给词表外状态打小 p 值是不可行的，因为时间序下良性数据本就会产生新组合，那会把误报做上去（0.050 已经是证据）。方法论层：**弃权语义会把改进悄悄吞掉**——细化状态本应增强检测，实际因为弃权而削弱，而弃权在指标上表现为"检出率低"，极易误诊为"模型不够好"。

这个实验还第二次踩到结论三十一的坑：细粒度臂的 A4 一度测出 0.418，查明是 `_likeliest_next` 拿操作名去二元组状态表里查、查不到便退回复制当前操作，**攻击者被悄悄降级成了朴素版本**；修好后是 0.022。注入器只要与被测模型有任何口径错配，就会自动变弱并虚报方法的功效。

### 已实测：E1 同一误报预算下的基线对比

（工具：`slid/tools/baseline_diag.py`；已实现 B1 mbdf / B2 markov / B3 butla / B4 tabor / B5 hsmm，B6–B7 未实现即不报告；断言：T30–T33）

**评测口径是这一节的前提，写论文时必须原样交代，否则数字全部无效。五条，都是被测量打出来的：**

1. **阈值定在同一批 case 的未注入版本上**，使各方法经验误报都为 $\alpha$。各方法原始分数量纲天差地别（$\ell_2$ 距离、负对数似然、$z$ 值），在不同误报率下比检出率毫无意义。
2. **绝不能用受攻击流内部的良性消息定阈值。** A2 这类原地改写会让后继良性消息拿一个伪造的前驱去比对，产生**攻击引起的级联触发**；把它算成误报会（a）冤枉方法，（b）在级联率超过 $\alpha$ 时使阈值退化为 $+\infty$、检出率假性归零——本方法 A2 的 DR 确实一度被这样测成 0.00。
3. **序贯一臂必须给基线也套上同一套 CUSUM。** 否则"本方法序贯 vs 基线逐消息"会被质疑不公平，也无法把增益**归因**到通道设计而不是归因到累积机制。B3/B7 逐观测判决确实是它们的设计属性，但 B2/B5 这类似然型基线完全可以外挂 CUSUM。
4. **每个方法都并行跑自己的子检测器，$\alpha$ 预算在子检测器间均分，任一触发即告警。** 不能把子检测器压成一条 min-p 流：那样每条消息的分数都被其它子检测器的噪声污染，弱信号在累积时被稀释（结论二十五）。实测把本方法四路压成 min-p 后 A4 的序贯检出率从 0.23 掉到 0.17、反被似然型基线超过——那是口径造成的假象。基线同样有 2–3 个子检测器，并行是双方共用的规则。
5. **序贯阈值 $h$ 的目标 ARL$_0$ 只能取 $1/\alpha$，且告警后必须复位。** 良性流只有 508 条消息，目标 ARL$_0$ 一旦超过流长，零误报会让 ARL$_0$ 记作无穷、二分搜索返回区间下界，$h$ 被定得过低。而 `CUSUM.update` 自身不复位，不复位则 $S$ 越过 $h$ 后永久停在上方、此后每条消息都告警。两个 bug 叠加时基线的序贯误报虚高到名义值的 **22 倍**、检出率一并虚高（TABOR 曾拿到 0.39、HSMM 在 A4 上拿到 0.66）。**报告序贯结果时必须把实测序贯误报一起给出**，否则这类错误无法被读者发现。
6. **序贯检出率必须减去偶然地板 $1-(1-\text{FPR})^{\text{budget}+1}$**，见结论三十八。延迟预算口径下"什么都不检测"也能拿到一个可观的分数。
7. **逐消息一行在本数据集规模下不可作主结果**，见结论三十九。
8. **本方法与基线同用 `train` 折拟合，$\alpha$ 预算只给天花板判据选中的三路**（硬层 + 时序 + 结构，见结论四十九）。此前我方吃 `train+calib` 是自己给自己让利，且会把 calib 变成样本内、使天花板判据读到训练折的 $q$（0.005）而非部署折的 $q$（0.032），互锁就剔不掉了。
9. **交给判决器的必须是原始不符合度分数，不能先过一层冻结的 conformal**，见结论五十一。

**校准漂移**（按良性校准折定阈值后在测试折的实测误报，名义 0.01）：mbdf 0.000、markov 0.014（1.4×）、butla 0.037（3.7×）、tabor 0.037（3.7×）、hsmm 0.010（1.0×）。基线普遍没有无分布保证、阈值靠人工容差，这一列本身就是 M8 的对照结果——B3 原文也自陈误报问题未解决。**注意 B5 HSMM 的漂移是 1.0×，与本方法的 conformal 保证相当**，故 M8 的卖点不能写成"只有我们控得住误报"，只能写成"我们的控制不依赖模型假设成立"。

**结论三十四：B1（原方法）在全部六个攻击族上的检出率减去偶然地板后恒等于零（均值 0.01），这是 T-a 不可能性结果的直接实证。** 原因已在 T-a 中证明：$\delta = \sqrt{\lVert\hat p\rVert^2 - 2\hat p_i + 1}$ 与阈值 $\gamma(1-\hat p_i)$ **都只依赖 $\hat p_i$**，判决因此退化成对预测概率的单阈值，凡预测概率足够高的观测标签一律不可标记，与它是否真实无关。这不是把基线调差了，而是该方法的结构性质——论文里应当把 B1 当作**不可能性结果的实证**来用，而不是当作一个弱对手。

**但陈述必须限定为"逐消息、扣除偶然地板后"，否则会被一个数字直接推翻。** 未减地板时 B1 在 $\alpha=0.05$ 下的序贯检出率是 **0.38**（六族 0.31–0.50），看上去"原方法也有三成检出率"。查明它自己的序贯误报是 0.035、对应地板 $1-(1-0.035)^{11}=0.326$——六个数全部贴着地板，实际什么都没检出。**这恰恰是 T-a 的预期表现，但若照抄未减地板的数字，论文会自己给不可能性结果提供反例。**唯一略微超出地板的是 A2（+0.08）与 A6（+0.07），而 A2 的超出正是 T-a.3 所预言的：零误报下可标记集恰为 $\{j: p_j = 0\}$，而 A2 注入的操作多半就落在这个集合里。**理论预测了它能抓什么、也预测了它抓不到什么，两头都对上了**，这比单纯的"基线得零分"有力得多。

**结论三十五：B4 TABOR 与 B3 BUTLA 在本数据集上逐格相同，原因是站内贝叶斯网络提供不了独立信息；由此得到一个更强的结论——参考模型的信息不可能从同一份日志里学出来。** 追查过程：TABOR 的站内 BN 在 90 个 (设备, 操作, 变量) 组合中有 82 个取值唯一，本身信息量就低；更要紧的是它给"该设备从未做过此操作"打出的极端负对数似然（27.6）**在良性测试折里已经出现**——测试折有 **3.9%（20/508）** 的良性活动是训练折未见过的 (设备, 操作) 组合（全部是 `hbw_1 //hbw/unload`）。于是这个极端值不再稀奇，$\alpha=0.01$ 下完全不可用。

而**参考模型拒绝了这 20 条中的 0 条**——它知道 `hbw` 本来就承担卸料。这就是本文用 BPMN 的根本理由，可以写成一句话：**在日志里"没见过"与"不允许"无法区分，而在时间序下"没见过"会以 3.9% 的比例良性发生；参考模型是唯一能把两者分开的信息来源。**这条同时解释了三件事：为什么一元 $\mathbf F$ 必须来自 BPMN 而不能从数据估（结论三十二）、为什么细化结构通道状态会退化成词表外弃权（结论三十三）、以及为什么 B4 打不过 B3。

**结论三十六：B5 HSMM 已实现且是真隐半马尔可夫，序贯口径下平均 0.20，本方法 0.51。** 实现用了一个标准等价：**最大时长为 $D$ 的显式时长 HSMM 等价于在扩展状态空间 (隐状态 $z$, 剩余步数 $r$) 上的 HMM**，其转移矩阵由 $(A, p)$ 结构化参数化。于是可跑标准带缩放 Baum-Welch，M 步再把扩展转移计数映射回 $A$ 与 $p$：$A[z,z'] \propto \sum_d \xi((z,1) \to (z',d))$，$p[z][d] \propto \sum_{z_0} \xi((z_0,1) \to (z,d)) + \text{初始质量}$。观测是二元的（操作符号的类别分布 + 对数时长的高斯），故它同时用结构与时长，是与本方法 M3+M4 对位的基线。隐状态数由**留出集似然**在 $\{2,3,4,6\}$ 中选出 $K=6$，六个隐状态学到的对数时长均值 1.88–3.66、$\sigma$ 0.21–1.81，时长分布非退化。**EM 的对数似然严格单调递增并收敛**（$-8093 \to -4716$，12 次迭代），这是实现正确的关键证据——有 bug 的 Baum-Welch 典型表现就是似然非单调，这一项已固化为断言 T32。

**结论三十七（必须写进论文的负面结果）：B2 纯一阶马尔可夫似然 + CUSUM 在 A4 与 A6 上不输甚至打赢本方法（减地板后 0.23 对 0.19、0.28 对 0.12），原因是预算划分而非通道设计。** B2 只有一个子检测器，独享全部 $\alpha$ 预算；本方法四路（硬层 + 三通道）均分，每路只有 $\alpha/4$，白吃 4 倍的 Bonferroni 代价。A4 与 A6 恰好都是**改变 case 内事件数目**的攻击（A4 插入一条伪造上报、A6 删除一条），而一阶马尔可夫似然对事件数目变化天然敏感——插入或删除一个事件就改写两个转移，CUSUM 把这点证据稳定地累起来。已核查 A4 的插入语义是**正确**的（状态模仿攻击的要义就是多发一条"我到了"骗调度器提前派工），所以这不是注入器假象。

三条推论：（1）**论文不能声称全面优于所有基线**，只能声称在 A1/A2/A3/A5 上领先、总均值领先（0.48 对 0.29），并如实报告 A4 基本打平、A6 落后；（2）这给"$\alpha$ 预算怎么分"提供了**实测依据**——均分明显不是最优，但加权必须在校准折上选而不能在测试折上调，否则就是调参作弊；（3）B2 这个"稻草人"其实相当强，正说明前文换掉稻草人的决定是对的，也说明**方法的复杂度需要用它买到的东西来辩护**：本方法比 B2 多出的三个通道，在 A5（0.90 对 0.00）、A3（0.17 对 −0.01）、A2（0.96 对 0.76）上买到了东西，在 A6 上买到的是负数。

**结论三十八（口径缺陷，会让整张序贯表虚高一个地板）：延迟预算口径下的检出率有一个纯偶然的地板 $1-(1-\text{FPR})^{\text{budget}+1}$，必须减掉或至少并排报告。** 判定"第 $i$ 条被篡改消息在 $i..i{+}10$ 内出现任一告警即算检出"时，窗口里有 11 个机会撞上一次误报。$\alpha=0.05$ 时地板高达 **0.43**，$\alpha=0.01$ 时 0.10。这个缺陷极隐蔽：它不违反任何误报约束、不报错，只是把所有方法一律抬高——**而抬高对弱基线是相对更大的恩惠**（B1 从 0.01 被抬到 0.08、$\alpha=0.05$ 下抬到 0.38），于是既虚增了基线、又压缩了方法间的相对差距。减地板后本方法对 B2 的领先由 1.3 倍（0.51/0.38）变为 1.7 倍（0.48/0.29），对 B5 由 2.6 倍变为 4.4 倍。**凡"延迟预算内任一告警即算检出"的报告口径都该检查这一项**，它在序贯检测文献里是标准做法但常被省略。已固化为断言 T34。

**结论三十九（口径缺陷，且系统性歧视多通道方法）：逐消息一行受良性参照流长度的分辨率限制，在本数据集规模下不可作主结果。** 良性参照流 508 条，经验 p 值下界 $1/509 = 0.00196$；四路均分后每路要 $\alpha/4 = 0.0025$，阈值以下**只容得下 1 个良性秩位**——攻击消息必须超过全部 508 条良性消息才算检出，实际执行的是"取良性最大值作阈值"而非 $\alpha=0.01$。把每路 $\alpha$ 改为不分（仅用于量化失真，不作报告口径）：

| 攻击 | 每路 $\alpha/4$ | 每路 $\alpha$ | 倍数 |
|---|---|---|---|
| A3 抢跑 | 0.027 | 0.266 | **9.9×** |
| A5 漂移 | 0.034 | 0.242 | **7.2×** |
| A4 模仿 | 0.040 | 0.064 | 1.6× |
| A1 重放 | 0.238 | 0.359 | 1.5× |
| A2 不可行 | 0.977 | 0.980 | 1.0× |

失真是**攻击特异**的：被削掉一个数量级的恰好是 A3 与 A5，即时序通道那两个有理论支撑的核心攻击；而 A2（硬层、确定性、分数二值）毫发无损。这有两个后果：（1）逐消息表的**攻击族间相对大小完全不可信**，会让读者以为时序通道很弱而硬层很强；（2）**系统性歧视多通道方法**——单检测器基线独享 $\alpha$，我方四路各拿 $\alpha/4$，恰好落在分辨极限上。这是结论二十"$n_{\text{cal}}=701$ 时 $\alpha=10^{-2}$ 已是可信下限"的同一条约束在新位置上再次咬人，且给出一条可操作的规则：**并行子检测器的路数受 $m \le \alpha\,(n_b+1)$ 约束**，本数据集 $\alpha=0.01$ 时 $m \le 5$，四路已在边缘。论文若要报逐消息结果，必须把 $\alpha$ 放到 0.05 或用多折汇合扩大良性参照流。已固化为断言 T35。

**尚未实现，故不报告：** B6 lstm_ae、B7 flow。两者是算力/可解释性代价说明与历史对照，不是主基线，可缺。

### 已实测：α 预算怎么分——校准折选不出来，只用良性数据的判据能选出来

（工具：`slid/tools/alloc.py`；`baselines.judge` 已支持非均分 `weights`；断言 T37）

结论三十七留下的问题是"均分明显不是最优，但加权必须在校准折上选而不能在测试折上调"。把日志切成 train（拟合）/ calib（选配额）/ test（评测）三折，候选取"哪些路给预算"的 46 个子集（已剔除每路配额低于 $1/(n{+}1)$ 的，T35），实测结果与预期完全相反。

**结论四十八（否定性结果）：在邻近的时间折上按攻击表现选配额，选出来的恰好是测试折上最差的那个——两折的排序近乎反相关。**

| 均分五路（现行，calib 第 1） | **0.608** | **0.370**（最差） | −0.238 |

**结论四十九：改用只依赖良性数据的天花板判据可以合法地选出配额，实测 +0.058；但天花板是通道语义的性质，通用的原子统计量做不到。** 判据即结论四十七的公式：给每路配额 $\alpha_i$，若 $\alpha_i/q_i < 0.5$ 则不给预算（$q_i$ 是该路离散异常事件在良性折上的发生率，迭代到不动点）。实测：

**但通用版本已试过并失败，这一点必须记下来。** 最初写的是"良性分数在最异常处的原子质量"，它在两处同时误判：硬层的良性分数**全部并列在 0**（良性零违反），于是原子质量读成 1.0、天花板 0.013，把最有用的一路剔掉了；互锁那边**随机化 p 值把 $q$ 那个原子摊成了 $[0,q]$ 上的连续区间**，于是读出 0.0017 而非真实的 3.15%。两个误判方向相反，合起来把配额选得比均分更差（test 0.319）。**教训：天花板来自通道语义（"这一路的异常事件是离散的吗、良性多久发生一次"），必须逐通道声明，不能从分数分布反推**——而随机化 p 值（结论十四要求的那一步）恰恰会把这个信息抹掉。这是两条设计规则之间一个真实的张力，论文里应当写明。

剩下的差距（0.428 对最优的 0.482）来自合成路：它是连续的、天花板判据看不出问题，只能靠结论四十三的机制论证（它针对的多通道攻击不在 A1–A6 里）以声明方式撤掉。**所以最终配置是"硬层 + 时序 + 结构"三路，其中互锁由良性判据剔除、合成由威胁模型声明剔除，两条理由都不依赖测试折。**

### 已实测：三路配置回填 E1 主表，并在此过程中查出两处口径缺陷

（`tools/path_power.py`、`Detector.path_q` / `path_weights`、`DetectorConfig.struct_score`）

回填后本方法的六族均值净检出率为 **0.48（$\alpha=0.01$）与 0.47（$\alpha=0.05$）**，最强基线 B2 markov 为 0.29 与 0.33。但 A4（0.17 对 0.23）与 A6（0.14 对 0.28）**在两个 $\alpha$ 下都稳定输给 B2**，这排除了分辨率假象，必须归因。B2 是纯结构似然，它赢的恰好是三个结构类攻击，故只有两种可能：预算被摊薄，或 M3 本身弱于一阶马尔可夫——两者对论文的含义相反。用"每条路单独拿满 $\alpha$"的诊断把它们分开，结果是先查出两处口径缺陷，各值约 0.06：

**结论五十：结构通道喂给校准器的必须是预测概率而非随机化 PIT p 值；这与结论二十九（时序必须用 $z$）是同一个错误的两次发作。** 随机化 PIT $p = \sum_{j: P_j<P_{\text{cur}}} P_j + U\sum_{j: P_j=P_{\text{cur}}} P_j$ 把 Dirichlet 平滑造成的**并列尾部原子**摊成一段均匀区间，而并列尾部质量与该行支撑度成反比：厚支撑行（见过 300 次）的 $at$ 只有 0.03，薄支撑行（见过 4 次）的 $at$ 高达 0.5，于是 $U\cdot at$ 近乎铺满 $(0,1]$、**该行完全没有功效**。攻击恰好落在薄支撑的行上——常见转移没什么可伪造的。换成概率型分数后满预算下结构通道对 B2 的差距由 $-0.10$ 收到 $-0.05$，**且经验 FPR 同时从 0.0217 降到 0.0138（名义 0.01）**，不是以误报换功效。已固化为断言 T38。

**这条与结论十四"离散通道一律取随机化 p 值"存在真实张力，论文必须写清边界**：随机化针对的是**直接拿去比 $\alpha$** 的 p 值；喂给 conformal 校准器的应当是保序的原始分数，分辨率由良性经验分布提供，并列只在**阈值处**被打破一次，而不是在每条消息上各摊一次。同一处张力已在结论四十九的天花板判据上出现过（随机化把 $q$ 那个原子抹掉了），是全项目第二次。

**结论五十一（口径缺陷，只罚我方一家）：比较装置里绝不能把已过一层冻结 conformal 的分数再交给判决器做经验 p 值变换——两次随机化会打乱相邻原子的次序，实测值 $+0.07$。** 判决器 `judge` 本身要做经验 p 值变换以对齐各方法的量纲，基线交的是原始分数、只经一次；我方此前交的是 conformal p 值、经两次。第一次的 $U(1+eq)/(n+1)$ 项在并列密集处幅度超过相邻档位间距，于是更异常的消息可能拿到更大的 p 值（实测反转率 >20%）。**部署时只有一层校准**（冻结的 conformal），`judge` 是它的替身而非附加层。修正后满预算结构通道对 B2 由 $-0.05$ 变为 $+0.01$。已固化为断言 T39。

**结论五十二：A4/A6 的落后完全可归因于预算摊薄，与 M3 的质量无关；这是多通道方法的固有代价，应写成限制而不是当缺陷修。** 三项归因逐一测量：（1）**校准折的数据代价为 0.00**——让 B2 只吃 `Detector.fit` 内部真正用于拟合的那 67% 折，六族逐格与吃满 `train` 完全相同，故 split conformal 留出校准集在本数据集上不损失结构信息；（2）**口径缺陷共 0.07**，即结论五十与五十一；（3）**其余全部是预算摊薄**：修正后结构通道满预算时 A4 拿 0.31、A6 拿 0.45，与 B2 的 0.41、0.45 齐平，而三路均分后只剩 0.18、0.19。

**这一条给论文提供了一个诚实且有内容的限制陈述**：多通道方法在"只有一路有信号"的攻击上必然输给恰好押中那一路的单通道方法，代价约等于路数倍的预算稀释；换来的是在 A2/A3/A5 上 3–9 倍的领先与不依赖攻击先验的覆盖。**不能声称全面优于基线**，只能声称平均领先 1.4–1.7 倍且没有任何一族归零，而 B2 在 A3/A5 上精确为零。**天花板判据无法进一步改善这一点**：它只能剔除有离散功效上限的路，无法在三条连续路之间判断"哪一路对当前攻击有信号"——那需要攻击先验，一旦引入就回到结论四十八的过拟合。

### 已实测：加强互锁的尝试——q 压下去了，端到端一无所获，病根另在别处

（`interlock.check_global`、`DetectorConfig.interlock_scope`）

按结论八指出的方向做了近似工件身份：把逐 case 令牌账换成**跨 case 全局令牌池 + 守恒**（每次产出最多被消耗一次，故"无产出不得消耗"与"不得双花"仍成立）。位置本就是跨 case 共享的物理地点，全局池能看见并发 case 在同一位置更早的产出。

**结论四十六：全局池把良性违反率 $q$ 从 1.70% 压到 0.22%、LATE 精确归零（17 → 0），但端到端贡献仍是 $+0.01$，一无所获。** 消融两种作用域下 `no_interlock` 都是 $+0.01$、完整臂都是 0.41。原因是两个效应恰好抵消——全局池更宽松，攻击者伪造消耗时只要池子恰好非空就蒙得过去：

| 攻击 | 逐 case：攻击触发率 / 良性 | 全局池：攻击触发率 / 良性 |
|---|---|---|
| A4 | **0.69** / 0.047 | 0.41 / 0.023 |
| A6 | 0.62 / 0.073 | 0.19 / 0.029 |
| A1 | 0.47 / 0.074 | 0.14 / 0.024 |
| A2 | 0.27 / 0.070 | 0.08 / 0.032 |
| A3 / A5 | 0.03 / 0.031 | 0.02 / 0.018 |

良性率减半的同时攻击触发率也减到三分之一到二分之一，似然比几乎不变（A4 由 14.7 微升到 17.8，A1 与 A6 反而变差）。

**结论四十七（本轮最有价值的诊断，且更正了结论三十代入的 $q$）：互锁通道的病根不是不变量质量，而是 $\min(1,\alpha/q)$ 天花板里的 $q$ 必须取部署流实测值，它比训练折高 9 倍。** 逐 case 账下训练折 $q=0.0054$、看上去天花板 $\alpha/q>1$ 不生效；但**测试流上的良性违反率实测 0.047**，天花板于是只有 $0.01/0.047 = 0.21$。代入 A4：触发率 $0.69 \times 0.21 = 0.145$，与覆盖矩阵测到的 0.12 和消融的 $+0.01$ 完全吻合。全局池把部署 $q$ 减半到 0.023、天花板翻倍到 0.43，但触发率同时降到 0.41，$0.41\times0.43=0.176$——净收益微乎其微，正是实测的样子。

这一条把"互锁为什么弱"从含糊的"不变量不够硬"变成了一个可计算的量：**互锁通道的单消息功效上界 = 攻击触发率 $\times \min(1,\alpha/q_{\text{部署}})$。** 三条推论：（1）结论三十的公式正确但此前代入了训练折的 $q$，**天花板必须用部署流的 $q$ 报告**，这与结论二十六（时间序下结构通道 FPR 涨 2.1 倍）是同一件事在互锁通道上的表现，且这里的漂移达 9 倍，是全项目最大的一处；（2）要让互锁够用，需把部署 $q$ 压到 $\alpha$ 量级即约 1%，全局池只做到 2.3%，**剩下的一半必须靠真正的工件身份（NFC/RFID）**——这把结论八的部署条件从定性建议变成了定量门槛；（3）**近似身份解析是一条已被走过并证明不通的路**，论文应当如实写成负面结果，它比不写更有价值：它说明"逐 case 账太紧、全局池太松"，中间那档只能由物理标识提供，无法由日志推断。

**结论四十五：conformal 在 DR 口径上必然看不出价值（$-0.01$），这不是负面结果而是口径的性质。** E1/E2 全部按"误报对齐"评测，而 M8 的作用恰恰就是把误报对齐——把它的价值放到 DR 表里衡量等于让它自己抵消自己。M8 的证据只能来自误报侧：结论十四（离散通道不随机化则 FPR 达 1.000）、结论二十（参数阈值使 FPR 近乎翻倍）、结论二十四（原始参数化 p 值在尾部错近两个数量级）、结论二十六（时间序下退化 1.8 倍）。**论文里 M8 的消融必须放在 FPR 表而不是 DR 表**，否则会自证无用。

#### 数据集的两个版本与两项风险

Trier 同时发布**原始含错版**与**清洗后 gold standard**。含错版的错误来源是 NTP 服务器宕机导致的时间戳漂移、超时导致的重复事件、通信故障导致的事件缺失。**训练与注入必须用 gold standard 版**，否则时序通道被良性异常打爆；但含错版本身是一份**第三方制造的"良性时序异常"硬负样本集**，正好用于 E9（漂移 vs 攻击的区分）与 FPR 稳健性验证，比自造扰动可信得多。

风险一：主日志 301 案例含 231 个变体（变体率 77%），原文亦称"traces can end in any of the activities"、烤炉–铣削–去毛刺工序含错误，即主流程层行为极不规整；子日志层 3,118 案例/269 变体则规整得多。**设计必须顺着数据走：驻留时间分布在子过程（单设备操作）层学，跨设备互锁在主过程层查**，不要指望在主流程层学到紧的时序模型。

风险二：**选它会引入第三支必须显式区分的相关工作——时间感知的一致性检查（time-aware conformance checking）**。审稿人很可能来自过程挖掘社区。差异点站得住：该支工作无攻击者模型、不做误报率保证、通常是对完整轨迹的离线批量拟合度计算，而非在线逐消息序贯判定。但必须写入 Related Work，不能绕。

### 可复用的评估协议（建议作为一项附加贡献）

把 add-on 过程本身写成一个通用协议并开源，能把"数据集弱"这个短板转成加分项：

1. **状态离散化**：由传感器/执行器信号按领域规则映射为每设备的离散状态
2. **掩码提取**：从参考过程模型（BPMN / 工艺文档 / PLC 逻辑）导出 $\mathbf F$
3. **不变量提取**：从物料流与工位前置关系导出 $\mathcal I$
4. **红队注入**：参数化注入 A1–A7 七类攻击（$\rho$、$k$、注入间隔、是否全知）
5. **产出物**：注入器 + 生成的攻击日志 + 基线实现，发布到 Zenodo 获得可引用的 artifact

这样审稿人问"凭什么信你的评估"时，答案是"协议与工具都开源，且在两个第三方真实测试床日志上跑过"。

### 仿真器需要新增记录的字段

现有仿真只记录了状态标签序列，必须重新生成：

- 每条上报消息：**接收侧到达时刻（ms）**、设备 ID、状态标签、消息序号（注意：绝不能用消息自带时间戳，那是攻击者可控的）
- 每条下行命令：下发时刻、目标设备、任务 ID、任务参数（起终点距离、产品型号、预计耗时）
- 物理真值：设备真实状态与真实转移时刻（**仅用于生成标签，不提供给检测器**）
- 攻击标注：注入时刻、注入内容、攻击类型编号（A1–A7）、抢跑量 $\rho$
- **AGV 行驶时间必须显式建模**（距离/速度 + 噪声），目前只有机械臂加工时长 $T=[10,11,7,5,12,\dots]$。行驶时间的 $\sigma_{\log\tau}$ 直接决定时序通道功效——**已在 Trier 真实日志上测得参考值**：运输类活动 `vgr_2` 为 0.110、`wt_2` 为 0.043、`vgr_1`（未条件于路线）为 0.480。仿真器应把 $\sigma_{\log\tau}$ 设为可调参数并覆盖 $[0.05,\,0.5]$ 区间，使仿真结论与真实日志可比。

### 评价指标

- **DR / FPR，在同一 conformal $\alpha$ 下比较**（关键：各方法阈值本不可比，统一到误报预算才公平）
- **检测延迟：以消息数计**（主）+ 以 ms 计（次）。注意区分"算得快"与"发现得早"——旧文的 DT 测的是前者
- **ARL$_0$**（正常运行下的平均误报间隔），序列检验的标准指标
- $F_1$（与旧文对照用，保留）
- 每步计算时延与内存**实测**：**单核 CPU 上的逐消息时延分布 + 复杂度分析**。原计划的"树莓派或工业边缘控制器级硬件实测"已撤回——手头无该类硬件，写成实测即为不实。$O(1)$/消息是可以严格论证的（四次查表 + 两次对数 + 常数次不变量检查，与状态数和设备数均无关），单核实测给出常数因子，两者合起来足以支撑"边缘可部署"，不必伪造硬件平台
- **理论界吻合度**：实测检出率随 $\rho$ 的曲线 vs 理论 $\rho^*(\alpha,\sigma)$。**已在 Trier 日志上预验证，全区间平均绝对偏差约 0.03（结论十七）**
- **必须同时报告校准集规模并限制 $\alpha$ 范围**：实测表明 $n_{\text{cal}}=701$ 时 $\alpha=10^{-2}$ 已是可信下限（结论二十），更低的误报预算须由序贯检验的 ARL$_0$ 承担而非单消息阈值

### 预期结论的写法

主张不要写成"我们 DR 更高"，而要写成三句：（1）在同一误报预算下，本方法在 **A3/A5** 两类**不带时间维的方法结构性无能**的攻击上有非零检出（0.18 / 0.87），而 B2 精确为零（$-0.01$ / $0.00$）；（2）在 A1/A2 上明显优于全部基线（0.55 / 0.95），在 **A4/A6 上低于 B2**（0.17 对 0.23、0.14 对 0.28），后者已归因为预算摊薄而非通道设计（结论五十二）；（3）检测延迟以消息数计显著更低，且有理论支撑。这样即使 E1 的总体数字优势不大，文章依然立得住。

> **订正一：A6 不能列进第（1）句。** 查新表 P4 行已判定"消息抑制类攻击"是计时自动机与 DCTA 的**既有能力**（clock guard、超时、计数器），此处再写成"既有方法结构性无能"就与自己的查新结论直接打架。
>
> **订正二（E1 实测后，比订正一更要紧）：A4 也必须从第（1）句移出，且不能移到"平手"而要移到"落后"。** 原论据是"A4 只有互锁通道能抓"，而互锁已判废（M-b）；实测 B2 在 A4 上拿 0.23、本方法 0.17，在 A6 上 0.28 对 0.14——**这两格是我方落后**，写成"既有方法结构性无能"会被一个数字直接推翻。第（1）句现在只留 **A3 与 A5**，二者的支撑是同一条且极硬：纯时序攻击一个标签都没改，纯标签模型的分数流在攻击流与良性流上逐条相同，故其检出率必然恰好等于误报率、减地板后为零。这不是"我们高几个点"，而是**结构性失明的实证**，且有两个独立证据源（B2 基线 + E2 去时序臂）。A3 的机理支撑仍是 M-d：抢跑重放落在区间型 clock guard 内部因而被计时自动机接受，但分级证据在 CUSUM 上可累积，二值区间判断不可。
