> 改动规模：正文 **143 行改写**（143 增 / 143 删，行数不变，即逐行替换）；14 个图脚本改动；12 张中文图重绘

## 0. 修订原则

1. **只改表述，不改事实。** 全部数值、公式、符号、表格读数、`\ref`／`\cite`／`\label` 键、章节结构与结论强度均未改动；所有改写都是同一含义的更正式说法。
2. **消除口语化措辞。** 例如"见过""没有做多""塌掉""打平""卖点""天花板""碰"。
3. **自造简称改为可自解释的术语。** 例如"硬层""抢跑""偶然地板"。
4. **图文术语同步。** 凡正文改名的术语，同步改图脚本并重绘，避免正文与图注、图内文字不一致。
5. **保持简洁。** 改写以澄清为目的，不额外增加篇幅；两轮改动后编译为 22 页。

### 与偶然告警基线相关的补充改写

原句"延迟预算内'窗口中任一告警即检出'存在偶然地板"直接抛出该量，未说明其来源。改后先交代机理再给公式：

> 在延迟预算内采用"窗口中出现任一告警即判为检出"的口径时，即使检测器不具备任何真实检测能力，窗口内的随机误报也会带来一定的检出率。该偶然告警基线为 $1-(1-\mathrm{FPR})^{B+1}$（$B=10$）。

## 4. 顺带修复的两个绘图工具链问题

这两项与措辞无关，是重绘中途暴露出来的既有缺陷；若不修复，本机无法重新生成图。

1. **三位十六进制色值。** `fig_arch*.py` 与 `fig_system*.py` 使用 `"#111"`、`"#222"`、`"#333"`。matplotlib 3.1.3 不接受三位写法，脚本直接抛 `ValueError: Invalid RGBA argument`。已补全为六位写法（`"#111111"` 等，颜色完全相同）。英文版脚本存在同样问题，一并修复。

2. **中文字体未子集化，PDF 体积失控。** 这两个脚本未设 `pdf.fonttype`，退回 Type 3 后无法嵌入 `.ttc` 字体（`RuntimeError: TrueType font is missing table`）；改设 `42` 后可以出图，但 matplotlib 3.1.3 在 Type 42 下会把**整个**宋体文件写进 PDF——单张图从 25 KB 涨到约 10 MB，全文 PDF 从 0.65 MB 涨到 **128 MB**。

   已在 `_style.py` 中新增 `subset_pdf()`：出图后用 `pdftocairo`（随 TeX Live 提供）重写 PDF，只嵌入实际用到的字形；`save()` 与两个独立脚本均调用。若系统中没有 `pdftocairo` 则自动跳过，不影响出图。修复后各图恢复到 15–46 KB，全文 PDF 为 **0.64 MB**，且 `pdffonts` 检查无 Type 3 字体（符合 ACM 要求）。
