## 2. 生成逻辑（这套文件是怎么从 SOW 推出来的）

编写时只做「翻译」和「补操作层」，不做范围发明。对应关系如下。

### 2.1 从 SOW 抽出必须守住的骨架

| SOW 位置 | 抽出来的硬约束 | 落到哪 |

### 2.2 计划为什么必须写到操作层

只给任务名不够带项目。本套文件在 SOW 范围之内补了：

1. **测试和生产拆开。** 合同交付物 #2 和 #6 分开；附件 A 的 M2 要同时签 #2～#6。
2. **每条任务有操作。** 西门子指导什么、客户必须先准备什么、做到哪一步才能签字。
3. **客户前置关门。** Onboarding、合规 Submodel Server、集群、数据、安全评审不关门，部署指导会空转。
4. **验收节奏写进计划。** §7 要求提前 5 个工作日通知。加速基线下 M1 通知期不够，须启动会当场发出并请客户确认。
5. **范围边界写进任务。** 例如 Submodel 是注册与验证，不是新建 Server 或写代码。

工期是管理决策：SOW 原文 58 个工作日，**当前执行基线按约 27 个工作日排**。范围、交付物、确认书不因此减少。

### 2.3 加速基线怎么排期（约 27 个工作日）

- **启动日**：`2026-08-17`（周一）。启动日变化时按工作日整体平移。
- **窗口**：`2026-08-17`～`2026-09-22`，共 **27 个工作日 / 6 个项目周**，赶在中秋（09-25）和国庆之前结束。
- **与 SOW §3.5 的关系**：合同仍写 58 日、第 2/7/10/12 周。本工作簿把四个里程碑压缩到执行第 1/4/5/6 周。这是执行加速，不是改合同。客户前置跟不上，按 §9 顺延，禁止砍范围。
- **依赖与并行**：任务在全部前置结束后的下一工作日开始。1.1/1.2/1.3 并行调研；2.5 观测、2.6 安全与 2.3 联调并行；3.1 灾备与 3.2 语义映射并行。
- **验收通知**：M2/M3/M4 仍按结束日前 5 个工作日通知。M1 只能在启动会当天通知，须客户书面接受。
- **没有假期缓冲**：任一关键延误都会把结项推过中秋，等于回到更长日历。风险见 R-17、R-26。

| --- | --- | --- | --- | --- | --- |
| M1 | W1 | 2026-08-21 | 第 2 周 | 《部署方案验收服务确认书》 | #1 |
| M2 | W4 | 2026-09-09 | 第 7 周 | 《生产环境验收服务确认书》 | #2 #3 #4 #5 #6 |

| M4 | W6 | 2026-09-22 | 第 12 周 | 《项目结项验收服务确认书》 | #9 |

### 2.4 风险单怎么生成

风险不是另做一套“通用 IT 风险”，而是把 SOW 里**已经写明会出事的假设、不在范围和附件 B 备注**改写成台账：

- 假设被打破 → 客户依赖类（Onboarding、集群、数据、人员）
- 不在范围被口头突破 → 范围类（加接口、压测、写代码、全员培训、陪伴期当驻场）
- 附件 B 的“若云不支持” → 技术类（Vault unseal、Node 扩容、集群限制）
- §7 / §9 的验收和变更 → 进度 / 治理类

评分：可能性、影响各为高=3、中=2、低=1，乘积 ≥6 为高、≥3 为中。高风险在启动会就要向指导委员会亮灯。

加速基线额外盯两条：**R-17**（27 天无缓冲，延误会撞上中秋/国庆）、**R-26**（§7 的 5 日通知 / 10 日审查在窗口内放不下，须客户书面同意当场签收）。

## 3. 计划工作簿里有哪些表

文件：`CatenaX_FastTrack_Plan.xlsx`

建议第一次按编号读：`00` → `01` → `06` → `02` → `03`。之后日常只动 `03` `06` `08` `11`，里程碑前加看 `02` `04`。

### `00_使用说明`

阅读顺序、日期规则、状态取值、范围红线、配套文件。新同事或客户 PM 第一次打开工作簿，先看这一页。

### `01_项目总览`

合同信息、目标、**在范围 / 不在范围**、关键假设。会议上有人要“顺便加一块”，先回到这一页，再决定是否建变更。

### `02_里程碑与验收`

四个合同里程碑的目标周、计划日、确认书名称、交付物打包关系、验收通知日（里程碑结束日前 5 个工作日）。下面还有 §7 验收操作要点。

**用法：** 每个里程碑前第 6 个工作日起草通知，第 5 个工作日发出。缺一份必包交付物，不要强推签字。

### `03_WBS详细计划`（日常主表）

23 条任务，也是整套文件的核心。主要列：

| 列 | 含义 |
| --- | --- |
| WBS | 编号，例如 1.5、2.10 |
| 操作指导 | 按此执行，不要只看任务名 |
| 工期 / 计划开始 / 计划结束 / 项目周 | 基线日期 |
| 前置 | 必须先完成的 WBS |
| 西门子做什么 / 客户做什么 | 责任边界 |
| 完成标准 | 可验收的关门条件 |
| 交付物 / SOW 条款 | 和合同的对应 |
| 注意/风险 | 这一步最容易踩的坑 |
| 里程碑 | M1～M4 所在行（浅红） |
| 状态 / 实际开始 / 实际结束 | 每周更新；状态下拉：未开始 / 进行中 / 已完成 / 阻塞 / 已取消 |

阶段用底色区分：蓝=方案，绿=部署上线，黄=灾备与设计，橙=培训结项。里程碑行加红，便于过滤。

**用法：** 每周五更新状态。状态改成「阻塞」时，必须到 `08` 建单。

### `04_交付物清单`

SOW §3.4.1 的 9 项交付物：编号、验收描述、格式、验收方（均为客户 IT）、所属里程碑、对应 WBS。未列出的交付物视为超范围。

### `05_RACI责任矩阵`

工作项 × 角色（西门子 PM、客户 PM、西门子技术、客户基础设施、客户业务/数据、客户安全、商务/CCB）。R=执行，A=问责，C=咨询，I=知情。

特别行：「对接代码开发」西门子是「—」，客户才是 A/R。不要在会上改口。

### `06_客户前置条件`

发给客户 PM 的第一份作业，C-01～C-18。每条有关闭证据、最迟关闭点、状态。未关门不要开始对应部署任务。

### `07_沟通与会议`

启动会、例会、四个节点会、指导委员会、CCB，以及 §6.5 升级时限（成员 3 个工作日 → 双方 PM 再 3 个工作日 → 指导委员会 3 个工作日内决策）。

### `08_问题与行动项`

已经发生的问题、待办、决策。前两行是示例，启动会后删掉换真实项。问题 ≠ 风险：风险在另一本工作簿。

### `09_变更记录`

按 §9 的 CR 台账。表下列出 SOW 原文归纳的典型触发情形（前置延误、数据要洗、加接口、验收拖延等）。出现即建单，不要靠加班消化。

西门子须在 5 个工作日内评估时间与费用；未签字的 CR 不实施。

### `10_周报模板`

例会前复制填写：本周完成、下周计划、里程碑预测、前置 / 风险 / 升级。也可直接贴进邮件正文。

### `11_项目周历`

6 个项目周各一行：起止日、本周收口任务、客户要配合谁、PM 本周盯什么。适合周会开场 30 秒对齐。原“对照旧计划”的表已删除，不再保留。

### `01_风险登记册`（主表）

| 列 | 含义 |

## 6. 怎么使用（按角色和时间）

### 6.1 启动后第一个工作日

1. 读完本 README 和 `CatenaX_项目经理工作提示.md` 第 1～2 节。
2. 打开计划 `01_项目总览`，确认现场对「不在范围」没有异议。
3. 把 `06_客户前置条件` 发给客户 PM，请其填写责任人和计划关闭日。
4. 打开风险单 `01_风险登记册`，删掉明显不适用的项，补现场新风险。
5. 按 `07_沟通与会议` 把例会、节点会、指导委员会、CCB 写进日历。

### 6.2 每周（建议周四更新、周五开会）

西门子 PM 更新：

1. 计划 `03_WBS` 的状态和实际日期
2. 计划 `08` 的开放 / 逾期项
3. 计划 `06` 仍未关闭的前置
4. 风险单中所有「高」且「开放」的风险
5. 计划 `10_周报模板`（可直接贴邮件）

例会只讨论：**偏差、缺口、决策、下周关门点**。不要开成技术分享会。

### 6.3 每个里程碑前

1. 对照 `02` 和 `04`，确认必包交付物齐全。
2. 用风险单 `03_风险应对检查` 做关门。
3. 至少提前 5 个工作日发出书面验收通知。
4. 会上预填对应《服务确认书》，当天归档扫描件。
5. 不要把「客户 10 个工作日不拒绝即视为接受」当成进度缓冲。那是保护条款，计划仍以会上签字为准。

### 6.4 出现范围争议或客户延误时

1. 先对 `01` 的不在范围、`05` 的 RACI。
2. 用 PM 提示第 5 节的标准答法，避免口头承诺。
3. 单一缺口 3 个工作日内能关：记 `08`。
4. 逾期且下一任务受阻：升级到双方 PM，再不行到指导委员会。
5. 要西门子洗数、加接口、改流程、改已签字方案：建 `09` 变更，**未签字不实施**。

### 6.5 结项当天

1. 签 M4 确认书。
2. 按 WBS 4.3 和 PM 提示第 4 节移交陪伴期：接口人、5×12、1 小时响应、远程默认、缺陷反馈计数（≤12 次）。
3. 书面声明：结项后的功能新增或改动为二次需求。
4. 把高风险关进风险单，未关闭项要么关闭、要么移交陪伴期服务台。

### 6.6 启动日或假期变了怎么办

1. 不要重写 WBS 条文，只平移「计划开始 / 计划结束」。
2. 保持四个里程碑的相对顺序和交付物打包关系；若无法继续压缩，按 §9 顺延，不要砍交付物。
3. 重新计算四个验收通知日（结束日前 5 个工作日；M1 除外），回写 `02`。
4. 方案确认书（M1）签字后，若环境事实与假设不符，先变更再重排，把本工作簿升为受控版本。

## 7. 不要做的事

- 不要把本套文件的任何一页当成可以替代 SOW 的范围定义。
- 不要另做第三套周报或第三套 WBS；有新字段就加在现有表上。
- 不要在客户说“你们先做着”之后，把超范围工作记成 WBS 正常任务。先有 CR。
- 不要用测试环境报告去签生产里程碑。
- 不要把风险单里的「已发生」只改颜色不转问题单。

## 8. 状态和颜色约定

计划 `03`、`04`、`06` 和风险单里的状态下拉请尽量用表内已有取值，便于筛选。

| 计划任务状态 | 含义 |
| --- | --- |
| 未开始 | 前置未完成或窗口未到 |
| 进行中 | 本周正在做 |
| 已完成 | 达到该行「完成标准」 |
| 阻塞 | 做不下去；必须进 `08` |
| 已取消 | 经变更取消，须能追溯到 CR |

| 风险状态 | 含义 |
| --- | --- |
