**paper01（静态）**  
《柔性作业车间调度与 AGV 无冲突路由的路由内嵌评价闭环双层框架》

- **问题**：常数运输矩阵默认车辆互不争用；一旦走廊排他、行驶时间由路由产生，通往快臂的走廊拥堵时，较慢但更好走的臂可能更优。沿用 van Os 的问题类，贡献在求解方法。
- **方法**：闭环双层——上层搜指派与排序，下层时间窗预约做无冲突路由。两条通路：路由内嵌评价（适应度取真实 \(C_{\max}\)），预约表感知派车（两段试算选车）。另有两项不改输出的降本。
- **主结果**：闭环约降 18.86%；闭环内再换派车约降 2.45%；端到端约 21.35%，近加性。闭环是主效应，派车是合计才显著的次效应。
- **明确不写**：故障、插单、动态到达（假设 A7）；未来工作第 (5) 条正好指向「故障下度量修复速度」。

**paper04（动态）**  
《任务图覆盖不到的级联损坏：无冲突柔性作业车间中的时空预约闭包》

**Cursor**

**主要是新的找损坏方法，不是新的调度算法。** paper04 自己把主语写成闭包，修复只是把它用起来。

新的是 **STRC**：以与扰动时窗重叠的预约为种子，沿让行、同车、同工件、同机取传递闭包，得到可释放 / 可冻结的范围。给定边集后，谁进闭包由结构唯一确定，不随搜索过程变。论文反复强调：**影响闭包是一次测量，不是一个决策。**

调度 / 修复一侧用的是已有形态，并且明文不主张创新：

- 第 1 级是原车、原指派、原扫描序，按段调用与 paper01 相同的时间窗 Dijkstra 改路；
- 「闭包内重规划 + 外侧冻结」是 MAPF 的标准做法；
- 失败后按工件后缀 / 同车 / 全部未来扩域，是 Local Rescheduling 换了扩张方向；
- 让行边与铁路 alternative arc 同源，这里不选弧，只在既定排程上取闭包。

实验也按这个归因来设计：E3 固定同一改路引擎，只换释放集（任务图 vs 闭包）；E7 的 RA 与 R2 连引擎、冻结判据都相同，只差释放集取平凡上界还是闭包。毫秒级响应被归因于「单遍改路、不重开搜索」；闭包兑现的是稳定性（少改外侧预约）。热启动全局重解（R0+）还是 paper01 那类搜索，只当对照。

所以：算法形态是旧的有界修复；新的是**损坏边界画在哪张图上、如何唯一确定释放集**。

**Cursor**

闭包给出释放集 \(U\) 之后，paper04 **不换一套新的重调度搜索**，而是把 \(U\) 送进同一套有界改路引擎。

**主路径（B 类：走廊阻断 / 降速）**

1. **第 1 级：`ReplayReroute`（算法 1）**  
   机器指派 \(x\)、扫描序 \(\pi\)、车辆指派 \(y\) 一律不动。  
   - 闭包外、且 \(t^e>t_{\mathrm{now}}\) 的预约按原字段预提交（冻结）；  
   - 闭包内按原扫描序、**原车**改路：已走完的走廊腿保留，从该车在 \(t_{\mathrm{now}}\) 的节点接起；  
   - 路由器就是 paper01 那条 **时间窗 Dijkstra**（Sun 等的时间窗路由），只改「哪些运输段被送进去」。

2. **失败则扩域，引擎不变（算法 2）**  
   依次扩大 \(U\) 再重跑同一套 `ReplayReroute`：  
   同工件后缀 → 同车后缀 → 释放全部未来预约。  
   仍是确定性单遍协调，不打开种群搜索。

**A 类额外动作（仍不改 \(\pi\)、不重开搜索）**

- 车辆故障：故障车摘除，未完成运输**换车**后再走上述改路；  
- 机械臂故障：未完工工序**改派**到其他可行机，再改路。

**不是这条路径的算法**

热启动 memetic / 染色体重解码（R0+、RD）和全局右移（RS）只当对照。STRC 路径的重调度就是：**闭包定 \(U\) + 时间窗最短路单遍重放，失败按依赖边扩 \(U\)**。新的是谁进 \(U\)，不是路由器本身。

**User**

这里的“损坏”主要指什么？‘

---

**Cursor**

这里的「损坏」主要不是设备坏了，而是**原排程里已经写下的承诺不再可行**——尤其是走廊预约失效，并沿让行关系传给后续车辆。

一份可行排程同时有工序指派 / 排序和一张走廊预约表。扰动可以打坏任务，也可以**只打坏预约**。paper04 的主对象是后一种。

**直接损坏（种子）**  
某条预约 \(r=(e,[t^s,t^e),k,u)\) 与扰动冲突，不能再按原字段执行。走廊阻断 / 降速时，就是占用区间与禁行（或降速）窗重叠的那些预约：工序指派一个没变，但这些走廊占用已经和排他时窗打架。

**级联损坏（闭包）**  
种子失效后，后车必须让行或改道，同车后续段、同工件下一段、同机下一道所诱导的预约也可能被迫重规划。从种子沿四类依赖边能走到的活预约，就是闭包。所谓「任务图覆盖不到」，是任务图里没有这些让行边，不是传感器漏检。

B 类（阻断、降速）是一击反例：任务图直接集为空，看起来像「没坏」，预约表上种子非空，原排程已经不可行。A 类（车辆 / 机械臂故障）也会产生损坏，但任务图看得到，不是本文要单独指认的那一类。

所以后文说「测量损坏」「释放损坏范围」，指的是：**哪些预约记录必须作废、哪些可以冻结**，不是车间里哪台机器物理坏了。

**Cursor**

**报出来的亚秒 / 毫秒，是整段有界恢复的墙钟时间，主要是重调度（单遍改路），不是「发现损坏」那一步。**

**和 paper01 的关系**

paper01 是两层：上层 memetic 搜指派 \(x\) 与扫描序 \(\pi\)，下层用时间窗 Dijkstra 在预约表上走出无冲突路径；每个候选都完整解码一次，适应度取真实 \(C_{\max}\)。

paper04 的 `ReplayReroute` **只复用下层那条原语**（论文写明：路网、时间窗路由、校验器与静态工作同一实现）。它做的是：

- 输入已是一份 01 风格搜出来的 \(\mathcal{S}^0=(x,\pi,y,R)\)；
- \(x,\pi,y\) **一律不动**；
- 闭包外预提交，闭包内按原序、原车、从 \(t_{\mathrm{now}}\) 接一段时间窗最短路。

所以它是 **01 解码器的受限重放**（冻外侧、只改 \(U\)、不改染色体），不是闭环搜索，也不是预约表感知派车。04 里和 01 更像的两条臂是对照，不是 STRC 主路径：

- **RD**：原染色体只解码一次（01 评价一个候选的代价）；
- **R0+**：热启动、可改 \(x\) 与 \(\pi\)，就是扰动约束下再跑 01 那类搜索。

**普通马尔可夫只问「下一步这个标签常见吗」；半马尔可夫多问一句「在上一个状态待了多久，像不像这类活该花的时间」。** 旧机制看不见的注入，标签往往完全合法，破绽只在时间被提前。

\[
Q_{A\to B}(\tau) = P_{A\to B}\times F_{A\to B}(\tau)
\]

- \(P\)：标签还走不走得通（和旧矩阵同一类信息）  
- \(F(\tau)\)：从 \(A\) 跳到 \(B\) 通常要花多久。paper02 里按「哪台设备、哪个操作」分组，认为 \(\log\tau\) 大致正态，均值 \(\mu\)、波动 \(\sigma\)

检测时看标准化残差：\(z=(\log\tau-\mu)/\sigma\)。正常完成，\(z\) 在 0 附近晃；抢跑把停留压成 \((1-\rho)\tau\)，\(z\) 会系统性偏负。

**为什么旧机制抓不到。**  
典型手法：活还没干完，就重放一条「已完成」，标签仍是调度器最指望看到的那个。\(P\) 接近 1，\(\ell_2\) 和良性众数转移一样大——距离只由「前驱 + 标签」决定，和真假无关。零误报下你不能把最常见的下一步标成攻击，否则日常也会响。所以**只改时间、不改标签**时，转移矩阵是盲的。

**为什么半马尔可夫能看见。**  
物理过程还在走，攻击者改不了真实进度，只能把上报时刻提前。标签仍合法，但 \(\tau\) 变短，\(z\) 持续偏负。单条可能仍落在「正常区间」里（计时自动机的时钟守卫会放行），可同方向偏快一条条加起来，CUSUM 会爬过门限。这就是 A3（零散抢跑）和 A5（一段活动一起提前）旧法净检出约 0、新法能非零的原因。

一句话：旧法核对的是**台词对不对**；半马尔可夫还核对**这句台词说得是不是太早**。伪造完成可以背对台词，背不了墙上的钟。

半马尔科夫好像是引入了2个因子而不是1个，为什么反而叫“半”？

**Cursor**

**「半」不是因子少了一半，而是马尔可夫性只保留了一半。** 半马尔可夫比普通连续时间马尔可夫**更一般**：跳转标签仍是马尔可夫，在状态里待多久可以随便分布，不再必须是无记忆的指数分布。

连续时间里，真正的马尔可夫过程有一条很硬的要求：**将来只取决于此刻在哪个状态，和已经待了多久无关。** 能满足这一点的停留时间几乎只能是指数分布（无记忆：再等 1 秒的概率，和已经等了多久无关）。所以「完整马尔可夫」看起来因子少，是因为时间被数学绑死了，不是模型更强。

半马尔可夫把一次转移拆开：

- **跳到哪**：嵌入的状态链仍是马尔可夫，\(P_{A\to B}\) 只看当前状态；
- **待多久**：\(F(\tau)\) 可以是对数正态等任意分布。

这样一来，**只在跳转那一瞬**还像马尔可夫；在两次跳转之间，已经待了多久会影响「还要再待多久」，连续时间轨迹不再无记忆。所以叫 semi-Markov：马尔可夫性是半吊子的——链上有，时钟上没有。

和检测的关系也在这里：旧机制用的是那条「只看标签」的链，时间被丢掉了。半马尔可夫把被完整马尔可夫强行抹掉的停留分布捡回来，才能看出「标签对、话说得太早」。名字显得像削弱，其实是放松了时间假设、多看了一维。
